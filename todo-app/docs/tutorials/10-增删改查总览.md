## 一、一条请求的 12 个环节

```
① 页面状态      TodoView.vue       query / form / dialog / list
② 按钮事件      TodoView.vue       @click / @change / v-model
③ 前端函数      TodoView.vue       handleSearch / handleSave / handleDelete
④ 接口封装      api/task.js        pageTasks / createTask / updateTask
⑤ axios         api/request.js     baseURL '/api' + 拦截器
⑥ 代理          Vite 或 Nginx      /api → http://backend:8080
⑦ Controller    TaskController     收参数、校验、包 Result
⑧ Service       TaskServiceImpl    业务、事务、缓存
⑨ Mapper        TaskMapper         BaseMapper，框架生成 SQL
⑩ 数据库        MySQL / Redis       t_task / todo:stats
⑪ 返回          Result → JSON      { code, message, data }
⑫ 回显          TodoView.vue       赋值给 ref/reactive → 页面刷新
```

**查、增、改、删都走这条线**，区别只在第 ③⑦⑧⑨⑩ 步。

## 二、四个操作速查

| 操作 | 页面入口 | HTTP | Service 方法 | 核心 SQL |
|---|---|---|---|---|
| **查** | 查询 / 搜索 / 分页 | `GET /api/tasks?...` | `pageTasks` | `SELECT ... WHERE deleted=0 LIMIT ?` |
| **增** | ＋新增 → 保存 | `POST /api/tasks` | `createTask` | `INSERT INTO t_task ...` |
| **改** | 编辑 → 保存 | `PUT /api/tasks/{id}` | `updateTask` | `UPDATE t_task SET ... WHERE id=?` |
| **改状态** | 行内开关 | `PATCH /api/tasks/{id}/finished` | `toggleFinished` | `UPDATE t_task SET finished=? ...` |
| **删** | 删除 → 确认 | `DELETE /api/tasks/{id}` | `removeTask` | `UPDATE t_task SET deleted=1 ...` |

> 「改」有两个入口：**编辑弹窗**改标题/备注/优先级/日期，用 `PUT`；
> **状态开关**只改 `finished`，用 `PATCH`。

## 三、前端状态：页面为什么自己会变

| 状态 | 作用 | 谁修改 |
|---|---|---|
| `loading` | 表格遮罩 | `loadList` 开始/结束 |
| `list` / `total` | 表格数据和总条数 | `loadList` |
| `query` | 搜索、筛选、分页参数 | 用户输入、`handleSearch` |
| `dialog` / `form` | 弹窗显隐、表单内容 | `openCreate` / `openEdit` / `handleSave` |
| `stats` | 三个统计卡片 + 缓存标签 | `loadStats` |

**一句话**：事件处理函数只改状态，Vue 负责把状态画到页面上。
`ref` 在 JS 里写 `.value`，模板里自动解包；`reactive` 直接改属性。

### 3.1 页面从哪来：index.html → main.js → TodoView

`index.html`：

```html
<div id="app"></div> <!-- Vue 的挂载点 -->
<script type="module" src="/src/main.js"></script> <!-- 入口脚本 -->
```

`main.js:21-32`：

```js
const app = createApp(App) // 创建 Vue 应用
app.use(ElementPlus, { locale: zhCn }) // 注册 Element Plus 组件和中文
app.use(router) // 注册路由
app.mount('#app') // 挂载到 index.html 的 #app
```

`router/index.js:11-17`：

```js
const routes = [
  { path: '/', name: 'todo', component: TodoView } // 访问 / 时渲染 TodoView
]
```

- **做什么**：把根组件、UI 组件库、路由装进应用，再挂到页面上。
- **为什么**：Vue 是单页应用，页面切换由路由完成；Element Plus 只有注册后才能用
  `el-table`、`el-dialog` 这些标签。

## 四、四篇共用的「公共底座」

| 约定 | 内容 | 看哪里 |
|---|---|---|
| 路径 | 前端 `baseURL: '/api'`，接口写 `/tasks` | `request.js:15-18`、`task.js` |
| 方法 | GET 查、POST 增、PUT 改、PATCH 局部改、DELETE 删 | `TaskController.java` |

### 4.1 axios 实例：`request` 不是浏览器原生方法

`request.js:15-18`：

```js
const request = axios.create({ // 创建一个 axios 实例，变量名叫 request
  baseURL: '/api',              // 所有请求自动加 /api 前缀
  timeout: 10000                // 10 秒没响应就报错，避免一直等
})
```

调用时：

```js
request.get('/tasks', { params: { pageNum: 1 } }) // request 是 axios 实例，get 是 axios 方法，params 会拼成查询参数
```

- `request` 是从 `request.js` import 进来的实例，不是浏览器全局对象。
- `get / post / put / patch / delete` 都是 **axios** 的方法。
- 底层浏览器真正用的是 `XMLHttpRequest`（axios 默认）或 `fetch`。

### 4.2 响应拦截器：为什么页面拿到的不是整个 response

`request.js:42-59`（简化）：

```js
request.interceptors.response.use((response) => { // 后端响应先经过这里
  const body = response.data // axios 的 response.data 是后端返回的 JSON
  if (body.code === 200) return body.data // 成功：只把 data 交给页面
  ElMessage.error(body.message) // 失败：弹出后端给的 message
  return Promise.reject(new Error(body.message)) // 并中断后面的代码
})
```

所以 `await pageTasks(...)` 拿到的直接是 `data`，
页面里写 `data.records`，而不是 `response.data.data.records`。

> **业务失败也是 HTTP 200**：标题为空返回 `{ "code": 400, ... }`，
> 前端拦截器看的是 `body.code`，不是 HTTP 状态码。

### 4.3 代理：浏览器只认识 5173 / 8081

前端代码只写 `/api/tasks`，**不写 `http://localhost:8080`**。
真正转发由运行环境完成：

| 环境 | 浏览器请求 | 谁转发 | 后端收到 |
|---|---|---|---|
| 开发 `npm run dev` | `http://localhost:5173/api/tasks` | Vite `server.proxy` | `http://localhost:8080/api/tasks` |
| Docker | `http://localhost:8081/api/tasks` | Nginx `location ^~ /api/` | `http://backend:8080/api/tasks` |

开发环境 `vite.config.js:28-39`（简化）：

```js
server: { // Vite 开发服务器配置
  proxy: { // 代理规则
    '/api': { target: 'http://localhost:8080', changeOrigin: true } // /api 开头的请求转给 8080
  }
}
```

Docker 环境 `nginx.conf:23-29`（简化）：

```nginx
location ^~ /api/ { # 匹配 /api/ 开头的请求
    proxy_pass http://backend:8080; # 转给 Docker 网络里的 backend 服务
}
```

**路径必须对上**：

```
前端 baseURL '/api' + 接口 '/tasks'  →  /api/tasks
后端 @RequestMapping("/api/tasks")   →  能接住
Nginx / Vite 匹配 '/api'             →  才会转发
```

任何一处少了 `/api` 或写错 `/tasks`，都会 404。

## 五、框架改写 SQL 的两个例子

```sql
SELECT ...                       -- 你写 page(page, wrapper) 后，日志里看到的是：查所有列（实际列很多，这里省略）
FROM t_task                       -- 任务表
WHERE deleted=0                  -- 逻辑删除：只看未删除的
  AND (title LIKE ?)             -- 标题模糊匹配；? 是参数，如 %报告%
ORDER BY finished ASC,           -- 未完成（0）排在已完成（1）前面
         priority DESC,          -- 优先级高的在前
         id DESC                 -- 同优先级时新建的在前
LIMIT ?;                         -- 分页拦截器加的：只取当前页

UPDATE t_task                    -- 你写 removeById(id) 后，日志里看到的是：
SET deleted=1                    -- 不是真删，只把删除标记改成 1
WHERE id=? AND deleted=0;        -- 只处理还没删过的那一条
```

- `deleted=0` / `deleted=1` 来自实体上的 `@TableLogic`。
- `LIMIT` 和单独的 `COUNT(*)` 来自分页拦截器。
- 日志里是 `?` 占位符，参数单独给出，不是字符串拼接。

## 六、怎么验证你看懂了

1. **Network**：按 `F12`，点一次操作，看 Method、URL、Payload、Response。
2. **后端日志**：找 `==> Preparing:` 和 `==> Parameters:`，看 SQL 和参数。
3. **Redis**：`docker exec -it todo-redis redis-cli`，看 `GET todo:stats`、`TTL todo:stats`。
4. **curl**：绕过前端直接调后端：

```bash
curl "http://localhost:8080/api/tasks?pageNum=1&pageSize=3" # pageNum=1 第 1 页，pageSize=3 每页 3 条
```

## 七、常见坑（先记这 8 个）

| 现象 | 最可能的原因 |
|---|---|
| 404 | `baseURL` / Controller 路径不一致 |
| 405 | HTTP 方法写错 |
| `code=400` 但 HTTP 200 | 业务失败看 body 的 `code` |
| 搜索无效但不报错 | 参数名不一致，或 `finished=null` 没传 |
| 表格空但 `total>0` | 页码越界，搜索时忘了 `pageNum=1` |
| 统计数字不刷新 | 缓存没失效，或直接改了数据库 |
| 开关点完弹回 | 请求失败，或没重新 `loadAll` |
| 删除后数据库还能查到 | 逻辑删除，`deleted=1` |
