# 04 · 前端与后端耦合：五份「契约」

> 一句话：前后端是两个独立程序，它们唯一的共识就是**契约**。契约对不上，接口往往「不报错，但不对」。
>
> **定位**：页面层与接口层之间的桥。它不写业务，只保证两边说的是同一种语言。

> 配套手册：`request.js` / `task.js` 的模板和 Axios 语法见 [06 前端模板](06-前端模板.md)。

---

## 本章你会

- 在浏览器 Network 面板里读懂一次请求
- 掌握五份契约：路径、方法、字段名、响应外壳、日期格式
- 知道开发和生产为什么是两套代理
- 用四步法定位联调问题

---

## 一、先看一次真实请求

打开页面，按 `F12` → `Network`（网络）→ 点「查询」，找到 `tasks` 这条请求：

```
请求 URL:  http://localhost:5173/api/tasks?pageNum=1&pageSize=5
请求方法:  GET
状态码:    200
响应体:    {"code":200,"message":"成功","data":{"records":[...],"total":8,...}}
```

看清楚三件事：

1. 请求发给了 **5173**（前端自己的地址），不是 8080 —— 这是代理在起作用
2. 路径是 `/api/tasks`，不是 `/tasks`
3. `data` 里还有一层 `records` 和 `total` —— 前端页面拿到的其实是这一层

下面五份契约，就是让这三件事成立的规则。

---

## 二、契约一：路径

一条请求要经过四个地方，**前缀必须一致**：

```
任务查询前缀              ← 统一叫 /api
  ① 前端：request.js       baseURL: '/api'
  ② 前端：task.js          request.get('/tasks')        → /api/tasks
  ③ 代理：Vite / Nginx     把 /api 转发到 8080
  ④ 后端：Controller       @RequestMapping("/api/tasks")
```

对应代码：

```js
// frontend/src/api/request.js
const request = axios.create({ baseURL: '/api', timeout: 10000 })
```
```js
// frontend/src/api/task.js —— 只写 '/tasks'，因为 baseURL 已经带了 /api
export function pageTasks(params) {
  return request.get('/tasks', { params })
}
```
```java
// backend/.../TaskController.java
@RequestMapping("/api/tasks")
```

**两个最容易犯的错**：

| 错误写法 | 实际请求 | 结果 |
|---|---|---|
| `request.get('/api/tasks')` | `/api/api/tasks` | 404 |
| 后端写成 `@RequestMapping("/tasks")` | `/api/tasks` 到后端没有对应接口 | 404 |

**实验**：把 `request.js` 的 `baseURL` 改成 `'/api2'`，刷新页面 → 表格报错、Network 里 404。改回来恢复正常。

---

## 三、契约二：HTTP 方法

同一个路径，用不同方法表示不同动作：

| 前端调用 | 后端注解 | 动作 | 语义 |
|---|---|---|---|
| `request.get('/tasks', {params})` | `@GetMapping` | 分页查询 | 查 |
| `request.get('/tasks/stats')` | `@GetMapping("/stats")` | 统计 | 查 |
| `request.post('/tasks', data)` | `@PostMapping` | 新增 | 增 |
| `request.put('/tasks/'+id, data)` | `@PutMapping("/{id}")` | 全量更新 | 改 |
| `request.patch('/tasks/'+id+'/finished')` | `@PatchMapping("/{id}/finished")` | 切换完成状态 | 局部改 |
| `request.delete('/tasks/'+id)` | `@DeleteMapping("/{id}")` | 删除（逻辑删） | 删 |

**PUT 和 PATCH 的区别**：

- `PUT` = 用请求体**整体替换**资源
- `PATCH` = 只改其中**一部分**

本项目切换完成状态只改 `finished` 一个字段，所以用 `PATCH`，语义更准确。

方法写错，后端会返回 **405 Method Not Allowed**（不是 404）。

## 四、契约三：字段名（最容易静默失败）

前后端是两个程序，它们唯一的共识是 **JSON 里的字段名**。

### 4.1 查询参数

```js
// frontend/src/views/TodoView.vue
const query = reactive({
  pageNum: 1,
  pageSize: 5,
  keyword: '',
  finished: null      // null = 全部，0 = 未完成，1 = 已完成
})
```
```java
// backend/.../dto/TaskQuery.java
private Long pageNum = 1L;
private Long pageSize = 5L;
private String keyword;
private Integer finished;
```

Spring MVC 会按**字段名**从 URL 查询参数里取值并 set 进去。

> **为什么 `finished: null` 能表示「全部」？** axios 会自动忽略值为 `null` 的参数，
> URL 里根本不会出现 `finished`，后端拿到的就是默认值 `null`，条件构造器于是不拼这个条件。

### 4.2 返回字段

```java
// backend/.../dto/TaskStats.java
private long total;
private long finished;
private long unfinished;
private boolean fromCache;
private long ttl;
```
```js
// frontend/src/views/TodoView.vue
const stats = reactive({ total: 0, finished: 0, unfinished: 0, fromCache: false, ttl: 0 })
```

名字必须**逐字一致**：`fromCache` 写成 `from_cache` 或 `fromcache`，前端就永远是 `undefined`。

### 4.3 断了的表现：静默失效

把前端 `keyword` 改成 `keyWord`（大写 W）：

- 不报错、不 500
- 只是搜索框输入后，后端完全没收到关键词 → 查出来还是全部数据

**因为参数绑不上时，后端拿到的是默认值，一切照常运行。**

这是联调里最费时间的一类 bug，排查方法见第八节。

## 五、契约四：响应外壳

所有接口都返回三段式：

```json
{ "code": 200, "message": "成功", "data": { ... } }
```

前端用**拦截器**统一拆壳：

```js
// frontend/src/api/request.js
request.interceptors.response.use(
  (response) => {
    const body = response.data
    if (body === null || typeof body !== 'object' || body.code === undefined) {
      return body                 // 非统一格式（静态资源等）原样返回
    }
    if (body.code === 200) {
      return body.data            // 成功：只把 data 交给页面
    }
    ElMessage.error(body.message || '请求失败')
    return Promise.reject(new Error(body.message))
  },
  (error) => {
    ElMessage.error(error.response?.data?.message || '网络异常，请确认后端服务已启动')
    return Promise.reject(error)
  }
)
```

所以页面上写的是：

```js
const data = await pageTasks({ ...query })
list.value = data.records        // ✅ data 已经是后端 data 字段
// list.value = data.data.records  // ❌ 多套一层，undefined
```

**业务失败和网络失败是两条路**：

| 情况 | 走哪个分支 | 用户体验 |
|---|---|---|
| `code === 200` | 成功分支 | 正常渲染 |
| `code !== 200`（如标题为空） | 成功分支内 `reject` | 弹出后端给的 `message` |
| 后端没启动 / 超时 | 失败分支 | 弹「网络异常」 |

**实验**：打开新增弹窗，标题留空点保存 —— 前端校验会先拦住。
把前端 `rules` 里的 `required` 临时删掉再点保存，就能看到后端返回的「任务标题不能为空」。

## 六、契约五：日期格式

日期是前后端最容易对不上的东西。

```vue
<!-- 前端：value-format 让 v-model 存的是字符串 "2026-11-10" -->
<el-date-picker v-model="form.dueDate" type="date" value-format="YYYY-MM-DD" />
```
```java
// 后端：告诉 Jackson 按这个格式解析
@JsonFormat(pattern = "yyyy-MM-dd")
private LocalDate dueDate;
```

- 前端**不写** `value-format`：`form.dueDate` 是 `Date` 对象，序列化成 `"2026-11-10T00:00:00.000Z"`，后端解析 `LocalDate` 直接报错
- 后端**不写** `@JsonFormat`：Jackson 默认把 `LocalDate` 输出成数组 `[2026,11,10]`

两边的格式是**字符串级**的约定，改一边要想着另一边。

## 七、两套代理，一个相对路径

前端代码里只写相对路径 `/api`，为什么开发和生产都能通？因为**两个环境各有一套代理**：

```
开发（npm run dev）：
  浏览器 → Vite 5173 ──server.proxy──▶ http://localhost:8080

生产（Docker）：
  浏览器 → Nginx 8081 ──proxy_pass──▶ http://backend:8080
```

| | 开发 | 生产 |
|---|---|---|
| 谁转发 | Vite `server.proxy`（`vite.config.js`） | Nginx `proxy_pass`（`nginx.conf`） |
| 服务地址 | `localhost:8080` | `backend:8080`（容器服务名） |
| 生效时机 | `npm run dev` | 镜像构建后 |

**为什么用代理而不是直接请求 8080？**

1. 浏览器同源策略：`5173` 页面请求 `8080` 算跨域，会被拦
2. 走代理后浏览器只看到 `5173`，是**同源**请求
3. 接口地址统一写 `/api`，**换环境不用改代码**

> 后端另外还配了 CORS（`config/WebConfig.java`）作为第二道保险，
> 方便你用 curl 或别的端口直接调接口时不被拦。两套代理的细节见 [09 必要技术](09-必要技术.md)。

## 八、联调排查四步法

遇到「页面没数据 / 参数不生效」，按顺序查：

```
第 1 步：F12 → Network
   ├─ 请求发出去了吗？URL 对不对？状态码是多少？
   ├─ 404  → 路径契约（第二节）
   ├─ 405  → 方法契约（第三节）
   └─ 200  → 继续第 2 步

第 2 步：看响应体
   ├─ code 是 200 吗？data 里有数据吗？
   └─ code 不是 200 → 看 message

第 3 步：看后端日志
   └─ 有没有 SQL？参数是什么？（application.yml 已开 SQL 打印）

第 4 步：对照字段名
   └─ 前端 query / stats 的字段 vs TaskQuery / TaskStats 的字段
```

| 现象 | 最可能的原因 | 先看哪节 |
|---|---|---|
| 请求 404 | 路径前缀不一致 | 第二节 |
| 请求 405 | HTTP 方法不一致 | 第三节 |
| 有数据但筛选/搜索无效 | 字段名拼错 | 第四节 |
| 页面拿不到数据，返回正常 | 拦截器拆包后又 `.data` | 第五节 |
| 日期保存报错 | `value-format` / `@JsonFormat` | 第六节 |
| 跨域报错 | 直接写了完整 URL 绕过代理 | 第七节 |
| 全站「网络异常」 | 后端没启动 / 端口不对 | 第七节 |

## 九、动手实验（改坏再改好）

1. **改字段名**：`TodoView.vue` 里 `keyword` 改成 `keyWord` → 搜索失效但不报错 → 改回来
2. **改前缀**：`request.js` 的 `baseURL` 改成 `'/api2'` → 404 → 改回来
3. **看拆包**：在 `loadList` 里 `console.log(data)`，确认拿到的已经是 `data` 字段而不是整个响应
4. **加参数**：在 `query` 里加一个 `foo: 1`，看 Network 里 URL 多了 `&foo=1`，后端并不认识它（不会报错）

做完这四个实验，你对「契约」的理解就比读十遍文档扎实。

## 十、自测：能不能答上来

1. `baseURL: '/api'` 和 `task.js` 里的 `'/tasks'` 为什么不能重复写 `/api`？
2. 参数名拼错，为什么常常不报错？
3. 拦截器 `return body.data` 之后，页面再写 `.data` 会怎样？
4. `PUT` 和 `PATCH` 在本项目里分别用在哪？
5. 开发和生产各由谁做代理？

<details>
<summary>参考答案</summary>

1. 两者会拼在一起变成 `/api/api/tasks`，后端没有这个路径。
2. Spring MVC 按名绑定，绑不上就用默认值/null，接口照常返回。
3. 拿到 `undefined`，因为外层已经拆掉了，只剩业务数据。
4. `PUT` 用于编辑表单整体保存；`PATCH` 用于表格里切换完成状态。
5. 开发用 Vite `server.proxy`，生产用 Nginx `proxy_pass`。

</details>
