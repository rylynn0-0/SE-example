# 14 · 删：确认框 → 逻辑删除 → 行消失

> **一句话**：点删除 → 二次确认 → `deleteTask` → `DELETE /api/tasks/{id}` →
> Controller → Service → `@TableLogic` 把 DELETE 改写成 `UPDATE deleted=1` →
> 清缓存 → `loadAll` → 行消失。
>
> 公共部分见 [10 总览](10-增删改查总览.md)。
> 代码里的 `//`、`--` 是中文解释，写在代码后面；新手先读注释，再读代码。

---

## 一、先看流程

```
点「删除」
  → ElMessageBox.confirm(...)
  → 点「取消」：直接 return，不发请求
  → 点「删除」
  → deleteTask(row.id)
  → DELETE /api/tasks/9
  → Vite / Nginx 代理到 8080
  → TaskController.delete(id)
  → TaskServiceImpl.removeTask(id)
  → removeById(id) + @TableLogic
  → UPDATE t_task SET deleted=1 WHERE id=? AND deleted=0
  → clearStatsCache()
  → Result.ok()  { code:200, data:null }
  → 本页最后一条？pageNum -= 1
  → loadAll()
  → 列表少一行、分页和统计更新
```

## 二、前端：先确认，再删除

`TodoView.vue:237-260`（节选）：

```js
async function handleDelete(row) { // 点“删除”时执行
  try { // 弹确认框
    await ElMessageBox.confirm(`确定要删除任务「${row.title}」吗？`, '删除确认') // 点“删除”才继续；点“取消”会进 catch
  } catch { // 点“取消”会走到这里
    return // 直接结束，不发 DELETE，直接结束，不发 DELETE
  }

  try { // 发 DELETE 请求
    await deleteTask(row.id) // 真正发 DELETE 请求
    ElMessage.success('删除成功') // 成功提示
    if (list.value.length === 1 && query.pageNum > 1) { // 删的是本页最后一条
      query.pageNum -= 1 // 页码回退一页，避免空白
    }
    await loadAll() // 重新查列表和统计
  } catch (e) { // 失败时拦截器已经弹过提示
  }
}
```

两个细节：

- `ElMessageBox.confirm` 取消时会 reject，`catch` 里直接 `return`，不会发 DELETE。
- 删除本页最后一条时，页码回退一页，避免出现空白页。

## 四、后端：删除成功返回 true，否则 404

`TaskController.java:168-177`：

```java
@DeleteMapping("/{id}") // 处理 DELETE /api/tasks/{id}
public Result<Void> delete(@PathVariable Long id) { // id 来自 URL
    if (!taskService.removeTask(id)) { // false=不存在/已删
        return Result.fail(404, "任务不存在"); // 业务失败，code=404
    }
    return Result.ok(); // 删除成功，data 为 null
}
```

`TaskServiceImpl.java:235-242`：

```java
@Transactional(rollbackFor = Exception.class) // 出异常回滚
public boolean removeTask(Long id) { // 返回 true=删成功，false=不存在
    boolean removed = this.removeById(id); // 看起来像 DELETE，实际被 @TableLogic 改写成 UPDATE
    clearStatsCache(); // 统计变了，删掉 Redis 缓存
    return removed; // true=删到了，false=id 不存在或已经删过
}
```

## 五、关键：`removeById` 实际是 UPDATE

实体上的 `@TableLogic`（`Task.java:104-106`）：

```java
@TableLogic // 告诉 MyBatis-Plus：这个字段是逻辑删除标记
@JsonIgnore // 不要让 deleted 出现在接口响应里
private Integer deleted; // 0=正常，1=已删除
```

所以 `removeById(id)` 生成的 SQL 是：

```sql
UPDATE t_task                   -- 任务表
SET deleted = 1             -- 标记删除，不是真删
WHERE id = ? AND deleted = 0; -- 只删还没删过的
```

效果：

- 记录还在表里，只是 `deleted` 从 0 变成 1。
- 所有查询自动加 `deleted=0`，所以列表和统计看不到它。
- 想恢复，直接执行 `UPDATE t_task SET deleted=0 WHERE id=9;`。

## 六、返回与回显

成功响应（JSON 不能写注释，字段说明看下面表格）：

```json
{ "code": 200, "message": "成功", "data": null }
```

| 字段 | 意思 |
|---|---|
| `code` | 200 表示删除成功 |
| `message` | 提示文字 |
| `data` | 删除没有返回数据，所以是 `null` |

`loadAll` 之后：

- 列表查询带 `deleted=0`，被删的行不再返回 → 表格少一行。
- `total` 减少 → 分页总页数可能变化。
- 统计重新 `COUNT` → 总数和对应状态数字减少。
- 缓存被删掉 → 这次统计是「回源」，下次刷新才「命中」。

## 八、3 个常见坑

| 现象 | 原因 |
|---|---|
| 点删除没反应 | 确认框被取消，或 `catch` 吞了 |
| 第二次删同一条返回 404 | 已经逻辑删除，`WHERE deleted=0` 匹配不到 |
| 数据库里还能查到 | 逻辑删除不是物理删除，看 `deleted` 字段 |
