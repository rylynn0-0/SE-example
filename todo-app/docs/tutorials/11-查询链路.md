# 11 · 查：点击「查询」→ 表格刷新

> **一句话**：点查询 → `handleSearch` → `pageTasks` → `GET /api/tasks` →
> `TaskController.page` → `TaskServiceImpl.pageTasks` → 分页 SQL → `list/total` → 表格刷新。
>
> 公共部分（12 环节、契约、表结构、代理、统一响应）见
> [10 总览](10-增删改查总览.md)。
>
> 代码里的 `//` 是中文解释，写在代码后面；新手先读注释，再读代码。

---

## 一、先看流程

```
点「查询」
  → query.pageNum = 1
  → loadList()
  → pageTasks({ ...query })
  → GET /api/tasks?pageNum=1&pageSize=5&keyword=报告
  → Vite / Nginx 代理到 8080
  → TaskController.page(TaskQuery)
  → TaskServiceImpl.pageTasks
  → COUNT(*) + SELECT ... LIMIT ?
  → Result.ok(IPage<Task>) → JSON
  → 拦截器拆壳 → list = data.records
  → 表格刷新
```

## 二、前端：按钮只改状态

`TodoView.vue:39-44`：

```js
const query = reactive({ // reactive：对象属性变了，页面会跟着变
  pageNum: 1,      // 当前第几页；后端从 1 开始数
  pageSize: 5,     // 每页显示几条
  keyword: '',     // 搜索关键词；空字符串表示不搜索
  finished: null   // 完成状态：null=全部，0=未完成，1=已完成
})
```

`TodoView.vue:152-155`：

```js
function handleSearch() { // 点“查询”或输入框回车时执行
  query.pageNum = 1 // 搜索时回到第 1 页，避免停在第 3 页导致空白
  loadList()        // 调下面的函数，真正去请求后端
}
```

按钮和输入框这样绑：

```vue
<el-input v-model="query.keyword" @keyup.enter="handleSearch" /> <!-- 输入框内容绑定 keyword，回车触发查询 -->
<el-select v-model="query.finished" @change="handleSearch"> <!-- 下拉框绑定完成状态，选完立刻查询 -->
  <el-option label="未完成" :value="0" /> <!-- 选中后 finished=0 -->
  <el-option label="已完成" :value="1" /> <!-- 选中后 finished=1 -->
</el-select>
<el-button @click="handleSearch">查询</el-button> <!-- 点击调用 handleSearch -->
```

> 为什么要 `pageNum = 1`？你在第 3 页搜索，结果只有 1 页时，
> 还请求第 3 页就会空白。重置到第 1 页最安全。

## 三、发请求：`loadList` + `pageTasks`

`TodoView.vue:107-117`：

```js
async function loadList() { // async：函数里有 await，要等请求回来
  loading.value = true // 打开表格的转圈遮罩

  try { // 发请求，等后端返回
    const data = await pageTasks({ ...query }) // 复制查询条件发给后端，等结果
    list.value = data.records        // 当前页数据 → 表格
    total.value = Number(data.total) // 总条数转数字 → 分页组件
  } finally { // 收尾：一定关遮罩
    loading.value = false // 不管成功失败都关遮罩，否则一直转圈
  }
}
```

`api/task.js:27-30`：

```js
export function pageTasks(params) { // 查询接口封装
  return request.get('/tasks', { params }) // baseURL '/api' + '/tasks' = /api/tasks；params 拼成 URL 参数
}
```

浏览器先发给 5173（开发）或 8081（Docker），再由 Vite/Nginx 转到 8080。

## 四、后端：接参数 → 拼条件 → 分页

`TaskController.java:68-72`：

```java
@GetMapping // 处理 GET /api/tasks
public Result<IPage<Task>> page(TaskQuery query) { // query 由 Spring 从 URL 参数自动填充
    return Result.ok(taskService.pageTasks(query)); // 调 Service，再包成统一响应
}
```

`TaskQuery` 会自动绑定 URL 参数，默认 `pageNum=1`、`pageSize=5`。

`TaskServiceImpl.java:81-102`：

```java
Page<Task> page = new Page<>(query.getPageNum(), query.getPageSize()); // 第几页、每页几条

LambdaQueryWrapper<Task> wrapper = new LambdaQueryWrapper<Task>() // 条件构造器
        .like(StringUtils.hasText(query.getKeyword()), Task::getTitle, query.getKeyword()) // 有 keyword 才拼 title LIKE ?
        .eq(query.getFinished() != null, Task::getFinished, query.getFinished()) // 有 finished 才筛选
        .orderByAsc(Task::getFinished) // 未完成（0）排在已完成（1）前面
        .orderByDesc(Task::getPriority) // 优先级高的在前（3 > 2 > 1）
        .orderByDesc(Task::getId); // 同优先级时新建的在前

return this.page(page, wrapper); // MyBatis-Plus：先 COUNT，再 SELECT ... LIMIT
```

实际 SQL：

```sql
SELECT COUNT(*) AS total        -- 先查总条数，分页组件要算总页数
FROM t_task                     -- 任务表
WHERE deleted=0                 -- 逻辑删除：只看未删除的
  AND (title LIKE ?);           -- ? 是关键词参数，如 %报告%

SELECT ...                      -- 查所有列（这里省略具体列名）
FROM t_task                     -- 任务表
WHERE deleted=0                 -- 同样只看未删除的
  AND (title LIKE ?)            -- 关键词模糊匹配
ORDER BY finished ASC,          -- 未完成在前
         priority DESC,         -- 优先级高的在前
         id DESC                -- 新建的在前
LIMIT ?;                        -- 只取当前页
```

- `deleted=0`：`@TableLogic` 自动加的。
- `LIMIT` / `COUNT(*)`：分页拦截器自动加的。

## 五、回显：`list` 和 `total` 变了，表格就变

```js
list.value = data.records        // 表格的数据源
total.value = Number(data.total) // 分页组件用它算总页数
```

```vue
<el-table v-loading="loading" :data="list"> <!-- :data=list：list 一变，表格自动重绘 -->
  <el-table-column prop="title" label="任务标题" /> <!-- 这一列显示每行的 title 字段 -->
  <el-table-column prop="priority" label="优先级" /> <!-- 显示 priority 字段 -->
  <el-table-column prop="dueDate" label="截止日期" /> <!-- 显示 dueDate 字段 -->
</el-table>

<el-pagination :total="total" :page-size="query.pageSize" /> <!-- 总条数 / 每页条数 -->
```

统计卡片是另一个请求：`GET /api/tasks/stats`。
第一次通常显示「Redis 回源」，刷新一次变成「Redis 命中 · 剩余 xx s」。

## 六、请求和响应长什么样

```http
GET /api/tasks?pageNum=1&pageSize=5&keyword=报告
```

| 部分 | 意思 |
|---|---|
| `GET` | 查询用 GET |
| `/api/tasks` | 任务列表接口 |
| `pageNum=1` | 第 1 页 |
| `pageSize=5` | 每页 5 条 |
| `keyword=报告` | 标题里包含“报告” |

JSON 不能写注释，字段说明看下面表格。

```json
{
  "code": 200,
  "message": "成功",
  "data": {
    "records": [
      {
        "id": 1,
        "title": "完成软工课程设计开题报告",
        "priority": 3,
        "finished": 0,
        "dueDate": "2026-11-14"
      }
    ],
    "total": 1,
    "current": 1,
    "pages": 1
  }
}
```

| 字段 | 意思 |
|---|---|
| `code` | 200 表示业务成功 |
| `message` | 提示文字 |
| `data.records` | 当前页的数据数组 |
| `data.total` | 总条数 |
| `data.current` | 当前第几页 |
| `data.pages` | 总页数 |

前端拦截器返回的是 `data`，所以页面直接拿 `data.records`。

## 八、3 个常见坑

| 现象 | 原因 |
|---|---|
| 404 | `baseURL` 或 Controller 路径不一致 |
| 405 | 用了 POST 调查询 |
| 搜索没结果但不报错 | 参数名写错，或 `finished=null` 被 axios 忽略 |
