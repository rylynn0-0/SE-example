## 一、链路总览

```
点「查询」
  → query.pageNum = 1
  → loadList()
  → pageTasks({ ...query })
  → axios：GET /api/tasks?pageNum=1&pageSize=5&keyword=报告
  → Vite / Nginx 把 /api 转到 backend:8080
  → TaskController.page(TaskQuery)
  → TaskServiceImpl.pageTasks：拼条件 + 分页
  → MyBatis-Plus 生成 COUNT(*) 和 SELECT ... LIMIT
  → Result.ok(IPage<Task>) → JSON
  → axios 拦截器只返回 data
  → list = data.records，total = data.total
  → 表格刷新
```

## 二、页面状态：先有数据，才有界面

`TodoView.vue:39-44`：

```js
const query = reactive({ // reactive：对象属性变了，页面会跟着变
  pageNum: 1,      // 当前第几页；后端从 1 开始数
  pageSize: 5,     // 每页显示几条
  keyword: '',     // 搜索关键词；空串表示不搜索
  finished: null   // 完成状态：null=全部，0=未完成，1=已完成
})
```

- **做什么**：保存查询条件。
- **为什么**：搜索框、下拉框、分页都读写这一份数据，请求参数只从它来。

`TodoView.vue:27-33`：

```js
const loading = ref(false) // 表格是否在加载
const list = ref([])       // 当前页数据
const total = ref(0)       // 满足条件的总条数
```

- **做什么**：保存表格状态。
- **为什么**：`ref` 的基本类型/数组变了，模板里用到它的地方会自动重绘。

## 三、按钮：把点击变成函数调用

`TodoView.vue` 模板（节选）：

```vue
<el-input v-model="query.keyword" @keyup.enter="handleSearch" /> <!-- 输入内容同步到 keyword，回车查询 -->
<el-select v-model="query.finished" @change="handleSearch"> <!-- 选中状态同步到 finished，选完查询 -->
  <el-option label="未完成" :value="0" /> <!-- 选中后 finished=0 -->
  <el-option label="已完成" :value="1" /> <!-- 选中后 finished=1 -->
</el-select>
<el-button @click="handleSearch">查询</el-button> <!-- 点击查询 -->
```

- **做什么**：用户输入/点击时改 `query`，或调用 `handleSearch`。
- **为什么**：`v-model` 双向绑定，页面输入和 JS 变量保持同步；`@click` 只负责触发函数，不直接发请求。

`TodoView.vue:152-155`：

```js
function handleSearch() { // 点“查询”或回车时执行
  query.pageNum = 1 // 搜索时回到第 1 页
  loadList()        // 调加载函数
}
```

- **做什么**：重置页码，然后加载列表。
- **为什么**：如果你在第 3 页搜索，而结果只有 1 页，继续请求第 3 页会得到空表格；回到第 1 页避免“假空白”。

## 四、发请求：`loadList` + `pageTasks`

`TodoView.vue:107-117`：

```js
async function loadList() { // async：函数里有 await
  loading.value = true // 打开表格遮罩

  try {
    const data = await pageTasks({ ...query }) // 复制查询条件，等后端返回
    list.value = data.records        // 当前页数据 → 表格
    total.value = Number(data.total) // 总条数 → 分页组件
  } finally {
    loading.value = false // 成功失败都关遮罩
  }
}
```

- **做什么**：请求当前页数据，写进 `list` 和 `total`。
- **为什么**：
  - `{ ...query }` 复制一份，避免请求过程中对象被改。
  - `try/finally` 保证请求失败也会关闭遮罩。
  - `total` 转成 `Number`，分页组件要的是数字。

`api/task.js:27-30`：

```js
export function pageTasks(params) { // 查询接口封装
  return request.get('/tasks', { params }) // GET /api/tasks?...；params 拼成查询串
}
```

- **做什么**：把“查询任务”封装成一个函数。
- **为什么**：页面只关心“调哪个方法”，不关心 URL、HTTP 方法；以后接口路径变了只改这里。

## 五、axios 和代理：请求怎么出去

`api/request.js:15-18`：

```js
const request = axios.create({ // 创建 axios 实例
  baseURL: '/api',              // 所有请求自动加 /api
  timeout: 10000                // 10 秒超时
})
```

- **做什么**：创建统一的 HTTP 客户端。
- **为什么**：接口都写 `/tasks` 这种相对路径，换环境只改代理，不改业务代码。

`api/request.js:42-59`（简化）：

```js
request.interceptors.response.use((response) => { // 后端响应先到这里
  const body = response.data // 后端返回的 JSON
  if (body.code === 200) return body.data // 成功：只把 data 交给页面
  ElMessage.error(body.message) // 失败：弹提示
  return Promise.reject(new Error(body.message)) // 中断后续代码
})
```

- **做什么**：统一拆 `{ code, message, data }` 外壳。
- **为什么**：页面不用每次写 `res.data.data`，也不用每个请求都判断 `code`。

代理：

```text
开发：浏览器 → http://localhost:5173/api/tasks → Vite → http://localhost:8080/api/tasks
Docker：浏览器 → http://localhost:8081/api/tasks → Nginx → http://backend:8080/api/tasks
```

- **做什么**：把 `/api` 开头的请求转给后端。
- **为什么**：浏览器只认识 5173/8081，同源请求没有跨域；前端也不需要写死后端地址。

配置在 `vite.config.js:28-39`、`nginx.conf:23-29`，细节见 [10 总览](10-增删改查总览.md) §4.3。

## 六、后端 Controller：接参数

`TaskController.java:68-72`：

```java
@GetMapping // 处理 GET /api/tasks
public Result<IPage<Task>> page(TaskQuery query) { // query 由 Spring 从 URL 参数填充
    return Result.ok(taskService.pageTasks(query)); // 调 Service，再包成统一响应
}
```

- **做什么**：接收查询参数，调用 Service，包装结果。
- **为什么**：Controller 只做“收参数、校验、返回”，业务和 SQL 不放在这里。

`TaskQuery.java:23-39`：

```java
public class TaskQuery { // 查询参数对象
    private Long pageNum = 1L;   // 页码，默认 1
    private Long pageSize = 5L;  // 每页条数，默认 5
    private String keyword;      // 标题关键词，可空
    private Integer finished;    // 完成状态，可空
}
```

- **做什么**：把 URL 参数装进一个对象。
- **为什么**：参数多时方法签名不易读；Spring 会按字段名自动绑定，`?pageNum=2` 就调用 `setPageNum(2)`。

## 七、后端 Service：拼条件 + 分页

`TaskServiceImpl.java:81-102`：

```java
Page<Task> page = new Page<>(query.getPageNum(), query.getPageSize()); // 第几页、每页几条

LambdaQueryWrapper<Task> wrapper = new LambdaQueryWrapper<Task>() // 条件构造器
        .like(StringUtils.hasText(query.getKeyword()), Task::getTitle, query.getKeyword()) // 有 keyword 才拼 LIKE
        .eq(query.getFinished() != null, Task::getFinished, query.getFinished()) // 有 finished 才筛选
        .orderByAsc(Task::getFinished) // 未完成在前
        .orderByDesc(Task::getPriority) // 优先级高的在前
        .orderByDesc(Task::getId); // 新建的在前

return this.page(page, wrapper); // 交给 MyBatis-Plus 执行
```

- **做什么**：根据参数动态拼 WHERE 和 ORDER BY，再执行分页。
- **为什么**：
  - `StringUtils.hasText` 为 false 时，这个条件不拼进 SQL，所以不用写一堆 `if`。
  - `Task::getTitle` 是方法引用，字段名写错编译期就报错，比字符串 `"title"` 安全。

`MybatisPlusConfig.java:28-34`：

```java
@Bean
public MybatisPlusInterceptor mybatisPlusInterceptor() { // 注册 MyBatis-Plus 拦截器
    MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
    interceptor.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL)); // 加 MySQL 分页插件
    return interceptor;
}
```

- **做什么**：让 `page()` 真的分页。
- **为什么**：不注册它，`page()` 会退化成查全表，`pageNum/pageSize` 就不起作用。

## 八、Mapper、实体和 SQL

`TaskMapper.java:22-27`：

```java
@Mapper
public interface TaskMapper extends BaseMapper<Task> { // 继承 BaseMapper，单表 CRUD 不用写 SQL
}
```

- **做什么**：声明数据访问接口。
- **为什么**：MyBatis 启动时为它生成代理对象，`selectPage`、`insert` 等方法自动对应 SQL。

`Task.java` 关键注解：

```java
@TableName("t_task") // 对应数据库表 t_task
public class Task {
    @TableId(type = IdType.AUTO) // 主键由数据库自增
    private Long id;

    @TableLogic // 逻辑删除标记
    @JsonIgnore // 不返回给前端
    private Integer deleted;
}
```

- **做什么**：告诉 MyBatis-Plus 表名、主键、逻辑删除字段。
- **为什么**：有了注解，Java 对象和表自动映射；查询自动加 `deleted=0`，删除自动改成 `UPDATE deleted=1`。

实际 SQL：

```sql
SELECT COUNT(*) AS total        -- 先查总条数，分页组件要算总页数
FROM t_task                     -- 任务表
WHERE deleted=0                 -- 只看未删除的
  AND (title LIKE ?);           -- 关键词参数，如 %报告%

SELECT ...                      -- 查所有列（这里省略列名）
FROM t_task
WHERE deleted=0                 -- 同样只看未删除的
  AND (title LIKE ?)            -- 关键词匹配
ORDER BY finished ASC,          -- 未完成在前
         priority DESC,         -- 优先级高的在前
         id DESC                -- 新建的在前
LIMIT ?;                        -- 只取当前页
```

- **做什么**：先数总数，再取当前页。
- **为什么**：分页组件要 `total` 算页数；`LIMIT` 避免一次查全表。

## 九、返回和回显

`Result.java:42-59`：

```java
public static <T> Result<T> ok(T data) { // 成功响应
    Result<T> result = new Result<>();
    result.setCode(200);       // 业务成功
    result.setMessage("成功"); // 提示
    result.setData(data);      // 真正的数据
    return result;
}
```

- **做什么**：把数据包成 `{ code, message, data }`。
- **为什么**：前端能区分“成功但数据为空”和“失败”；所有接口结构一致，拦截器才能统一处理。

响应：

```json
{
  "code": 200,
  "message": "成功",
  "data": {
    "records": [ { "id": 1, "title": "完成软工课程设计开题报告" } ],
    "total": 1,
    "current": 1,
    "pages": 1
  }
}
```

| 字段 | 意思 |
|---|---|
| `code` | 200 表示业务成功 |
| `message` | 提示文字 |
| `data.records` | 当前页数据 |
| `data.total` | 总条数 |
| `data.current` | 当前页 |
| `data.pages` | 总页数 |

回显：

```js
list.value = data.records        // 表格数据
total.value = Number(data.total) // 分页总条数
```

- **做什么**：把后端数据放进响应式变量。
- **为什么**：`el-table` 的 `:data="list"`、`el-pagination` 的 `:total="total"` 会自动跟着变，页面不需要手动操作 DOM。

## 十、统计卡片：Redis 缓存链路

`TodoView.vue:125-128`：

```js
async function loadStats() { // 加载三个统计卡片
  const data = await getStats() // GET /api/tasks/stats
  Object.assign(stats, data) // 把 total/finished/unfinished/fromCache/ttl 写进 stats
}
```

- **做什么**：请求统计数据，合并到 `stats`。
- **为什么**：统计需要全表 `COUNT`，前端只有当前页数据，算不出来。

`api/task.js:90-92`：

```js
export function getStats() { // 统计接口封装
  return request.get('/tasks/stats') // GET /api/tasks/stats
}
```

- **做什么**：调用统计接口。
- **为什么**：和其他接口一样，路径、方法集中管理。

`TaskServiceImpl.java:112-155`（简化）：

```java
public TaskStats stats() { // 查统计
    try {
        String cachedJson = redisTemplate.opsForValue().get(STATS_KEY); // GET todo:stats
        if (cachedJson != null) { // 缓存命中
            TaskStats cached = objectMapper.readValue(cachedJson, TaskStats.class); // JSON → 对象
            cached.setFromCache(true); // 告诉前端这次是命中
            Long ttl = redisTemplate.getExpire(STATS_KEY, TimeUnit.SECONDS); // 剩余秒数
            cached.setTtl(ttl == null ? 0L : ttl); // 防止 null 拆箱
            return cached; // 直接返回，不查数据库
        }
    } catch (Exception e) { // Redis 挂了就降级
    }

    long total = this.count(); // SELECT COUNT(*) WHERE deleted=0
    long finished = this.count(new LambdaQueryWrapper<Task>().eq(Task::getFinished, 1)); // 已完成数
    TaskStats stats = new TaskStats(); // 组装结果
    stats.setTotal(total); // 总数
    stats.setFinished(finished); // 已完成
    stats.setUnfinished(total - finished); // 未完成
    stats.setFromCache(false); // 这次是回源

    try {
        String json = objectMapper.writeValueAsString(stats); // 对象 → JSON
        redisTemplate.opsForValue().set(STATS_KEY, json, 60, TimeUnit.SECONDS); // 写缓存 60 秒
    } catch (Exception e) { // 写缓存失败不影响本次返回
    }
    return stats;
}
```

- **做什么**：先读 Redis，未命中再查 MySQL，最后写回 Redis。
- **为什么**：
  - 统计要两次 `COUNT`，缓存 60 秒能减少数据库压力。
  - 先读缓存、未命中回源、写回缓存，这就是 Cache-Aside（旁路缓存）。
  - 写操作（增/改/删）都会 `DEL todo:stats`，否则统计卡片会显示旧数字。

## 十二、常见坑

| 现象 | 原因 |
|---|---|
| 404 | `baseURL` 或 Controller 路径不一致 |
| 405 | 用了 POST 调查询 |
| 搜索没结果但不报错 | 参数名写错，或 `finished=null` 被 axios 忽略 |
| 表格空但 `total>0` | 页码越界，搜索时忘了 `pageNum=1` |
| 分页不生效 | 没注册分页拦截器 |
