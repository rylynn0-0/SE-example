# 15 · 移动端：把 Web 项目迁移到 uni-app x

> 一句话：**后端、数据库、Redis、Docker 全部不动；新增一个 `mobile/` 客户端，用同一套 `.uvue` 页面同时产出 Android、iOS、H5。**
>
> 先看这一章，建立整体认识；真正操作 Android 云打包时，跟着 [16 Android 云打包](16-Android云打包.md) 一步一步点。

---

## 本章你会

- 知道 uni-app x 和原来的 Vue 3 Web 端是什么关系
- 知道哪些代码能复用、哪些必须重写
- 看懂 `mobile/` 目录里每个文件的作用
- 看懂手机端请求后端的完整链路
- 知道 Android、iOS、H5 的地址和打包差异
- 知道 Android 云打包前必须准备什么

## 一、先看结论：迁移的不是整个项目

原来的项目是：

```
Vue 3 + Element Plus + Axios + Vite
        │
        ▼
Spring Boot + MyBatis-Plus
        │
        ├── MySQL
        └── Redis
```

迁移后是：

```
┌──────────────────────────────┐
│  todo-app/frontend/          │  原来的 Web 端，继续保留
│  Vue 3 + Element Plus        │
└──────────────┬───────────────┘
               │
               │  同一套后端 API
               ▼
┌──────────────────────────────┐
│  todo-app/mobile/            │  新增的 uni-app x 客户端
│  Android / iOS / H5          │
└──────────────┬───────────────┘
               │
               ▼
┌──────────────────────────────┐
│  Spring Boot + MySQL + Redis │  完全不动
└──────────────────────────────┘
```

**只做三件事：**

1. 新建 `mobile/` 工程；
2. 把页面和请求层用 uni-app x 重写；
3. 后端补一个 `GET /api/tasks/{id}`，给编辑页回填数据。

数据库表、Redis key、Docker Compose、Knife4j 都不需要改。

---

## 二、为什么选 uni-app x

| | 原来的 Web 端 | uni-app x |
|---|---|---|
| 页面文件 | `.vue` | `.uvue` |
| UI 库 | Element Plus | 内置组件 + 自定义样式 |
| 请求 | Axios | `uni.request` |
| 路由 | Vue Router | `pages.json` + `uni.navigateTo` |
| 运行环境 | 浏览器 | Android / iOS 原生渲染，或 H5 |
| 打包产物 | 静态网站 | APK / IPA / H5 / 小程序 |

选它的原因：

1. 还是 Vue 3 的组合式 API，`ref`、`async/await`、`v-for` 都能继续用；
2. 一套业务代码可以出 Android、iOS、H5；
3. App 端不是简单套 WebView，页面会编译成原生渲染；
4. 不需要为了手机端再学 Flutter 或 React Native。

代价也要提前知道：

- **Element Plus 不能用了**，表格、弹窗、分页要改成手机端组件；
- uni-app x 的 CSS 是 Web CSS 的子集，不能依赖复杂 DOM 选择器；
- Android 真机、iOS 真机、H5 的后端地址不一样；
- iOS 打包仍然需要 Apple 证书。

## 三、技术栈逐项映射

| 原来的东西 | 迁移后 | 说明 |
|---|---|---|
| `TodoView.vue` | `pages/index/index.uvue` | 首页：统计、搜索、筛选、列表 |
| `App.vue` | `App.uvue` | 应用入口、全局样式 |
| `router/index.js` | `pages.json` | 页面注册，不用手写路由表 |
| `el-table` | `view` + `text` 任务卡片 | 手机屏幕不适合横向表格 |
| `el-pagination` | “加载更多”按钮 | 移动端更自然 |
| `el-dialog` | 独立编辑页 | 避免小屏键盘遮挡 |
| `el-input` | `input` | 内置组件 |
| `el-select` | 顶部筛选胶囊 | 全部 / 未完成 / 已完成 |
| `el-date-picker` | `picker mode="date"` | 调用系统日期选择器 |
| `el-switch` | 自定义完成圆钮 | 点击后调接口，成功再刷新 |
| `ElMessage` | `uni.showToast` | 跨端提示 |
| `ElMessageBox.confirm` | `uni.showModal` | 跨端确认框 |
| Axios | `api/request.uts` | Promise 封装 `uni.request` |
| Vite 代理 | H5 用 Nginx；App 直连 | 见第六节 |
| `px` | `rpx` + flex | 适配不同屏宽 |

### 3.1 哪些能直接复用

- 后端所有接口
- 数据库表结构
- Redis 缓存逻辑
- 接口字段名：`title`、`priority`、`finished`、`dueDate`
- Vue 3 的响应式写法
- 业务规则：标题必填、优先级 1/2/3、逻辑删除

### 3.2 哪些必须重写

- 页面模板：Element Plus 标签全部换成 `view` / `text` / `input`
- 请求层：Axios 换成 `uni.request`
- 路由：Vue Router 换成 `pages.json`
- 弹窗：改成独立页面或自定义遮罩
- 分页：改成“加载更多”
- 样式：从桌面表格布局改成移动卡片布局

### 4.1 为什么页面是 `.uvue`

uni-app x 的页面和组件统一用 `.uvue`，结构还是三块：

```vue
<template>
  <!-- 界面 -->
</template>

<script setup lang="uts">
  // 逻辑，UTS 是 TypeScript 风格
</script>

<style>
  /* 样式，App 端是 CSS 子集 */
</style>
```

先说结论：**新手先把 `.uvue` 当成“Vue 单文件组件 + 少量限制”即可**，不要一上来研究 UTS 编译原理。

## 五、请求链路：手机上一次点击经过了谁

以首页搜索为例：

```
① 用户输入关键词，点键盘“搜索”
② pages/index/index.uvue 的 handleSearch()
③ api/task.uts 的 pageTasks()
④ api/request.uts 的 request()
⑤ uni.request 发出 GET
⑥ Android 直连 http://电脑IP:8080/api
   （H5 走 /api，由 Nginx 转发）
⑦ Spring Boot TaskController.page()
⑧ TaskServiceImpl.pageTasks()
⑨ MyBatis-Plus 查 MySQL
⑩ 返回 { code, message, data }
⑪ request.uts 检查 code，拆出 data
⑫ pageTasks() 把 JSON 转成 Task[]
⑬ 页面 tasks.value = ...
⑭ 列表刷新
```

和原来的 Axios 链路相比，只换了第 ③④⑤ 步，后端第 ⑦⑧⑨ 步完全一样。

### 5.1 `request.uts` 干了什么

```ts
export function request(
  method: RequestMethod,
  path: string,
  body: UTSJSONObject | null = null
): Promise<UTSJSONObject> {
  return new Promise<UTSJSONObject>((resolve, reject) => {
    const options: RequestOptions<UTSJSONObject> = {
      url: getApiBase() + path,
      method: method,
      timeout: 12000,
      dataType: 'json',
      success: (res) => {
        // 1. 检查 HTTP 状态码
        // 2. 检查 body.code === 200
        // 3. 把 body.data 交给页面
      },
      fail: (err) => {
        // 网络层错误
      }
    }
    uni.request(options)
  })
}
```

它替代了原来 Axios 的三个职责：

| Axios 里的东西 | uni-app x 里的对应 |
|---|---|
| `baseURL` | `getApiBase()` |
| 响应拦截器拆 `{code,message,data}` | `request.uts` 的 `success` 回调 |
| `ElMessage.error` | `uni.showToast` |

### 5.2 为什么不用 Axios

App 端没有浏览器环境，Axios 依赖的 XMLHttpRequest / fetch 在 Android 原生渲染层不可用。`uni.request` 是 uni-app x 官方跨端网络 API，Android、iOS、H5 都能用。

## 六、跨平台的关键：后端地址不能写死

同一个后端，在不同运行环境里的地址不同：

| 运行环境 | 默认地址 | 原因 |
|---|---|---|
| H5 + Nginx | `/api` | 同源，Nginx 转发 |
| Android 模拟器 | `http://10.0.2.2:8080/api` | 模拟器里的 `localhost` 是模拟器自己 |
| iOS 模拟器 | `http://127.0.0.1:8080/api` | 模拟器共享电脑网络 |
| Android/iOS 真机 | `http://电脑局域网IP:8080/api` | 手机和电脑要在同一 Wi-Fi |
| 微信小程序 | `https://你的域名/api` | 必须 HTTPS，并配置合法域名 |

`api/config.uts` 用条件编译给每个平台默认值：

```ts
export function getDefaultApiBase(): string {
  let base = 'http://localhost:8080/api'

  // #ifdef H5
  base = '/api'
  // #endif

  // #ifdef APP-ANDROID
  base = 'http://10.0.2.2:8080/api'
  // #endif

  // #ifdef APP-IOS
  base = 'http://127.0.0.1:8080/api'
  // #endif

  return base
}
```

同时首页提供“服务器设置”，用户可手动覆盖：

```
http://192.168.1.10:8080/api
```

覆盖值保存在 `uni.setStorageSync`，下次启动仍然有效。

### 6.1 真机为什么不能填 localhost

```
手机上的 localhost = 手机自己
电脑上的 localhost = 电脑
```

手机要访问电脑，必须用电脑在局域网里的 IP，例如 `192.168.1.10`。

### 6.2 为什么 Android 要允许明文 HTTP

开发阶段后端是：

```
http://192.168.1.10:8080
```

Android 9 以后默认禁止明文 HTTP。工程根目录的 `AndroidManifest.xml` 已配置：

```xml
<application android:usesCleartextTraffic="true" />
```

正式发布时建议改成 HTTPS。

### 7.2 统计数字为什么不在前端算

原来 Web 端也是从后端取：

```
GET /api/tasks/stats
```

手机端同样：

```ts
stats.value = await getStats()
```

好处是能直接看到 Redis 的 `fromCache` 和 `ttl`：

```
Redis 命中 · 剩余 42s
Redis 回源 · 已写入缓存 60s
```

如果前端自己用列表长度算，就看不到缓存效果了。

### 7.3 为什么分页改成加载更多

桌面端有横向空间放页码；手机屏幕窄，页码按钮会挤。改成：

```
第一页 10 条
  ↓ 点击“加载更多”
pageNum = 2
  ↓
追加到 tasks.value
```

代码在 `loadMore()`，最终仍是调用同一个分页接口。

### 7.4 编辑页为什么独立

桌面端用弹窗，手机端键盘弹起会遮住弹窗。改成独立页面：

```
首页 → 点“编辑” → /pages/edit/edit?id=3
                    ↓
              GET /api/tasks/3
                    ↓
              回填表单
```

新增和编辑共用 `pages/edit/edit.uvue`，通过 `id` 是否大于 0 区分。

## 八、后端只加了一个接口

编辑页要按 ID 取任务，所以新增：

```java
@GetMapping("/{id}")
public Result<Task> getById(@PathVariable Long id) {
    Task task = taskService.getById(id);
    if (task == null) {
        return Result.fail(404, "任务不存在");
    }
    return Result.ok(task);
}
```

位置：`backend/src/main/java/com/example/todo/controller/TaskController.java`。

原有接口不变：

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/tasks` | 分页、搜索、筛选 |
| GET | `/api/tasks/stats` | 统计 + Redis 状态 |
| GET | `/api/tasks/{id}` | 编辑页回填（新增） |
| POST | `/api/tasks` | 新增 |
| PUT | `/api/tasks/{id}` | 更新 |
| PATCH | `/api/tasks/{id}/finished` | 切换状态 |
| DELETE | `/api/tasks/{id}` | 逻辑删除 |

## 九、运行方式：先 H5，再 Android

### 9.1 为什么先跑 H5

H5 编译最快，浏览器打开就能看页面和接口，适合先验证：

- 页面布局有没有错
- 请求地址对不对
- 新增、编辑、删除能不能走通

### 9.2 H5 怎么访问后端

生产环境用 Nginx：

```
浏览器 → http://你的域名/
          ├── /        → 静态文件
          └── /api/*   → http://backend:8080
```

开发/演示时也可以用本地静态服务器 + 代理。

### 9.3 Android 怎么访问后端

```
Android App
  → http://电脑局域网IP:8080/api
  → Spring Boot
```

必须保证：

1. 手机和电脑同一 Wi-Fi；
2. Windows 防火墙放行 8080；
3. App 内服务器地址填对；
4. `usesCleartextTraffic=true`。

### 9.4 云打包和本地打包的区别

| | 云打包 | 本地离线打包 |
|---|---|---|
| 需要 Android Studio | 不需要 | 需要 |
| 需要 Android SDK | 不需要 | 需要 |
| 需要 DCloud 登录 | 需要 | 不需要 |
| 证书 | 云端证书或自选 | 自己配置 |
| 适合新手 | **是** | 否 |

本项目的 Android 端走云打包，具体步骤见 [16 Android 云打包](16-Android云打包.md)。

## 十、跨平台还要注意什么

### 10.1 iOS

- 需要 Apple 开发者账号；
- 需要证书和 Provisioning Profile；
- Windows 不能本地出 IPA，但可以用 HBuilderX 云打包；
- 页面代码和 Android 共用。

### 10.2 H5

- 需要 Nginx 托管 `dist`；
- `/api` 反向代理到后端；
- 建议开启 gzip；
- 同一套 `.uvue` 页面，不需要另写。

### 10.3 微信小程序

- 需要小程序 AppID；
- 后端必须是 HTTPS；
- 要把域名加入“request 合法域名”；
- 不能用 `http://192.168.x.x`。

### 10.4 平台差异只放在三个地方

```
api/config.uts         后端地址
manifest.json          包名、图标、权限、SDK
AndroidManifest.xml    Android 原生配置
```

页面和业务逻辑尽量不写 `#ifdef`，这样跨平台代码才好维护。

## 十一、卡住了看这里

| 现象 | 先看 | 再看 |
|---|---|---|
| HBuilderX 不识别项目 | 项目图标是不是圆形 U | 右键“重新识别项目类型” |
| 云打包提示 AppID 不存在 | 是否重新获取 AppID | 是否登录 DCloud |
| App 打开白屏 | HBuilderX 控制台编译错误 | 是否误选自定义基座 |
| App 提示网络异常 | 手机浏览器能否访问后端 | 服务器设置、防火墙、IP |
| 真机请求 localhost 失败 | 改成电脑局域网 IP | 同一 Wi-Fi |
| 页面样式错乱 | 是否用了 App 不支持的 CSS | 改用 flex + rpx |
| 编辑页 404 | 后端是否加了 `GET /{id}` | 是否重启后端 |
| 统计不更新 | 写操作是否清缓存 | 等 60 秒或手动删 Redis key |

## 十二、本章小结

- 迁移的是**客户端**，不是后端和数据库。
- uni-app x 用 `.uvue` 重写页面，用 `uni.request` 替代 Axios。
- 后端只加 `GET /api/tasks/{id}`，其余接口不变。
- 跨平台的关键是 **API 地址按平台配置**，真机不能用 `localhost`。
- Android 第一版走 **HBuilderX 云打包**，不需要 Android Studio。
