# 05 · 后端与数据库耦合：MyBatis-Plus 与 Redis 客户端

> 一句话：后端**不直接拼 SQL 字符串**，而是把「Java 对象 ↔ 表」「Java 方法 ↔ SQL」交给 MyBatis-Plus，
> 把「缓存读写」交给 `StringRedisTemplate`。

---

## 本章你会

- 看懂数据源配置怎么连上 MySQL

- 看懂统计缓存从读到写的完整代码

## 一、先看一条查询从 Controller 到 SQL

```
TaskController.page(TaskQuery)
   │
   ▼
TaskServiceImpl.pageTasks(query)
   │   new Page<>(页码, 每页条数)
   │   new LambdaQueryWrapper<>().like(...).eq(...).orderBy(...)
   ▼
this.page(page, wrapper)          ← ServiceImpl 提供
   │
   ▼
TaskMapper（BaseMapper 的代理）
   │
   ▼
MyBatis-Plus 分页拦截器：改写 SQL，加 LIMIT，再发一条 COUNT
   │
   ▼
MySQL: SELECT ... WHERE deleted=0 AND title LIKE ? ORDER BY ... LIMIT 0,5
```

打开后端日志（`application.yml` 里开了 `log-impl: StdOutImpl`），能看到实际执行的 SQL：

```
==>  Preparing: SELECT COUNT(*) AS total FROM t_task WHERE deleted=0 AND (title LIKE ?)
==> Parameters: %报告%(String)
==>  Preparing: SELECT id,title,... FROM t_task WHERE deleted=0 AND (title LIKE ?) ORDER BY finished ASC,priority DESC,id DESC LIMIT ?
==> Parameters: %报告%(String), 5(Long)
```

**这两行就是「耦合」的具体样子**：Java 方法调用变成了 SQL。

## 二、数据源：怎么连上 MySQL

`backend/src/main/resources/application.yml`：

```yaml
spring:
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: jdbc:mysql://${MYSQL_HOST:localhost}:${MYSQL_PORT:3306}/${MYSQL_DB:todo_db}
         ?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
         &useSSL=false&allowPublicKeyRetrieval=true
    username: ${MYSQL_USER:todo}
    password: ${MYSQL_PASSWORD:todo123456}
```

四个参数的作用：

| 参数 | 作用 | 不写会怎样 |
|---|---|---|
| `useUnicode` + `characterEncoding` | 中文不乱码 | 中文可能变问号 |
| `serverTimezone` | 时区对齐 | 时间差 8 小时 |
| `useSSL=false` | 本地不加密连接 | 握手可能失败 |
| `allowPublicKeyRetrieval=true` | MySQL 8 认证插件需要 | 报 `Public Key Retrieval is not allowed` |

`${MYSQL_HOST:localhost}` 这种写法让同一份 jar 在本地和容器里都能跑（[02 后端](02-后端.md) 第八节讲过）。

**连接池**：Spring Boot 默认用 HikariCP 管理连接，你只管配 URL 和账号，不用管「怎么建连接、怎么复用」。

## 三、MyBatis-Plus 四件套

### 3.1 实体：Java 类 ↔ 表

```java
@Data
@TableName("t_task")                       // 对应哪张表
public class Task {
    @TableId(type = IdType.AUTO)           // 主键自增
    private Long id;

    private String title;

    @TableField(updateStrategy = FieldStrategy.ALWAYS)   // 允许被清空
    private String description;

    private Integer priority;
    private Integer finished;

    @TableField(updateStrategy = FieldStrategy.ALWAYS)
    @JsonFormat(pattern = "yyyy-MM-dd")
    private LocalDate dueDate;
}
```

### 3.2 Mapper：一行 SQL 都不写

```java
@Mapper
public interface TaskMapper extends BaseMapper<Task> {
    // 什么都不用写
}
```

`BaseMapper` 内置了 17 个通用方法：`insert`、`deleteById`、`updateById`、`selectById`、`selectList`、`selectPage`、`selectCount` 等。
启动时 MyBatis 会为这个接口生成**动态代理**，按方法名和泛型自动拼 SQL。

### 3.3 Service：业务层拿到通用 CRUD

```java
@Service
@RequiredArgsConstructor
public class TaskServiceImpl extends ServiceImpl<TaskMapper, Task> implements TaskService {
    // this.save(task) / this.getById(id) / this.page(page, wrapper) / this.count()
}
```

`ServiceImpl` 把 Mapper 的能力包装成更顺手的 `IService` 方法。

### 3.4 分页拦截器：不注册分页就失效

```java
@Configuration
public class MybatisPlusConfig {
    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        interceptor.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));
        return interceptor;
    }
}
```

**不注册它会怎样？** `page()` 会退化成查全表、`total` 不准 —— 而且**不报错**，非常隐蔽。

## 四、实体 ↔ 表：五条映射规则

| 规则 | Java | 数据库 | 靠什么 |
|---|---|---|---|
| 表名 | `Task` | `t_task` | `@TableName` |
| 主键 | `id` | `id` | `@TableId(type = AUTO)` |
| 列名 | `dueDate` | `due_date` | `map-underscore-to-camel-case: true` |
| 逻辑删除 | `deleted` | `deleted` | `@TableLogic` + 全局配置 |
| 更新策略 | `description` 可为 null | 想清空 | `updateStrategy = ALWAYS` |

### 4.1 驼峰映射

```yaml
mybatis-plus:
  configuration:
    map-underscore-to-camel-case: true
```

数据库 `due_date` ↔ Java `dueDate`。**关了它，所有下划线字段全是 `null`。**

### 4.2 逻辑删除

```java
@TableLogic
@JsonIgnore
private Integer deleted;
```
```yaml
mybatis-plus:
  global-config:
    db-config:
      logic-delete-field: deleted
      logic-delete-value: 1
      logic-not-delete-value: 0
```

效果：

```sql
-- 查询自动加条件
SELECT ... FROM t_task WHERE deleted = 0

-- 删除自动变成 UPDATE
UPDATE t_task SET deleted = 1 WHERE id = ? AND deleted = 0
```

两处缺一不可：**实体上要有 `@TableLogic`，全局配置也要有**（框架才知道字段名和取值）。

### 4.3 `ALWAYS`：为了能清空字段

MyBatis-Plus 默认「null 字段不拼进 SQL」，这是为了支持局部更新。
副作用是用户**没法清空**备注/日期：前端传 `null`，默认策略跳过该列，旧值还在。

```java
@TableField(updateStrategy = FieldStrategy.ALWAYS)
private String description;
```

加上它，null 也会写进 SQL，才能真正清空。

### 4.4 时间字段为什么不赋值

```sql
create_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
update_time DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
```

插入时 Java 侧是 null → 不拼该列 → 数据库填默认值；更新时数据库自动刷新 `update_time`。

## 五、条件构造器：用 Java 拼 WHERE

```java
LambdaQueryWrapper<Task> wrapper = new LambdaQueryWrapper<Task>()
        .like(StringUtils.hasText(query.getKeyword()), Task::getTitle, query.getKeyword())
        .eq(query.getFinished() != null, Task::getFinished, query.getFinished())
        .orderByAsc(Task::getFinished)      // 未完成（0）在前
        .orderByDesc(Task::getPriority)     // 优先级高的在前
        .orderByDesc(Task::getId);          // 同优先级时新的在前
```

两个关键设计：

**① 方法引用代替字符串**

```java
.eq(Task::getFinished, 1)     // ✅ 字段名写错，编译期报错
.eq("finished", 1)            // ❌ 运行期才炸
```

**② 第一个布尔参数是「开关」**

```java
.like(StringUtils.hasText(keyword), Task::getTitle, keyword)
```

- `keyword` 有值 → 拼 `AND title LIKE '%xxx%'`
- `keyword` 为空 → **整个条件不拼接**

省掉一堆 `if-else`，这就是 `pageTasks` 能写得这么短的原因。

## 六、事务：一组操作要么全成功

```java
@Transactional(rollbackFor = Exception.class)
public Task createTask(Task task) { ... }
```

本项目四个写方法都加了它。虽然目前每个方法只有一条 SQL，加了之后将来扩展（比如「新增任务同时写一条日志」）就自动具备原子性。

**注意**：`@Transactional` 要加在**被外部调用的 public 方法**上。同类内部方法互相调用不会走代理，事务不生效 —— 这是 Spring 事务最常见的坑。

## 七、Redis 接入：缓存读写全流程

### 7.1 注入模板

```java
private final StringRedisTemplate redisTemplate;   // key/value 都是字符串
private final ObjectMapper objectMapper;           // 对象 ↔ JSON
```

`StringRedisTemplate` 由 Spring Boot 自动配置，读的是 `application.yml` 里的 `spring.data.redis.*`。

**为什么 key/value 都用字符串？** 最直观，也便于用 `redis-cli` 直接看内容。
代价是要手动序列化 —— 本项目用 `ObjectMapper` 把 `TaskStats` 转成 JSON。

### 7.2 读缓存（`stats()` 前半段）

```java
try {
    String cachedJson = redisTemplate.opsForValue().get(STATS_KEY);
    if (cachedJson != null) {
        TaskStats cached = objectMapper.readValue(cachedJson, TaskStats.class);
        Long ttl = redisTemplate.getExpire(STATS_KEY, TimeUnit.SECONDS);
        cached.setFromCache(true);
        cached.setTtl(ttl == null ? 0L : ttl);
        return cached;                       // 命中：不碰数据库
    }
} catch (Exception e) {
    log.warn("读取 Redis 失败，降级查询数据库：{}", e.getMessage());
}
```

### 7.3 未命中：查库并写回（后半段）

```java
long total = this.count();
long finished = this.count(new LambdaQueryWrapper<Task>().eq(Task::getFinished, 1));

TaskStats stats = new TaskStats();
stats.setTotal(total);
stats.setFinished(finished);
stats.setUnfinished(total - finished);
stats.setFromCache(false);
stats.setTtl(STATS_TTL_SECONDS);

try {
    redisTemplate.opsForValue().set(STATS_KEY,
            objectMapper.writeValueAsString(stats),
            STATS_TTL_SECONDS, TimeUnit.SECONDS);
} catch (Exception e) {
    log.warn("写入 Redis 失败（不影响本次返回）：{}", e.getMessage());
}
```

### 7.4 写操作：删缓存

```java
private void clearStatsCache() {
    try {
        redisTemplate.delete(STATS_KEY);
    } catch (Exception e) {
        log.warn("清除 Redis 缓存失败：{}", e.getMessage());
    }
}
```

四个写方法末尾各调一次：

| 方法 | 为什么清 |
|---|---|
| `createTask` | 总数 +1 |
| `updateTask` | 可能改完成状态 |
| `removeTask` | 总数 −1 |
| `toggleFinished` | 完成/未完成互换 |

**为什么每个 Redis 操作都包 try/catch？** 缓存是加速层，不是数据源。
Redis 挂了应该降级去查数据库，而不是让接口 500。

**已知简化**：本项目是在事务提交前删缓存的，极端并发下可能有短暂不一致。
生产做法是用 `TransactionSynchronizationManager` 注册 `afterCommit` 回调 —— 代码注释里写了。

## 八、四类问题怎么排查

### 8.1 连不上数据库

```
Communications link failure
```

| 检查 | 命令 |
|---|---|
| MySQL 起了吗 | `docker compose ps` |
| 健康了吗 | 等 `healthy` 状态 |
| 端口对吗 | `docker exec todo-mysql mysqladmin ping -h127.0.0.1 -utodo -ptodo123456` |
| 变量名对吗 | `MYSQL_HOST` vs `MYSQLHOST` |

### 8.2 表不存在

```
Table 'todo_db.t_task' doesn't exist
```

按顺序查：

```bash
docker compose logs mysql | grep -iE "running /docker-entrypoint|init process done|denied"
```

看到 `running ... init.sql` 后紧跟 `MySQL init process done.` 才算成功。
若出现 `Permission denied`，说明脚本权限过严（`chmod 644 init.sql`）。
若什么都没看到，说明数据卷已存在、初始化被跳过 → `docker compose down -v`。

### 8.3 字段全是 null

| 现象 | 原因 |
|---|---|
| `dueDate`、`createTime` 全 null | 驼峰映射没开 |
| 更新后旧值还在 | 该字段没加 `updateStrategy = ALWAYS` |
| 删了还能查到 | `@TableLogic` 或全局配置缺失 |

### 8.4 缓存相关

| 现象 | 原因 | 解决 |
|---|---|---|
| 统计数字不刷新 | 写操作没清缓存 | 检查四个写方法是否调了 `clearStatsCache()` |
| 一直 `fromCache: false` | Redis 没连上，走了降级 | 看日志 `RedisConnectionFailure` |
| 反序列化异常 | 缓存里是旧结构的数据 | `DEL todo:stats` |
| 缓存永不过期 | `set` 时没传 TTL | 补 `60, TimeUnit.SECONDS` |

## 九、动手实验

1. **看 SQL**：访问一次列表接口，看后端控制台打印的 SQL，对照 `pageTasks` 的条件
2. **改 TTL**：把 `STATS_TTL_SECONDS` 从 60 改成 10，重启后刷新统计接口，观察 `ttl` 递减
3. **验证逻辑删除**：删一条任务，然后在数据库里 `SELECT id, deleted FROM t_task` —— 记录还在，只是 `deleted=1`
4. **绕过接口改库**：直接 `UPDATE t_task SET finished=1`，看页面统计会不会变（60 秒内不变，因为缓存还在）

## 十、自测：能不能答上来

1. 分页拦截器不注册会怎样？
2. `map-underscore-to-camel-case` 关掉，哪些字段会坏？
3. `updateStrategy = ALWAYS` 解决什么问题？
4. 写操作为什么删缓存而不是更新缓存？
5. 为什么所有 Redis 操作都要 try/catch？

<details>
<summary>参考答案</summary>

1. `page()` 退化成查全表，`total` 不准，且不报错。
2. 所有下划线列名对应的字段：`due_date`、`create_time`、`update_time`。
3. 让用户能把备注/日期清空（null 也写进 SQL）。
4. 并发更新时「更新缓存」可能用旧值覆盖新值；删除让下次读强制回源。
5. 缓存是加速层不是数据源，Redis 挂了应降级查库，而不是让接口 500。

</details>
