## 三、5 分钟跑起来（Docker 方式，推荐）

前置：装好 Docker 和 Docker Compose。

```bash
cd todo-app
docker compose up -d --build
```

首次需要下载镜像并编译，约 2～5 分钟。等 `docker compose ps` 里四个容器都 `running` / `healthy` 后：

| 入口 | 地址 |
|---|---|
| 应用页面 | http://localhost:8081 |
| 接口文档 | http://localhost:8081/doc.html |
| 后端直连 | http://localhost:8080/api/tasks |

### 跑通后按这个顺序体验一遍

1. **看数据**：8 条任务，未完成在前、优先级高的更靠前
2. **看缓存**：工具栏显示「Redis 回源」→ 刷新一次变「Redis 命中 · 剩余 xx s」
3. **搜索**：输入「报告」→ 只剩标题含该词的记录
4. **筛选**：状态下拉选「已完成」→ 只剩 3 条
5. **新增**：填标题 → 保存 → 列表和统计数字同时变
6. **切换状态**：点表格里的开关 → 统计卡片实时变化
7. **看文档**：点页头「接口文档 Knife4j ↗」，直接在网页上调试接口

### 停止与重置

```bash
docker compose down        # 停止，保留数据
docker compose down -v     # 停止并删数据卷（init.sql 会重新执行）
```

## 四、不用 Docker 的本地开发

前置：JDK 17、Maven、Node 18+、Docker（只用来跑 MySQL/Redis）。

```bash
cd todo-app
docker compose up -d mysql redis      # 1) 只起数据库

cd backend
mvn spring-boot:run                    # 2) 后端 → 8080

cd ../frontend
npm install                            # 3) 前端 → 5173（第一次才需要）
npm run dev
```

打开 http://localhost:5173 。前端热更新、后端可断点调试。

## 六、一条请求走了哪些路

以「点击查询」为例：

1. `TodoView.vue` 的 `handleSearch()` 被触发
2. 调 `api/task.js` 的 `pageTasks(query)`
3. `api/request.js` 的 axios 发出 `GET /api/tasks?pageNum=1&pageSize=5&keyword=报告`
4. 开发时 Vite 代理、Docker 时 Nginx 反代 —— 都转到后端 8080
5. `TaskController.page()` 接收 `TaskQuery`
6. `TaskServiceImpl.pageTasks()` 用 `LambdaQueryWrapper` 拼条件
7. MyBatis-Plus 分页拦截器改写成 `... WHERE deleted=0 AND title LIKE ? LIMIT 0,5`，并另发 `COUNT(*)`
8. 结果逐层包装成 `Result<IPage<Task>>` → JSON
9. axios 响应拦截器拆掉 `{code,message,data}` 外壳
10. `list.value = data.records`，表格刷新

这条链路上每一环对应一章：

| 步骤 | 章节 |
|---|---|
| 1–3 | 01 前端 |
| 4 | 04 耦合 / 06 Nginx |
| 5 | 02 后端 |
| 6–7 | 05 后端与数据库耦合 |
| 8 | 02 后端 |
| 9–10 | 04 耦合 / 01 前端 |

## 七、怎么读这个项目的代码（重点）

**不要从第一个文件第一行读到最后一个文件最后一行**，会迷路。按下面的五步走。

### 第 1 步：先看目录，记住四个入口

```
frontend/src/main.js          前端入口
frontend/src/views/TodoView.vue   业务页面（80% 的前端代码在这）
backend/.../TaskController.java   接口入口
backend/.../db/init.sql           数据从哪来
```

### 第 2 步：读一个文件时，按这个顺序看

打开任何一个 `.vue` 或 `.java` 文件，从上到下只扫这五样：

| 顺序 | 看什么 | 能知道什么 |
|---|---|---|
| 1 | 顶部 `import` | 它依赖谁（一眼看出这个文件负责什么） |
| 2 | 状态声明（`ref`/`reactive`/字段） | 它有哪些数据 |
| 3 | 函数 / 方法列表 | 它能干什么 |
| 4 | `template` 或方法体 | 它是怎么干的 |
| 5 | `<style>` | **直接跳过**，读代码阶段不需要 |

以 `TodoView.vue` 为例，扫一遍就知道：

```js
import ... from '../api/task'      // → 它会调后端接口
const list = ref([])               // → 有列表数据
const query = reactive({...})      // → 有查询条件
async function loadList() {...}    // → 会加载列表
function handleSearch() {...}      // → 有搜索动作
```

### 第 3 步：读一个函数，问三个问题

对每个函数，只回答三件事：

1. **谁调用它？**（在文件里搜函数名）
2. **它的输入是什么？**（参数、或它读了哪个 `ref`）
3. **它的输出给了谁？**（改了什么数据 / 返回给谁）

示例：`handleSearch`

```
谁调用：模板里的查询按钮 @click="handleSearch"，以及搜索框回车
输入：读 query（页码/关键词/状态）
输出：把 pageNum 重置为 1，然后调 loadList() → 改 list 和 total
```

### 第 4 步：跟一条完整的链路（推荐从「搜索」开始）

按这个顺序点开文件、只看相关的那几行：

```
① TodoView.vue       找到 handleSearch → 调用 pageTasks
② api/task.js        找到 pageTasks → request.get('/tasks', { params })
③ api/request.js     看 baseURL（'/api'）和响应拦截器
④ vite.config.js     看 proxy 把 /api 转到 8080（或者 nginx.conf）
⑤ TaskController     @GetMapping → page(TaskQuery)
⑥ TaskServiceImpl    pageTasks：怎么拼条件、怎么分页
⑦ TaskMapper         extends BaseMapper<Task>（没有 SQL）
⑧ init.sql           表结构长什么样
```

每一环只需要看 **10～20 行**。看完整条链，你就理解了 70% 的项目。

### 第 5 步：用「改一下看效果」验证理解

读代码最容易自欺欺人。改一小处，能看到预期变化，才算真懂了：

| 改动 | 预期 | 如果没变说明 |
|---|---|---|
| 改 `query.pageSize` 为 3 | 每页 3 条 | 没找到真正的分页参数 |
| 改 `orderByDesc(Task::getPriority)` 为 `Asc` | 优先级低的在前 | 没找到排序在哪 |
| 把 `STATS_TTL_SECONDS` 改成 10 | `ttl` 10 秒后回源 | 没找到缓存 TTL |
| 把 `@RequestMapping` 改成 `/api/todo` | 前端 404 | 没理解路径契约 |

> 读不懂某个文件时，最快的办法是：**看它的调用方**（谁用了它）。
> IDE 里右键方法 → 「Find Usages / 查找用法」。没有 IDE，就用全局搜索函数名。

## 十二、一句话总结每章

- **01 前端**：数据驱动界面，`ref`/`reactive` 是核心
- **02 后端**：四层分工，Controller 不碰数据库
- **03 数据库**：MySQL 是真相，Redis 是加速
- **04 耦合**：路径、方法、字段名，五份契约对不上就静默失效
- **05 耦合**：注解把 Java 映射成表，Wrapper 把条件翻译成 SQL
- **06 必要技术**：注解出文档、Nginx 转发、Docker 打包
- **07 前端模板**：前端文件 + 页面区块逐块拆解 + Vue/JS 语法
- **08 后端模板**：后端文件 + 每个接口/方法逐块拆解 + Java/Spring 语法
- **09 数据库模板**：建表脚本六块拆解 + SQL/Redis 语法
