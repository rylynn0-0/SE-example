## 二、技术定位：每门技术站在哪一层

先记住一张表，后面每一章都是在这张表上展开。

| 层 | 技术 | 在本项目里负责 | 主要跟谁打交道 | 对应章节 |
|---|---|---|---|---|
| **页面** | Vue 3 | 把数据画成界面、把点击变成函数调用 | Element Plus、Axios | 01 |
| **页面** | Element Plus | 现成的表格 / 表单 / 弹窗组件 | Vue | 01 |
| **页面** | Vite | 开发服务器、把 `.vue` 编译成浏览器能跑的代码 | 源码文件、浏览器 | 01 |
| **页面** | Axios | 发 HTTP 请求、统一拆响应外壳 | 后端接口 | 01 / 04 |
| **接口** | Spring Boot | 接收请求、校验、调业务、返回 JSON | Axios、Service | 02 |
| **数据访问** | MyBatis-Plus | Java 对象 ↔ 表、Java 方法 ↔ SQL | MySQL | 05 |
| **数据** | MySQL | 唯一真相：任务存在这 | MyBatis-Plus | 03 |
| **数据** | Redis | 缓存：统计数字存 60 秒 | Spring Boot | 03 / 05 |
| **文档** | Knife4j | 把注解渲染成 `/doc.html` | Controller 注解 | 09 |
| **部署** | Nginx | 托管静态页 + 把 `/api` 转发给后端 | 浏览器、backend | 09 |
| **部署** | Docker | 把四个容器打包成一条命令启动 | 全部 | 09 |

**一句话记住三层**：

```
页面层（浏览器）  ──HTTP/JSON──▶  接口层（8080）  ──SQL──▶  数据层（MySQL/Redis）
   Vue/Element                        Spring Boot              MyBatis-Plus
```

## 三、系统全景：谁连谁

```
浏览器
  │ http://localhost:8081
  ▼
frontend 容器（Nginx）
  │  · 托管 Vue 构建产物
  │  · /api/* 转发给 backend:8080
  ▼
backend 容器（Spring Boot 8080）
  │
  ├── TaskController   收参数、校验、包装返回
  ├── TaskServiceImpl  业务规则 + 事务 + 缓存失效
  └── TaskMapper       MyBatis-Plus
        │
        ├──▶ mysql:3306   持久化（唯一真相）
        └──▶ redis:6379   缓存（统计 60 秒）
```

### 3.1 耦合总览（哪两件东西靠什么连）

| 耦合双方 | 媒介 | 章节 | 断了会怎样 |
|---|---|---|---|
| Vue ↔ Element Plus | `app.use(ElementPlus)` + 模板标签 | 01 | 组件不渲染 |
| Vue ↔ Axios | 页面调用 `api/task.js` | 01 | 表格永远空 |
| **前端 ↔ 后端** | 路径 `/api`、HTTP 方法、JSON 字段名、响应外壳 | **04** | 404 / 405 / 参数静默失效 |
| 前端 ↔ 代理 | Vite `proxy` / Nginx `proxy_pass` | 04 / 09 | 404 / 502 |
| **后端 ↔ MySQL** | 数据源配置、实体注解、Wrapper | **05** | 连不上 / 字段 null |
| **后端 ↔ Redis** | key、TTL、Cache-Aside | **05** | 统计永远回源 |
| Docker ↔ Spring Boot | 环境变量 → `${...}` 占位符 | 09 | `Communications link failure` |
| Nginx ↔ backend | 服务名 + 端口 | 09 | 502 |

> 这就是本项目的全部耦合。读 04、05 时对照这张表，任何问题先问：**是哪一行断了？**

### 3.2 一条请求经过了谁

以「点击查询」为例：

1. `TodoView.vue` 的 `handleSearch()` 被触发
2. 调 `api/task.js` 的 `pageTasks(query)`
3. `api/request.js` 的 axios 发出 `GET /api/tasks?pageNum=1&pageSize=5&keyword=报告`
4. 开发时 Vite 代理、Docker 时 Nginx 反代 —— 都转到后端 8080
5. `TaskController.page()` 接收 `TaskQuery`
6. `TaskServiceImpl.pageTasks()` 用 `LambdaQueryWrapper` 拼条件
7. MyBatis-Plus 分页拦截器改写成 `... WHERE deleted=0 AND title LIKE ? LIMIT 0,5`，并另发 `COUNT(*)`
8. 结果逐层包装成 `Result<IPage<Task>>` → JSON
9. axios 响应拦截器拆掉 `{code,message,data}` 外壳
10. `list.value = data.records`，表格刷新

| 步骤 | 经过的层 | 章节 |
|---|---|---|
| 1–3 | 页面层 | 01、04 |
| 4 | 代理 | 04、09 |
| 5 | 接口层 | 02 |
| 6–7 | 数据访问层 + 数据层 | 05 |
| 8 | 接口层 | 02 |
| 9–10 | 页面层 | 04、01 |

## 四、5 分钟跑起来（Docker 方式，推荐）

前置：装好 Docker 和 Docker Compose。

```bash
cd todo-app
docker compose up -d --build
```

首次需要下载镜像并编译，约 2～5 分钟。等 `docker compose ps` 里四个容器都 `running` / `healthy` 后：

| 入口 | 地址 |
|---|---|
| 应用页面 | http://localhost:8081 |
| 接口文档 | http://localhost:8081/doc.html |
| 后端直连 | http://localhost:8080/api/tasks |

### 跑通后按这个顺序体验一遍

1. **看数据**：8 条任务，未完成在前、优先级高的更靠前
2. **看缓存**：工具栏显示「Redis 回源」→ 刷新一次变「Redis 命中 · 剩余 xx s」
3. **搜索**：输入「报告」→ 只剩标题含该词的记录
4. **筛选**：状态下拉选「已完成」→ 只剩 3 条
5. **新增**：填标题 → 保存 → 列表和统计数字同时变
6. **切换状态**：点表格里的开关 → 统计卡片实时变化
7. **看文档**：点页头「接口文档 Knife4j ↗」，直接在网页上调试接口

### 停止与重置

```bash
docker compose down        # 停止，保留数据
docker compose down -v     # 停止并删数据卷（init.sql 会重新执行）
```

## 五、不用 Docker 的本地开发

前置：JDK 17、Maven、Node 18+、Docker（只用来跑 MySQL/Redis）。

```bash
cd todo-app
docker compose up -d mysql redis      # 1) 只起数据库

cd backend
mvn spring-boot:run                    # 2) 后端 → 8080

cd ../frontend
npm install                            # 3) 前端 → 5173（第一次才需要）
npm run dev
```

打开 http://localhost:5173 。前端热更新、后端可断点调试。

## 六、怎么读这个项目的代码（五步法）

**不要从第一个文件第一行读到最后一个文件最后一行**，会迷路。

### 第 1 步：先看目录，记住四个入口

```
frontend/src/main.js               前端入口
frontend/src/views/TodoView.vue    业务页面（80% 的前端代码在这）
backend/.../TaskController.java    接口入口
backend/.../db/init.sql            数据从哪来
```

### 第 2 步：读一个文件时，按这个顺序看

| 顺序 | 看什么 | 能知道什么 |
|---|---|---|
| 1 | 顶部 `import` | 它依赖谁 |
| 2 | 状态声明（`ref`/`reactive`/字段） | 它有哪些数据 |
| 3 | 函数 / 方法列表 | 它能干什么 |
| 4 | `template` 或方法体 | 它是怎么干的 |
| 5 | `<style>` | **跳过**，读代码阶段不需要 |

### 第 3 步：读一个函数，问三个问题

1. **谁调用它？**（在文件里搜函数名）
2. **它的输入是什么？**（参数，或它读了哪个 `ref`）
3. **它的输出给了谁？**（改了什么数据 / 返回给谁）

示例 `handleSearch`：

```
谁调用：查询按钮 @click、搜索框回车
输入：读 query（页码/关键词/状态）
输出：pageNum 重置为 1 → 调 loadList() → 改 list 和 total
```

### 第 4 步：跟一条完整链路（推荐从「搜索」开始）

```
① TodoView.vue     handleSearch → pageTasks
② api/task.js      request.get('/tasks', { params })
③ api/request.js   baseURL '/api' + 响应拦截器
④ vite.config.js   proxy 把 /api 转到 8080（或 nginx.conf）
⑤ TaskController   @GetMapping → page(TaskQuery)
⑥ TaskServiceImpl  pageTasks：拼条件、分页
⑦ TaskMapper       extends BaseMapper<Task>（没有 SQL）
⑧ init.sql         表结构
```

每一环只看 10～20 行。走完整条链，你就理解了 70% 的项目。

> 「查」走通后，[10 总览](10-增删改查总览.md) 给出公共机制，
> [11 查](11-查询链路.md) / [12 增](12-新增链路.md) / [13 改](13-修改链路.md) / [14 删](14-删除链路.md)
> 会把四个操作各自逐行拆一遍，并给出每一步的 HTTP 请求、SQL 和前端状态变化。

### 第 5 步：改一下看效果

| 改动 | 预期 | 没变说明 |
|---|---|---|
| `query.pageSize` 改 3 | 每页 3 条 | 没找到真正的分页参数 |
| `orderByDesc(Task::getPriority)` 改 `Asc` | 优先级低的在前 | 没找到排序位置 |
| `STATS_TTL_SECONDS` 改 10 | 10 秒后回源 | 没找到缓存 TTL |
| `@RequestMapping` 改 `/api/todo` | 前端 404 | 没理解路径契约 |

> 读不懂某个文件时，最快的是**看它的调用方**：IDE 右键 → 查找用法。

## 十一、一句话总结每章

- **01 前端**：数据驱动界面，`ref`/`reactive` 是核心
- **02 后端**：四层分工，Controller 不碰数据库
- **03 数据库**：MySQL 是真相，Redis 是加速
- **04 耦合**：路径、方法、字段名，五份契约对不上就静默失效

- **06 前端模板**：页面区块逐块拆 + Vue/JS 语法
- **07 后端模板**：接口/方法逐块拆 + Java/Spring 语法
- **08 数据库模板**：建表脚本逐块拆 + SQL/Redis 语法
- **09 必要技术**：Knife4j 出文档、Nginx 转发、Docker 打包
