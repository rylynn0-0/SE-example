# 02 · 后端：接口与业务规则

> 一句话：后端是**跑在服务器上的程序**，负责接收 HTTP 请求、处理业务、返回 JSON。

> 配套手册：文件怎么建、注解和语法怎么写，见 [08 后端文件模板](08-后端文件模板.md)。

## 一、先跑起来（5 分钟）

前置：JDK 17、Maven；**MySQL 必须在运行**（Redis 建议一起起，统计接口要用到）。

```bash
cd todo-app
docker compose up -d mysql redis     # 先起数据库（持久层）
cd backend
mvn spring-boot:run                  # 看到 Started TodoApplication 就成功
```

验证：

```bash
curl "http://localhost:8080/api/tasks?pageNum=1&pageSize=2"
```

应该返回：

```json
{"code":200,"message":"成功","data":{"records":[...],"total":8,"size":2,"current":1,"pages":4}}
```

浏览器打开 `http://localhost:8080/doc.html` 能看到接口文档（[06 必要技术](06-必要技术.md) 讲原理）。

> **启动失败最常见的原因**：MySQL 没起。
> 日志里看到 `Communications link failure`，就是它 —— 见 [05 后端与数据库耦合](05-后端与数据库耦合.md) 的排查表。

## 三、Spring Boot：三个卖点

传统 Java Web 项目要手动配 Tomcat、web.xml、Spring 容器、Jackson、数据源……十几个 XML。
Spring Boot 把这些全自动化了。

| 卖点 | 含义 |
|---|---|
| **自动配置** | 引入 `spring-boot-starter-web`，自动装好 Tomcat + Jackson |
| **起步依赖** | 一个 starter 打包一整组相关依赖 |
| **内嵌容器** | Tomcat 在 jar 里，`java -jar` 就能跑，不用单独部署 |

最小可运行的后端就是一个类：

```java
@RestController
@RequestMapping("/api/hello")
public class HelloController {

    @GetMapping
    public Map<String, Object> sayHi() {
        return Map.of("msg", "hello");
    }
}
```

启动后访问 `http://localhost:8080/api/hello` 就有 JSON —— **没有配置任何 XML**。

## 四、四层结构：本项目怎么分层

```
Controller  ← 只做「收参数、校验、包装返回」
    ↓
Service     ← 业务规则、事务边界、缓存失效（唯一的业务层）
    ↓
Mapper      ← 只和数据库打交道
    ↓
Entity      ← 表结构映射
```

依赖方向**单向向下**，不允许 Mapper 反调 Controller。

| 层 | 本项目文件 | 关键点 |
|---|---|---|
| 启动 | `TodoApplication.java` | `@SpringBootApplication` + `@MapperScan` |
| 接口 | `controller/TaskController.java` | 6 个 REST 接口 |
| 业务 | `service/impl/TaskServiceImpl.java` | 排序规则、Redis 缓存、`@Transactional` |
| 数据 | `mapper/TaskMapper.java` | 继承 `BaseMapper`，一行 SQL 不写 |
| 实体 | `entity/Task.java` | 表映射 + JSON 格式 + 文档注解 |
| 传输 | `dto/TaskQuery.java`、`dto/TaskStats.java` | 请求参数 / 统计返回 |
| 配置 | `resources/application.yml` | 数据源 / Redis / MyBatis-Plus |

**为什么 Controller 不直接查库？**

| 如果 Controller 直接调 Mapper | 分层之后 |
|---|---|
| 加缓存要改每个接口 | 只改 Service 一处 |
| 事务边界到处散落 | Service 上写一个 `@Transactional` |
| 换 ORM 要动所有接口 | 只动 Mapper |

## 五、注解速查

| 注解 | 作用 | 本项目例子 |
|---|---|---|
| `@SpringBootApplication` | 启动类 + 自动扫描本包及子包 | `TodoApplication` |
| `@RestController` | 方法返回值自动转 JSON | `TaskController` |
| `@RequestMapping("/api/tasks")` | 类级路径前缀 | `TaskController` |
| `@GetMapping` / `@PostMapping` / `@PutMapping` / `@PatchMapping` / `@DeleteMapping` | 方法 + 子路径 | 6 个接口各一个 |
| `@RequestBody` | 请求体 JSON → 对象 | `create`、`update` |
| `@PathVariable` | 取路径里的 `{id}` | `update`、`toggle`、`delete` |
| `@Service` | 标记业务层，交给容器管理 | `TaskServiceImpl` |
| `@Transactional` | 开启事务 | 四个写方法 |
| `@MapperScan` | 扫描 Mapper 接口并生成代理 | 启动类 |

**包扫描是隐形坑**：Controller 如果放到 `com.example.todo` 的**外面**，不会被扫描到，接口 404 且没有任何报错。

## 六、依赖注入：别自己 `new`

Spring 的核心思路：需要什么就声明什么，容器负责创建和装配。

本项目的写法统一是**构造器注入 + Lombok**：

```java
@Service
@RequiredArgsConstructor            // Lombok：为所有 final 字段生成构造器
public class TaskServiceImpl extends ServiceImpl<TaskMapper, Task> implements TaskService {

    private final StringRedisTemplate redisTemplate;   // 容器自动注入
    private final ObjectMapper objectMapper;           // 容器自动注入
}
```

为什么不写 `new TaskMapper()`？因为 Mapper 是动态代理、Redis 模板要读配置，你自己造不出来。

构造器注入对比字段注入：

```java
// ❌ 字段注入：依赖可变，单元测试要启动容器
@Autowired private TaskService service;

// ✅ 构造器注入：final 不可变、不会为 null，测试时直接 new
private final TaskService service;
```

## 七、统一响应：所有接口长一个样

后端所有接口都返回同一个外壳：

```json
{ "code": 200, "message": "成功", "data": { ... } }
```

对应 `common/Result.java`：

```java
@Data
public class Result<T> {
    private Integer code;      // 200 成功，其它失败
    private String message;    // 给人看的提示
    private T data;            // 业务数据

    public static <T> Result<T> ok(T data) { ... }
    public static <T> Result<T> fail(String message) { ... }
    public static <T> Result<T> fail(Integer code, String message) { ... }
}
```

好处：**前端只需要判断 `code === 200`**，不用猜 HTTP 状态码的含义。

| code | 含义 | 本项目出现场景 |
|---|---|---|
| 200 | 成功 | 所有正常返回 |
| 400 | 参数错误 | 标题为空 |
| 404 | 资源不存在 | 更新/删除/切换不存在的任务 |
| 500 | 服务器错误 | `fail(message)` 默认值 |

## 八、配置文件：同一份 jar 到处能跑

`backend/src/main/resources/application.yml`：

```yaml
server:
  port: 8080

spring:
  datasource:
    url: jdbc:mysql://${MYSQL_HOST:localhost}:${MYSQL_PORT:3306}/${MYSQL_DB:todo_db}?...
    username: ${MYSQL_USER:todo}
    password: ${MYSQL_PASSWORD:todo123456}
  data:
    redis:
      host: ${REDIS_HOST:localhost}
      port: ${REDIS_PORT:6379}
```

`${MYSQL_HOST:localhost}` 的意思是：**读环境变量 `MYSQL_HOST`，读不到就用 `localhost`**。

这就是「同一份 jar 在本地和 Docker 里都能跑」的关键：

| 环境 | `MYSQL_HOST` | 实际连到 |
|---|---|---|
| 本地开发 | 不设置 → 默认 | `localhost:3306` |
| Docker 容器 | 注入 `mysql` | 容器网络里的 mysql 服务 |

变量名**必须逐字一致**，`MYSQL_HOST` 写成 `MYSQLHOST` 就静默退化成 `localhost`，容器里连不上库。

**实验**：把 `server.port` 改成 9090，重启后访问 `http://localhost:9090/api/tasks`。改回 8080 再看一遍。

## 九、一个接口的完整旅程

以「分页查询」为例，从点击到返回：

```java
// 1. Controller 收参数（Spring MVC 按字段名把 URL 参数塞进 TaskQuery）
@GetMapping
public Result<IPage<Task>> page(TaskQuery query) {
    return Result.ok(taskService.pageTasks(query));
}
```

```java
// 2. Service 拼条件并查询
public IPage<Task> pageTasks(TaskQuery query) {
    Page<Task> page = new Page<>(query.getPageNum(), query.getPageSize());
    LambdaQueryWrapper<Task> wrapper = new LambdaQueryWrapper<Task>()
            .like(StringUtils.hasText(query.getKeyword()), Task::getTitle, query.getKeyword())
            .eq(query.getFinished() != null, Task::getFinished, query.getFinished())
            .orderByAsc(Task::getFinished)
            .orderByDesc(Task::getPriority)
            .orderByDesc(Task::getId);
    return this.page(page, wrapper);
}
```

完整链路：

1. 请求进来 → `TaskController.page(query)`
2. Spring MVC 把 `?pageNum=1&pageSize=5&keyword=报告` 绑定到 `TaskQuery` 的字段
3. 调用 `taskService.pageTasks(query)`
4. MyBatis-Plus 把条件翻译成 SQL：`WHERE title LIKE '%报告%' AND deleted=0 ORDER BY ... LIMIT 0,5`
5. 额外发一条 `SELECT COUNT(*)` 算总数（分页插件做的）
6. 结果包成 `Result.ok(...)`
7. Jackson 把对象转成 JSON
8. 浏览器收到响应

9～10 步（前端怎么解析）在 [04 前端与后端耦合](04-前端与后端耦合.md)。

## 十、Maven：三条命令走天下

| 命令 | 作用 | 什么时候用 |
|---|---|---|
| `mvn spring-boot:run` | 直接启动 | 本地开发 |
| `mvn package` | 打成 `target/*.jar` | 部署 |
| `mvn clean package -DskipTests` | 跳过测试打包 | Docker 构建 |

- 依赖都写在 `pom.xml`，版本大多由 Spring Boot 父工程统一管理
- `target/` 是产物目录，不要提交 git

国内下载依赖慢，用 `backend/settings.xml` 里的阿里云镜像：`mvn -s settings.xml package`（Docker 构建时就是这么做的，见 [06 必要技术](06-必要技术.md)）。

## 十一、自测：能不能答上来

1. Controller、Service、Mapper 各负责什么？
2. `@MapperScan` 去掉会怎样？
3. `Result` 为什么要包一层 `{code, message, data}`？
4. `${MYSQL_HOST:localhost}` 里冒号后面那段是什么？
5. 一个接口返回 404，可能是 `Result` 里的哪个值？

<details>
<summary>参考答案</summary>

1. Controller 收参数/校验/包装；Service 业务规则、事务、缓存；Mapper 只访问数据库。
2. 启动报 `No qualifying bean of type TaskMapper`，因为 Mapper 接口没有生成代理对象。
3. 统一结构让前端只判断 `code`，也能区分「成功但没数据」和「失败」。
4. 默认值：读不到环境变量时用 `localhost`。
5. `code = 404`，同时 `message` 会写「任务不存在」。

</details>

## 十二、常见错误

| 现象 | 原因 | 解决 |
|---|---|---|
| 接口 404 | Controller 不在启动类的包或子包下 | 调整包位置 |
| `No qualifying bean of type TaskMapper` | 漏了 `@MapperScan` 或 `@Mapper` | 补上 |
| 启动即退出 | MySQL 没起 / 连不上 | 看日志 `Communications link failure` |
| 端口被占用 | 8080 有别的程序 | 改 `server.port` |
| `@RequestBody` 收到 null | 前端把数据放进了 URL 参数 | 前端改成传请求体 |
| yml 改了不生效 | 缩进错误 / 没重启 | 用空格缩进，重启 |
| 中文乱码 | 数据库或连接字符集不对 | 见 03 章字符集 |
