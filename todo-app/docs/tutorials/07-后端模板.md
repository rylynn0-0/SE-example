## 二、逐个文件怎么写

### 2.1 `pom.xml` —— 5 个区块

```xml
<project xmlns="http://maven.apache.org/POM/4.0.0">
    <modelVersion>4.0.0</modelVersion>

    <!-- ① 父工程：统一版本 -->
    <parent>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-parent</artifactId>
        <version>3.3.5</version>
        <relativePath/>
    </parent>

    <!-- ② 本项目坐标 -->
    <groupId>com.example</groupId>
    <artifactId>todo-backend</artifactId>
    <version>1.0.0</version>

    <!-- ③ 变量 -->
    <properties>
        <java.version>17</java.version>
    </properties>

    <!-- ④ 依赖 -->
    <dependencies>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-web</artifactId>
        </dependency>

        <dependency>
            <groupId>com.baomidou</groupId>
            <artifactId>mybatis-plus-spring-boot3-starter</artifactId>
            <version>3.5.7</version>
        </dependency>

        <dependency>
            <groupId>com.mysql</groupId>
            <artifactId>mysql-connector-j</artifactId>
            <scope>runtime</scope>
        </dependency>

        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-data-redis</artifactId>
        </dependency>

        <dependency>
            <groupId>com.github.xiaoymin</groupId>
            <artifactId>knife4j-openapi3-jakarta-spring-boot-starter</artifactId>
            <version>4.5.0</version>
        </dependency>

        <dependency>
            <groupId>org.projectlombok</groupId>
            <artifactId>lombok</artifactId>
            <optional>true</optional>
        </dependency>

        <!-- 测试（本项目只保留依赖，未写测试类） -->
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-test</artifactId>
            <scope>test</scope>
        </dependency>
    </dependencies>

    <!-- ⑤ 打包插件 -->
    <build>
        <plugins>
            <plugin>
                <groupId>org.springframework.boot</groupId>
                <artifactId>spring-boot-maven-plugin</artifactId>
            </plugin>
        </plugins>
    </build>
</project>
```

拆开看：

| 区块 | 作用 | 改哪里 |
|---|---|---|
| 父工程 `parent` | 决定所有 starter 的版本 | 升级 Spring Boot 时改 |
| 坐标 | 项目的 groupId/artifactId/version | 换项目名时改 |
| `properties` | 定义变量，下面用 `${}` 引用 | `java.version` |
| 依赖 | 每引入一个能力加一条 | 加库时 |
| 打包插件 | 打成可执行 jar（并排除 lombok） | 一般不动 |

**语法点**：

| 写法 | 含义 |
|---|---|
| `<parent>` / `<dependency>` | XML 元素；依赖 = 三个坐标 |
| `<scope>runtime</scope>` | 只在运行时需要（编译期不用） |
| `<optional>true</optional>` | 不向下传递给依赖本项目的工程 |
| `${java.version}` | 引用 `<properties>` 里的变量 |

**易错**：`mybatis-plus-spring-boot3-starter` 写成不带 `3` 的版本 → 与 Boot 3 不兼容；依赖漏版本号又不在 parent 管理里 → 构建失败。

### 2.2 `application.yml` —— 6 个区块

```yaml
# ① 服务
server:
  port: 8080

# ② 数据源
spring:
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: jdbc:mysql://${MYSQL_HOST:localhost}:${MYSQL_PORT:3306}/${MYSQL_DB:todo_db}?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&useSSL=false&allowPublicKeyRetrieval=true
    username: ${MYSQL_USER:todo}
    password: ${MYSQL_PASSWORD:todo123456}

  # ③ Redis
  data:
    redis:
      host: ${REDIS_HOST:localhost}
      port: ${REDIS_PORT:6379}
      timeout: 3s

  # ④ JSON
  jackson:
    date-format: yyyy-MM-dd HH:mm:ss
    time-zone: Asia/Shanghai

# ⑤ MyBatis-Plus
mybatis-plus:
  configuration:
    map-underscore-to-camel-case: true
    log-impl: org.apache.ibatis.logging.stdout.StdOutImpl
  global-config:
    banner: false
    db-config:
      id-type: auto
      logic-delete-field: deleted
      logic-delete-value: 1
      logic-not-delete-value: 0

# ⑥ 文档
springdoc:
  api-docs:
    path: /v3/api-docs

knife4j:
  enable: true
  setting:
    language: zh_cn
```

拆开看：

| 区块 | 作用 | 关键点 |
|---|---|---|
| `server.port` | 后端端口 | 容器内 8080 |
| `datasource` | 连 MySQL | `${变量:默认值}`，冒号不能省 |
| `data.redis` | 连 Redis | 超时设 3s |
| `jackson` | 日期格式、时区 | 影响 JSON 输出 |
| `mybatis-plus` | 驼峰映射、逻辑删除、SQL 日志 | 少了字段会 null / 删不掉 |
| `springdoc` + `knife4j` | 文档开关与中文 | 关闭文档时置 false |

**语法点**：

| 写法 | 含义 |
|---|---|
| `key: value` | 冒号后**必须有空格** |
| 缩进 | 只能用空格，不能 Tab |
| `${MYSQL_HOST:localhost}` | 环境变量 + 默认值 |
| 层级 | `spring.datasource.url` 等价于两层缩进 |

**易错**：`port:8080`（缺空格）→ 值解析异常；`serverProt` 拼错 → 不报错但配置不生效。

### 2.3 `TodoApplication.java` —— 2 块

```java
package com.example.todo;

import org.mybatis.spring.annotation.MapperScan;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
@MapperScan("com.example.todo.mapper")
public class TodoApplication {
    public static void main(String[] args) {
        SpringApplication.run(TodoApplication.class, args);
    }
}
```

拆开看：

| 小组件 | 作用 | 关键点 |
|---|---|---|
| `package` | 包名 | 必须和目录一致，且在业务代码父包 |
| `@SpringBootApplication` | 启动 + 扫描本包及子包 | Controller 必须在它下面 |
| `@MapperScan` | 扫描 Mapper 接口 | 包名写错 → 启动找不到 Bean |
| `main` | 程序入口 | `SpringApplication.run` |

**易错**：启动类放到 `com.example.todo.app` 子包 → 兄弟包的 Controller 扫不到，接口 404。

### 2.4 `entity/Task.java` —— 8 组字段

```java
package com.example.todo.entity;

import com.baomidou.mybatisplus.annotation.*;
import com.fasterxml.jackson.annotation.JsonFormat;
import com.fasterxml.jackson.annotation.JsonIgnore;
import io.swagger.v3.oas.annotations.media.Schema;
import lombok.Data;

import java.time.LocalDate;
import java.time.LocalDateTime;

@Data
@TableName("t_task")
@Schema(description = "待办任务")
public class Task {

    @TableId(type = IdType.AUTO)
    @Schema(description = "主键")
    private Long id;

    @Schema(description = "标题", example = "完成开题报告")
    private String title;

    @TableField(updateStrategy = FieldStrategy.ALWAYS)
    @Schema(description = "备注")
    private String description;

    @Schema(description = "优先级：1低 2中 3高")
    private Integer priority;

    @Schema(description = "完成状态：0未完成 1已完成")
    private Integer finished;

    @TableField(updateStrategy = FieldStrategy.ALWAYS)
    @JsonFormat(pattern = "yyyy-MM-dd")
    @Schema(description = "截止日期")
    private LocalDate dueDate;

    @JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss")
    private LocalDateTime createTime;

    @JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss")
    private LocalDateTime updateTime;

    @TableLogic
    @JsonIgnore
    private Integer deleted;
}
```

拆开看（每一组字段）：

| 字段 | 注解 | 作用 |
|---|---|---|
| `id` | `@TableId(type = AUTO)` | 数据库自增主键 |
| `title` | 无 | 普通列，驼峰映射 |
| `description` | `@TableField(updateStrategy = ALWAYS)` | 允许被清空（null 也写 SQL） |
| `priority` / `finished` | 无 | 整数状态字段 |
| `dueDate` | `ALWAYS` + `@JsonFormat("yyyy-MM-dd")` | 日期格式对齐前端 |
| `createTime` / `updateTime` | `@JsonFormat` | 时间格式；值由数据库维护 |
| `deleted` | `@TableLogic` + `@JsonIgnore` | 逻辑删除；不输出给前端 |

类级注解：

| 注解 | 作用 |
|---|---|
| `@Data` | Lombok 生成 getter/setter/toString |
| `@TableName("t_task")` | 类 ↔ 表 |
| `@Schema(description=...)` | 文档里这个实体的说明 |

**易错**：`updateStrategy` 写成 `FieldStrategy.NOT_NULL` → 清空备注失效；`LocalDate` 写成 `Date` → JSON 格式对不上。

### 2.5 `dto/TaskQuery.java` 与 `TaskStats.java` —— 按字段组

```java
@Data
@Schema(description = "分页查询参数")
public class TaskQuery {
    private Long pageNum = 1L;     // 组 1：分页
    private Long pageSize = 5L;
    private String keyword;        // 组 2：筛选
    private Integer finished;
}
```

```java
@Data
@Schema(description = "任务统计")
public class TaskStats {
    private long total;            // 组 1：三个数字
    private long finished;
    private long unfinished;
    private boolean fromCache;     // 组 2：缓存状态
    private long ttl;
}
```

拆开看：

| 字段组 | 作用 | 谁填 |
|---|---|---|
| `pageNum` / `pageSize` | 分页参数 | 前端 URL 参数 |
| `keyword` / `finished` | 筛选条件 | 前端 URL 参数 |
| `total` / `finished` / `unfinished` | 统计数字 | Service 查库算出来 |
| `fromCache` / `ttl` | 缓存是否命中 / 剩余秒数 | Service 读缓存时填 |

**语法点**：`Long` 可为 null，`long` 不能；`1L` 是 long 字面量；`@Data` 生成 getter/setter，Jackson 才能序列化。

**易错**：字段名和前端不一致（`fromCache` vs `from_cache`）→ 前端永远 `undefined`。

### 2.7 `service/TaskService.java` —— 6 个方法声明

```java
public interface TaskService extends IService<Task> {
    IPage<Task> pageTasks(TaskQuery query);   // 分页查询
    TaskStats stats();                        // 统计（带缓存）
    Task createTask(Task task);               // 新增
    Task updateTask(Long id, Task task);      // 更新
    boolean removeTask(Long id);              // 删除
    Task toggleFinished(Long id);             // 切换状态
}
```

拆开看：

| 方法 | 输入 | 输出 | 谁调用 |
|---|---|---|---|
| `pageTasks` | 分页条件 | `IPage<Task>` | Controller.page |
| `stats` | 无 | `TaskStats` | Controller.stats |
| `createTask` | 任务对象 | 落库后的任务 | Controller.create |
| `updateTask` | id + 任务对象 | 更新后的任务 | Controller.update |
| `removeTask` | id | 是否成功 | Controller.delete |
| `toggleFinished` | id | 切换后的任务 | Controller.toggle |

**语法点**：`接口 extends 接口`；方法只有签名，没有方法体；返回类型可以是泛型。

**易错**：接口方法漏写 `public`（默认就是 public，但习惯上省略）；返回类型和实现不一致 → 编译失败。

### 2.8 `service/impl/TaskServiceImpl.java` —— 拆成 10 块

这个文件是后端核心，按方法拆开看。

#### 2.8.1 类声明与依赖

```java
@Slf4j
@Service
@RequiredArgsConstructor
public class TaskServiceImpl extends ServiceImpl<TaskMapper, Task> implements TaskService {

    public static final String STATS_KEY = "todo:stats";
    private static final long STATS_TTL_SECONDS = 60L;

    private final StringRedisTemplate redisTemplate;
    private final ObjectMapper objectMapper;
}
```

| 小组件 | 作用 | 关键点 |
|---|---|---|
| `extends ServiceImpl<M, T>` | 拿到 `save/getById/page/count` 等 | 泛型是 Mapper 和实体 |
| `implements TaskService` | 实现业务接口 | 方法必须全部实现 |
| `@Slf4j` | 生成 `log` | Lombok |
| `@RequiredArgsConstructor` | 为 final 字段生成构造器 | 构造器注入 |
| `STATS_KEY` | 缓存 key | 命名 `业务:对象` |
| `STATS_TTL_SECONDS` | 缓存 60 秒 | 演示用短 TTL |

**易错**：字段没加 `final` → `@RequiredArgsConstructor` 不生成它的构造器参数 → 注入为 null。

#### 2.8.2 `pageTasks`：拼条件 + 分页

```java
@Override
public IPage<Task> pageTasks(TaskQuery query) {
    Page<Task> page = new Page<>(query.getPageNum(), query.getPageSize());

    LambdaQueryWrapper<Task> wrapper = new LambdaQueryWrapper<Task>()
            .like(StringUtils.hasText(query.getKeyword()), Task::getTitle, query.getKeyword())
            .eq(query.getFinished() != null, Task::getFinished, query.getFinished())
            .orderByAsc(Task::getFinished)
            .orderByDesc(Task::getPriority)
            .orderByDesc(Task::getId);

    return this.page(page, wrapper);
}
```

拆开看：

| 小组件 | 作用 | 关键点 |
|---|---|---|
| `new Page<>(页码, 条数)` | 分页对象 | 页码从 1 开始 |
| `.like(开关, 字段, 值)` | 模糊搜索 | 开关为 false 时不拼条件 |
| `.eq(开关, 字段, 值)` | 等值筛选 | `finished != null` 才拼 |
| 三个 `orderBy` | 排序 | 未完成 → 优先级高 → id 新 |
| `this.page(...)` | 执行分页 | 需要分页拦截器 |

**语法点**：`Task::getTitle` 方法引用；链式调用每个方法返回 wrapper 自身。

**易错**：没注册分页拦截器 → `page()` 退化成查全表；`like` 的开关传 `false` 写成字符串 "false"（类型错，编译报错）。

#### 2.8.3 `stats`：先读缓存

```java
@Override
public TaskStats stats() {
    try {
        String json = redisTemplate.opsForValue().get(STATS_KEY);
        if (json != null) {
            TaskStats cached = objectMapper.readValue(json, TaskStats.class);
            Long ttl = redisTemplate.getExpire(STATS_KEY, TimeUnit.SECONDS);
            cached.setFromCache(true);
            cached.setTtl(ttl == null ? 0L : ttl);
            return cached;
        }
    } catch (Exception e) {
        log.warn("读 Redis 失败，降级查库：{}", e.getMessage());
    }
    // 下面继续：未命中查库
}
```

拆开看：

| 小组件 | 作用 | 关键点 |
|---|---|---|
| `opsForValue().get(key)` | 读字符串 | key 用常量 |
| `readValue(json, 类)` | JSON → 对象 | 用共享的 ObjectMapper |
| `getExpire(...)` | 剩余秒数 | `-1` 永不过期，`-2` 不存在 |
| `setFromCache(true)` / `setTtl` | 告诉前端命中了 | 演示用 |
| `catch` | 降级 | Redis 挂了继续查库 |

**易错**：反序列化失败没兜住 → 接口 500；`ttl` 为 null 直接 set → 前端拿到 null。

#### 2.8.4 `stats`：未命中查库并写回

```java
long total = this.count();
long finished = this.count(new LambdaQueryWrapper<Task>().eq(Task::getFinished, 1));

TaskStats stats = new TaskStats();
stats.setTotal(total);
stats.setFinished(finished);
stats.setUnfinished(total - finished);
stats.setFromCache(false);
stats.setTtl(STATS_TTL_SECONDS);

try {
    redisTemplate.opsForValue().set(STATS_KEY,
            objectMapper.writeValueAsString(stats),
            STATS_TTL_SECONDS, TimeUnit.SECONDS);
} catch (Exception e) {
    log.warn("写 Redis 失败：{}", e.getMessage());
}
return stats;
```

拆开看：

| 小组件 | 作用 | 关键点 |
|---|---|---|
| `count()` | 总数（自动带 `deleted=0`） | MyBatis-Plus 提供 |
| `count(wrapper)` | 已完成数 | 条件计数 |
| `total - finished` | 未完成数 | 不查第三次 |
| `writeValueAsString` | 对象 → JSON | 与读缓存对称 |
| `set(key, value, ttl, unit)` | 带过期时间写入 | 不传 TTL 就永不过期 |

**易错**：`set` 忘传 TTL → 缓存永不过期，数字永远不刷新。

#### 2.8.5 `createTask`：新增

```java
@Override
@Transactional(rollbackFor = Exception.class)
public Task createTask(Task task) {
    if (task.getPriority() == null) task.setPriority(2);
    if (task.getFinished() == null) task.setFinished(0);

    this.save(task);          // INSERT，并把自增 id 回填到 task
    clearStatsCache();        // 统计数据变了

    return this.getById(task.getId());   // 补齐数据库生成的时间字段
}
```

| 小组件 | 作用 | 关键点 |
|---|---|---|
| 两个默认值 | 前端没传时兜底 | 优先级默认中，状态默认未完成 |
| `save` | 插入 | 自增 id 回填 |
| `clearStatsCache()` | 删缓存 | 下次读自然回源 |
| `getById` | 重新查 | 拿到 create_time 等 |

**易错**：直接 `return task` → 返回给前端的 create_time 是 null。

---

#### 2.8.6 `updateTask`：更新

```java
@Override
@Transactional(rollbackFor = Exception.class)
public Task updateTask(Long id, Task task) {
    task.setId(id);           // 以路径 id 为准，防篡改
    task.setDeleted(null);    // 不允许改逻辑删除标记

    this.updateById(task);    // UPDATE ... WHERE id = ?
    clearStatsCache();

    return this.getById(id);
}
```

| 小组件 | 作用 | 关键点 |
|---|---|---|
| `setId(id)` | 路径 id 覆盖请求体 id | 防止改别人数据 |
| `setDeleted(null)` | 不更新删除标记 | 安全 |
| `updateById` | 按主键更新 | 默认跳过 null 字段 |
| `getById` | 返回最新数据 | |

**易错**：不 `setId` → 请求体没 id 时 update 影响 0 行，接口却返回「成功」。

---

#### 2.8.7 `removeTask`：逻辑删除

```java
@Override
@Transactional(rollbackFor = Exception.class)
public boolean removeTask(Long id) {
    boolean removed = this.removeById(id);   // 有 @TableLogic 时是 UPDATE deleted=1
    clearStatsCache();
    return removed;
}
```

| 小组件 | 作用 |
|---|---|
| `removeById` | 逻辑删除（不是 DELETE） |
| `clearStatsCache` | 总数变了 |

**易错**：实体上漏 `@TableLogic` → 变成物理删除，数据找不回来。

#### 2.8.8 `toggleFinished`：切换状态

```java
@Override
@Transactional(rollbackFor = Exception.class)
public Task toggleFinished(Long id) {
    Task task = this.getById(id);
    if (task == null) return null;

    task.setFinished(task.getFinished() != null && task.getFinished() == 1 ? 0 : 1);
    this.updateById(task);
    clearStatsCache();

    return this.getById(id);
}
```

| 小组件 | 作用 |
|---|---|
| `getById` | 先查当前值 |
| 三元取反 | 1 → 0，其它 → 1 |
| `updateById` | 只更新这条 |
| `getById` | 返回最新 |

**易错**：用 `1 - finished` → 脏数据 null 时抛 NPE。

#### 2.8.9 `clearStatsCache`：删缓存

```java
private void clearStatsCache() {
    try {
        redisTemplate.delete(STATS_KEY);
    } catch (Exception e) {
        log.warn("清缓存失败：{}", e.getMessage());
    }
}
```

| 小组件 | 作用 |
|---|---|
| `delete(key)` | 删除缓存 |
| `try/catch` | 缓存故障不影响业务 |

#### 2.8.10 四个写方法的小结

| 方法 | 清缓存原因 | 返回什么 |
|---|---|---|
| `createTask` | 总数 +1 | 重新查出的任务 |
| `updateTask` | 状态可能变 | 重新查出的任务 |
| `removeTask` | 总数 −1 | boolean |
| `toggleFinished` | 完成/未完成互换 | 重新查出的任务 |

### 2.10 `common/Result.java` —— 3 块

```java
@Data
@Schema(description = "统一响应")
public class Result<T> {
    private Integer code;
    private String message;
    private T data;

    public static <T> Result<T> ok() { return ok(null); }

    public static <T> Result<T> ok(T data) {
        Result<T> r = new Result<>();
        r.setCode(200);
        r.setMessage("成功");
        r.setData(data);
        return r;
    }

    public static <T> Result<T> fail(Integer code, String message) {
        Result<T> r = new Result<>();
        r.setCode(code);
        r.setMessage(message);
        return r;
    }
}
```

| 小组件 | 作用 | 关键点 |
|---|---|---|
| 三个字段 | code / message / data | 前端只认 `code === 200` |
| `ok()` | 无数据成功 | 删除接口用 |
| `ok(data)` | 带数据成功 | 查询/新增用 |
| `fail(code,msg)` | 失败 | 400 参数错，404 不存在 |

**语法点**：`static <T> Result<T>` 静态泛型方法；`new Result<>()` 菱形推断。

## 六、后端最常见的 7 个错

| 现象 | 原因 | 解决 |
|---|---|---|
| 编译报「程序包不存在」 | 目录和 `package` 不一致 | 目录逐级对上 |
| 接口 404 | 启动类不在业务代码父包 | 移到 `com.example.todo` |
| 找不到 `TaskMapper` | 漏 `@MapperScan` 或包名错 | 检查启动类 |
| 启动即退出 | MySQL 没起 | 看 `Communications link failure` |
| 字段全 null | 驼峰映射没开 | `map-underscore-to-camel-case: true` |
| 更新后旧值还在 | 字段没加 `updateStrategy = ALWAYS` | 补注解 |
| 分页返回全表 | 没注册分页拦截器 | 补 `MybatisPlusInterceptor` |
