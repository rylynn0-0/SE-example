## 三、`init.sql` 拆开看（7 块）

### 3.1 连接字符集

```sql
SET NAMES utf8mb4;
```

| 小组件 | 作用 | 不写会怎样 |
|---|---|---|
| `SET NAMES utf8mb4` | 本次连接的 客户端/连接/结果 全用四字节 UTF-8 | 容器内客户端可能按 latin1 解析，中文变 `å®Œæˆ` |

**语法点**：这是一条**会话级**设置，不是持久配置；每次连接都要设。

**易错**：只在建库时设 `utf8mb4`，但客户端连接是 latin1 → 写入时就已经乱码。

---

### 3.2 建库

```sql
CREATE DATABASE IF NOT EXISTS todo_db
    DEFAULT CHARACTER SET utf8mb4
    COLLATE utf8mb4_general_ci;

USE todo_db;
```

| 小组件 | 作用 |
|---|---|
| `IF NOT EXISTS` | 库已存在时不报错，可重复执行 |
| `DEFAULT CHARACTER SET` | 库的默认字符集 |
| `COLLATE` | 排序/比较规则（大小写不敏感） |
| `USE todo_db` | 后面所有语句作用于这个库 |

**易错**：漏 `USE` → 报「No database selected」；库名和 `application.yml` 的 `${MYSQL_DB:todo_db}` 不一致 → 后端连不上。

---

### 3.3 建表：逐个列

```sql
CREATE TABLE t_task
(
    id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键 ID',
    title       VARCHAR(100)    NOT NULL COMMENT '任务标题',
    description VARCHAR(500)             DEFAULT NULL COMMENT '任务备注',
    priority    TINYINT         NOT NULL DEFAULT 1 COMMENT '优先级：1低 2中 3高',
    finished    TINYINT         NOT NULL DEFAULT 0 COMMENT '完成状态：0未完成 1已完成',
    due_date    DATE                     DEFAULT NULL COMMENT '截止日期',
    create_time DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP
                                 ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    deleted     TINYINT         NOT NULL DEFAULT 0 COMMENT '逻辑删除：0未删除 1已删除',
    PRIMARY KEY (id),
    KEY idx_finished (finished),
    KEY idx_title (title)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4;
```

按「列组」拆开：

| 列组 | 列 | 写法 | 为什么 |
|---|---|---|---|
| 主键 | `id` | `BIGINT UNSIGNED AUTO_INCREMENT` | 自增；无符号；范围大 |
| 文本 | `title` | `VARCHAR(100) NOT NULL` | 限长 + 必填 |
| 备注 | `description` | `VARCHAR(500) DEFAULT NULL` | 可空 |
| 状态 | `priority` / `finished` | `TINYINT NOT NULL DEFAULT ...` | 1 字节，整数比 Boolean 稳 |
| 日期 | `due_date` | `DATE DEFAULT NULL` | 只要年月日 |
| 时间 | `create_time` / `update_time` | `DATETIME DEFAULT CURRENT_TIMESTAMP` | 数据库自动维护 |
| 逻辑删除 | `deleted` | `TINYINT NOT NULL DEFAULT 0` | 配合 `@TableLogic` |

**语法点**：

| 写法 | 含义 |
|---|---|
| `列名 类型 [约束]` | 每列一行，逗号分隔 |
| `NOT NULL` / `DEFAULT 值` | 非空 / 默认值 |
| `AUTO_INCREMENT` | 自增，插入时不用给值 |
| `COMMENT '说明'` | 列注释，`DESC 表` 可见 |
| `ON UPDATE CURRENT_TIMESTAMP` | 更新任意列时自动刷新 |

**易错**：`title` 忘了 `NOT NULL` → 能写入空标题，前端却以为必填；`due_date` 写成 `DATETIME` → 后端 `LocalDate` 反序列化失败。

---

### 3.4 建表：索引

```sql
PRIMARY KEY (id),
KEY idx_finished (finished),
KEY idx_title (title)
```

| 索引 | 对应查询 | 注意 |
|---|---|---|
| 主键 | 按 id 查/更新/删 | 唯一且非空 |
| `idx_finished` | 状态筛选、排序 | 区分度低，但过滤有效 |
| `idx_title` | 关键词搜索 | `LIKE '%词%'` 用不上，前缀匹配才用得上 |

**语法点**：`KEY 名字 (列)` 建普通索引；索引名用 `idx_列名`。

**易错**：给每个列都建索引 → 写入变慢、占空间；搜索用前置 `%` 却以为走了索引。

---

### 3.5 建表：表选项

```sql
ENGINE = InnoDB
DEFAULT CHARSET = utf8mb4
COLLATE = utf8mb4_general_ci
COMMENT = '待办任务表';
```

| 小组件 | 作用 |
|---|---|
| `ENGINE = InnoDB` | 支持事务、行锁、外键 |
| `CHARSET` / `COLLATE` | 表级字符集 |
| `COMMENT` | 表注释 |

**易错**：用 `MyISAM` → 没有事务，`@Transactional` 白加。

---

### 3.6 演示数据

```sql
INSERT INTO t_task (title, description, priority, finished, due_date)
VALUES ('完成软工课程设计开题报告', '整理论文选题、技术选型与进度安排', 3, 0, DATE_ADD(CURDATE(), INTERVAL 2 DAY)),
       ('搭建 Spring Boot 后端工程骨架', '引入 Web、MyBatis-Plus、Redis、Knife4j', 3, 1, DATE_SUB(CURDATE(), INTERVAL 3 DAY));
```

| 小组件 | 作用 |
|---|---|
| `INSERT INTO 表 (列...)` | 指定列名，顺序可换 |
| `VALUES (...), (...)` | 一次插多行 |
| `DATE_ADD(CURDATE(), INTERVAL 2 DAY)` | 今天 + 2 天 |
| `DATE_SUB(...)` | 今天 − N 天 |

**为什么用相对日期**：写死 `'2026-11-10'` 过段时间全变成逾期；相对日期保证任何时候演示都合理。

**易错**：列顺序和值顺序不一致 → 数据错位；漏列 → 用默认值（可能不是你想要的）。

### 3.7 这块脚本怎么执行

**方式一：Docker 自动（本项目）**

```yaml
volumes:
  - ./backend/src/main/resources/db/init.sql:/docker-entrypoint-initdb.d/init.sql:ro
```

| 操作 | 会执行吗 |
|---|---|
| 首次 `docker compose up` | ✅ |
| 再次 `up` | ❌ 数据卷已存在 |
| `down` 后 `up` | ❌ |
| `down -v` 后 `up` | ✅ |

**方式二：本地 MySQL**

```bash
mysql -uroot -p < backend/src/main/resources/db/init.sql
```

**方式三：容器内**

```bash
docker exec -i todo-mysql mysql -uroot -proot123456 < backend/src/main/resources/db/init.sql
```

## 四、SQL 语法速查

### 4.1 建库建表

```sql
CREATE DATABASE IF NOT EXISTS todo_db DEFAULT CHARACTER SET utf8mb4;
USE todo_db;

CREATE TABLE t_task (
    id       BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    title    VARCHAR(100) NOT NULL,
    finished TINYINT NOT NULL DEFAULT 0,
    PRIMARY KEY (id),
    KEY idx_finished (finished)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4;
```

### 4.2 增删改查

```sql
INSERT INTO t_task (title, priority) VALUES ('学习 SQL', 2);

SELECT * FROM t_task WHERE deleted = 0 AND finished = 0 ORDER BY id DESC;

UPDATE t_task SET finished = 1 WHERE id = 1;

DELETE FROM t_task WHERE id = 1;              -- 物理删除
UPDATE t_task SET deleted = 1 WHERE id = 1;   -- 逻辑删除
```

### 4.3 条件与分页

| 写法 | 含义 |
|---|---|
| `WHERE a = 1 AND b > 2` | 条件 |
| `ORDER BY 列 DESC` | 排序（`ASC` 可省略） |
| `LIMIT 0, 5` | 第 1 页（跳过 0 条取 5 条） |
| `LIMIT 5, 5` | 第 2 页 |
| `COUNT(*)` | 计数 |
| `LIKE '%词%'` | 模糊匹配（前置 `%` 用不上索引） |

### 4.4 常用查看命令

```sql
SHOW TABLES;
DESC t_task;
SHOW INDEX FROM t_task;
EXPLAIN SELECT * FROM t_task WHERE finished = 0;
```

## 五、Redis 里到底存了什么（3 块）

Redis 不存表，只存缓存。本项目只有 1 个 key。

### 5.1 key 的设计

```
todo:stats
```

| 小组件 | 含义 |
|---|---|
| `todo` | 业务名 |
| `stats` | 对象名（统计） |
| `:` 分隔 | 命名规范，便于 `KEYS "todo:*"` 批量操作 |

### 5.2 value 的结构

```json
{"total":8,"finished":3,"unfinished":5,"fromCache":false,"ttl":60}
```

就是 `TaskStats` 序列化后的 JSON。**注意 `fromCache` 在缓存里是 false**，命中后由后端改写为 true，不会写回缓存。

### 5.3 TTL

| 操作 | TTL 变化 |
|---|---|
| 未命中写回 | 60 秒 |
| 命中读取 | 不变（只读剩余秒数） |
| 写操作 | key 被删，下次读重新写 |

### 5.4 命令

```bash
GET todo:stats          # 取内容
TTL todo:stats          # 剩余秒数（-1 永不过期，-2 不存在）
DEL todo:stats          # 手动删（演示回源）
KEYS "todo:*"           # 按前缀找
```

**易错**：`TTL` 返回 -2 说明 key 不存在（过期或没访问过接口）；不要在生产用 `KEYS *`，量大时阻塞。

## 六、建完怎么验证

### 6.1 数据在不在

```bash
docker exec -it todo-mysql mysql -utodo -ptodo123456 todo_db \
  -e "SELECT id, title, priority, finished FROM t_task;"
```

应看到 8 行，其中 3 行 `finished=1`。

### 6.2 结构对不对

```sql
SHOW TABLES;
DESC t_task;
SHOW INDEX FROM t_task;
SELECT COUNT(*) FROM t_task;
```

### 6.3 逻辑删除验证

```bash
curl -X DELETE http://localhost:8080/api/tasks/1

docker exec -it todo-mysql mysql -utodo -ptodo123456 todo_db \
  -e "SELECT id, title, deleted FROM t_task WHERE id = 1;"
```

记录还在，`deleted=1`。

### 6.4 缓存验证

```bash
curl http://localhost:8080/api/tasks/stats
docker exec -it todo-redis redis-cli GET todo:stats
docker exec -it todo-redis redis-cli TTL todo:stats
```

| 现象 | 说明 |
|---|---|
| `KEYS` 为空 | 还没请求统计，或已过期 |
| `GET` 有 JSON | 写入成功 |
| `TTL` 0～60 | 剩余秒数 |

## 七、数据库命名约定

| 类型 | 约定 | 例子 |
|---|---|---|
| 库 | 小写下划线 | `todo_db` |
| 表 | 小写下划线，`t_` 前缀 | `t_task` |
| 列 | 小写下划线 | `due_date` |
| 主键 | 统一 `id` | `id` |
| 索引 | `idx_列名` | `idx_finished` |
| 逻辑删除列 | 统一 `deleted` | `deleted` |

对齐关系：

```
数据库 due_date  ←→  Java dueDate    （驼峰映射）
数据库 t_task    ←→  @TableName("t_task")
数据库 deleted   ←→  @TableLogic
```

## 八、数据库最常见的 7 个错

| 现象 | 原因 | 解决 |
|---|---|---|
| `Table 'todo_db.t_task' doesn't exist` | init.sql 没执行 | `down -v` 重建；看日志 |
| 中文变 `å®Œæˆ` | 连接字符集是 latin1 | 脚本头 `SET NAMES utf8mb4` + 容器 `LANG=C.UTF-8` |
| 中文变问号 | 库/表不是 utf8mb4 | 建库建表都指定 |
| 时间差 8 小时 | 时区不一致 | 容器 `TZ` + JDBC `serverTimezone` |
| `Access denied` | 账号密码不对 | 对照 compose 的 `MYSQL_USER/PASSWORD` |
| 删了还能查到 | 逻辑删除（正常） | 看 `deleted` 列 |
| 改了脚本没生效 | 数据卷已存在 | `docker compose down -v` |
