# 13 · 改：编辑弹窗（PUT）与状态开关（PATCH）

> 公共部分见 [10 总览](10-增删改查总览.md)。
> 代码里的 `//`、`--`、`<!-- -->` 是中文解释，写在代码后面；新手先读注释，再读代码。
>
> 「改」有两个入口：
>
> | 入口 | 改什么 | HTTP |
> |---|---|---|
> | 编辑弹窗 → 保存 | 标题、备注、优先级、日期 | `PUT /api/tasks/{id}` |
> | 行内开关 | 只改 `finished` | `PATCH /api/tasks/{id}/finished` |
>
> 两个请求都走和查询相同的代理（Vite / Nginx）。

---

## 〇、先看两条流程

```
编辑：
点「编辑」→ openEdit(row) 回填 form → 点「保存」
→ PUT /api/tasks/{id} → Controller.update → Service.updateTask
→ UPDATE ... WHERE id=? AND deleted=0 → loadAll → 行更新

开关：
点开关 → handleToggle(row)
→ PATCH /api/tasks/{id}/finished → Controller.toggle → Service.toggleFinished
→ getById → 取反 → updateById → loadAll → 开关/统计/排序更新
```

## 一、入口 A：编辑弹窗

### 1. 回填：列表行 → 表单（不发请求）

`TodoView.vue:192-202`：

```js
function openEdit(row) { // row 是表格里当前行的数据
  dialog.id = row.id // 记住正在编辑哪条；有 id 就表示“编辑模式”
  Object.assign(form, { // 把当前行的数据复制到表单
    title: row.title,                   // 标题
    description: row.description ?? '', // 备注；null 时用空串
    priority: row.priority ?? 2,        // 优先级；null 时默认 2（中）
    dueDate: row.dueDate ?? null        // 日期；null 保持 null
  })
  dialog.visible = true // 打开弹窗
}
```

**关键点**：列表接口返回的 `row` 已经是完整任务对象，
所以编辑时不用再调 `GET /api/tasks/{id}` 查详情。

### 2. 保存：走 `updateTask`

`TodoView.vue:216-218`：

```js
if (dialog.id) { // dialog.id 有值，说明是编辑，不是新增
  await updateTask(dialog.id, { ...form }) // 把 id 和表单一起发给后端
  ElMessage.success('修改成功') // 成功后提示
}
```

`api/task.js:53-55`：

```js
export function updateTask(id, data) { // 更新接口封装
  return request.put(`/tasks/${id}`, data) // PUT /api/tasks/{id}；data 是请求体
}
```

请求体（JSON 不能写注释，字段说明看下面表格）：

```json
{
  "title": "完成软工课程设计开题报告（已改期）",
  "description": "整理论文选题",
  "priority": 3,
  "dueDate": "2026-11-20"
}
```

| 字段 | 意思 |
|---|---|
| `title` | 标题，必填 |
| `description` | 备注；传 `null` 可以清空 |
| `priority` | 1 低 / 2 中 / 3 高 |
| `dueDate` | 截止日期；传 `null` 可以清空 |

### 3. 后端：先确认存在，再更新

`TaskController.java:121-135`：

```java
@PutMapping("/{id}") // 处理 PUT /api/tasks/{id}
public Result<Task> update(@PathVariable Long id, @RequestBody Task task) { // id 来自 URL，task 来自 JSON
    if (!StringUtils.hasText(task.getTitle())) { // 标题不能为空
        return Result.fail(400, "任务标题不能为空"); // 业务失败，code=400
    }
    if (taskService.getById(id) == null) { // 先查 id 是否存在
        return Result.fail(404, "任务不存在"); // 不存在就别“假成功”
    }
    return Result.ok(taskService.updateTask(id, task)); // 存在，更新并返回
}
```

`TaskServiceImpl.java:207-223`：

```java
@Transactional(rollbackFor = Exception.class) // 出异常回滚
public Task updateTask(Long id, Task task) { // 返回更新后的任务
    task.setId(id); // 以 URL 里的 id 为准，忽略请求体里可能伪造的 id
    task.setDeleted(null); // 不允许通过编辑接口改逻辑删除标记
    this.updateById(task); // 生成 UPDATE ... WHERE id=? AND deleted=0
    clearStatsCache(); // 统计可能变化，删掉 Redis 统计缓存
    return this.getById(id); // 返回数据库里的最新数据
}
```

### 4. 实际 SQL

```sql
UPDATE t_task                   -- 任务表
SET title=?,                    -- 新标题
    description=?,              -- 新备注；传 null 也能清空
    priority=?,                 -- 新优先级
    due_date=?                  -- 新日期；传 null 也能清空
WHERE id=? AND deleted=0;       -- 只更新未删除的这条
```

- `description` / `dueDate` 即使传 `null` 也会写进 SQL，
  因为实体上加了 `@TableField(updateStrategy = FieldStrategy.ALWAYS)`，
  这样才能把备注/日期清空。
- 表单不提交 `finished`，所以编辑弹窗不会顺带改完成状态。

### 5. 回显

```js
dialog.visible = false // 关闭弹窗
await loadAll()        // 重新查列表和统计
```

重新查列表后，这一行的标题、优先级标签、日期、更新时间都会更新。

## 二、入口 B：状态开关

### 1. 模板：单向绑定，不抢跑

`TodoView.vue:374`：

```vue
<el-switch :model-value="row.finished === 1" @change="handleToggle(row)" /> <!-- :model-value 只读后端 finished；@change 调 handleToggle -->
```

为什么不用 `v-model`？
`v-model` 会在点击瞬间把开关改掉，如果后端失败，页面就和数据库不一致。
`:model-value` 只读后端数据，成功 `loadAll` 后开关才变。

### 2. 请求：PATCH

`TodoView.vue:271-278`：

```js
async function handleToggle(row) { // 点开关时执行
  try { // 发 PATCH 请求
    await toggleTask(row.id) // PATCH /api/tasks/{id}/finished，不需要请求体
    await loadAll() // 成功后重新查列表，开关状态以后端为准
  } catch (e) { // 失败时拦截器已经弹过提示，开关保持原样
  }
}
```

`api/task.js:65-67`：

```js
export function toggleTask(id) { // 切换完成状态接口
  return request.patch(`/tasks/${id}/finished`) // PATCH；局部更新，只改 finished
}
```

### 3. 后端：查出来 → 取反 → 更新

`TaskController.java:147-157`：

```java
@PatchMapping("/{id}/finished") // 处理 PATCH /api/tasks/{id}/finished
public Result<Task> toggle(@PathVariable Long id) { // id 来自 URL
    Task task = taskService.toggleFinished(id); // 让 Service 把 finished 取反
    if (task == null) { // 任务不存在
        return Result.fail(404, "任务不存在"); // 业务失败，code=404
    }
    return Result.ok(task); // 返回切换后的任务
}
```

`TaskServiceImpl.java:254-273`：

```java
@Transactional(rollbackFor = Exception.class) // 出异常回滚
public Task toggleFinished(Long id) { // 返回切换后的任务
    Task task = this.getById(id); // 先查当前值
    if (task == null) return null; // 不存在，交给 Controller 返回 404

    task.setFinished(task.getFinished() != null && task.getFinished() == 1 ? 0 : 1); // 1 变 0，其它变 1
    this.updateById(task); // 写回数据库
    clearStatsCache(); // 完成数量变了，删统计缓存
    return this.getById(id); // 返回最新数据
}
```

核心 SQL：

```sql
UPDATE t_task                   -- 任务表
SET finished=?              -- 新的完成状态：0 或 1
WHERE id=? AND deleted=0;   -- 只改这一条未删除的记录
```

> 注意：因为 Service 是「先查完整实体，再 `updateById`」，
> 日志里的 `SET` 可能还会带上 `title`、`description` 等原值。
> 业务结果没问题，只是 SQL 比「只改 finished」宽一点。

### 4. 回显

```js
await loadAll() // 重新查列表和统计
```

- `row.finished` 变 → 开关状态变。
- 统计重新 `COUNT` → 已完成/未完成数字互换。
- 列表按 `finished ASC` 排序 → 已完成的任务会移到后面。

## 四、3 个常见坑

| 现象 | 原因 |
|---|---|
| 编辑弹窗是空的 | `openEdit(row)` 没拿到 `row`，或列表没返回字段 |
| 备注/日期清不掉 | 字段没加 `FieldStrategy.ALWAYS` |
| 开关点完弹回 | 请求失败，或没有重新 `loadAll` |
