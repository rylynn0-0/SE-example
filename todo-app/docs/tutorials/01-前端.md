# 01 · 前端：用户看到的一切

> 一句话：前端就是**跑在浏览器里的代码**，负责「把数据画成界面，把点击变成请求」。

> 配套手册：文件怎么建、每个文件里的语法怎么写，见 [07 前端模板](07-前端模板.md)（模板 + 语法点放在一起）。

## 一、先跑起来（3 分钟）

前置：装好 Node 18+（本项目 Docker 里用的是 Node 22）。

```bash
cd todo-app/frontend
npm install          # 第一次才需要；仓库里已有 node_modules 可跳过
npm run dev
```

终端会输出：

```
  VITE v5.x  ready in 300 ms
  ➜  Local:   http://localhost:5173/
```

浏览器打开 `http://localhost:5173`，应该能看到待办列表。

> **后端没启动也能打开页面**，只是表格会弹「网络异常」。
> 因为前端和后端是两个独立程序，前端先画界面、再异步拿数据。

### 第一个实验：热更新

打开 `TodoView.vue`，找到 `<el-button type="primary" @click="handleSearch">查询</el-button>`，
把「查询」改成「搜一下」，保存。

**不用刷新浏览器**，按钮文字立刻变了。这就是 Vite 的热更新（HMR）。

## 二、浏览器只认三样东西

浏览器只懂 **HTML（结构）、CSS（样式）、JavaScript（行为）**。
它不认识 `.vue` 文件，也不认识 `import App from './App.vue'` 这种写法。

所以中间必须有人翻译：

```
你写的 .vue  ──Vite 编译──▶  浏览器能跑的 HTML + JS + CSS
```

`.vue` 文件叫**单文件组件（SFC）**，一个文件里同时写三块：

```vue
<script setup>
// 逻辑：数据、函数
</script>

<template>
  <!-- 结构：长得像 HTML -->
</template>

<style scoped>
/* 样式：scoped 表示只对当前组件生效 */
</style>
```

## 三、Vue 3 的三个核心

### 3.1 模板：声明「界面长什么样」

模板就是写在 `<template>` 里的类 HTML 代码，用几个特殊语法把数据和界面连起来：

| 写法 | 作用 | 本项目示例 |
|---|---|---|
| `{{ 值 }}` | 显示数据 | `{{ stats.total }}` |
| `:属性="值"` | 动态绑定属性（**冒号是关键**） | `:data="list"` |
| `@事件="函数"` | 绑定事件 | `@click="handleSearch"` |
| `v-model` | 双向绑定（输入框改了数据也改） | `v-model="query.keyword"` |
| `v-if` | 条件渲染（不满足就不存在） | — |
| `v-for` | 列表渲染 | 本项目交给了 `el-table` |

最容易错的是冒号：

```vue
<el-table data="list" />    <!-- ❌ 把字符串 "list" 传给了组件 -->
<el-table :data="list" />   <!-- ✅ 把 list 这个变量的值传进去 -->
```

### 3.2 响应式：数据变了，界面自己变

传统写法要手动改页面：

```js
list.push(task)
document.getElementById('list').innerHTML = render(list)   // 每次都得记得写
```

Vue 的写法：**只改数据，界面自动更新**。

```js
import { ref, reactive } from 'vue'

const count = ref(0)          // 包基本类型
count.value++                 // 注意：脚本里要写 .value

const query = reactive({      // 包对象
  pageNum: 1,
  keyword: ''
})
query.pageNum = 2             // 对象不用 .value
```

为什么两种？一句话记：

| | `ref` | `reactive` |
|---|---|---|
| 装什么 | 基本类型、数组、对象都行 | 只能装对象 / 数组 |
| 脚本里取值 | `x.value` | `obj.field` |
| 整体替换 | ✅ 可以 | ❌ 会丢响应式 |
| 本项目用在哪 | `list`、`total`、`loading` | `query`、`stats`、`form`、`dialog` |

**模板里不用写 `.value`**，Vue 自动拆包：

```vue
{{ count }}   <!-- 正确，不需要写成 count.value -->
```

### 3.3 组件：一个 `.vue` 文件就是一个组件

`<script setup>` 是 Vue 3 的简写：**顶层声明的变量和函数，模板里直接能用**，不需要 `return`。

```vue
<script setup>
import { ref } from 'vue'

const message = 'hello'
function sayHi() {
  alert(message)
}
</script>

<template>
  <button @click="sayHi">{{ message }}</button>
</template>
```

组件挂载到页面后，有几个「生命周期钩子」可以插入逻辑。本项目只用了 `onMounted`：

```js
import { onMounted } from 'vue'

onMounted(loadAll)   // 页面一打开就去后端拉数据
```

## 四、Element Plus：别人写好的组件

自己用原生 HTML 写一个带分页、斑马纹、排序的表格，大概要 200 行。
Element Plus 里是：

```vue
<el-table :data="list" stripe>
  <el-table-column prop="title" label="标题" />
</el-table>
```

### 4.1 注册

本项目在 `main.js` 里**一次性全量注册**：

```js
import ElementPlus from 'element-plus'
import 'element-plus/dist/index.css'     // 样式必须引，否则组件没有外观
import zhCn from 'element-plus/es/locale/lang/zh-cn'

app.use(ElementPlus, { locale: zhCn })   // 注册 + 中文语言包
```

不配中文语言包，分页会显示 `Go to`、`items/page`。

### 4.2 表格：默认列 vs 自定义列

默认直接显示字段值：

```vue
<el-table-column prop="title" label="任务标题" />
```

要改样式（比如完成后加删除线）就用插槽：

```vue
<el-table-column label="任务标题">
  <template #default="{ row }">
    <span :class="{ 'is-done': row.finished === 1 }">{{ row.title }}</span>
  </template>
</el-table-column>
```

`{ row }` 就是「这一行的数据」。

### 4.3 表单：三条规则缺一不可

```vue
<el-form ref="formRef" :model="form" :rules="rules" label-width="90px">
  <el-form-item label="标题" prop="title">
    <el-input v-model="form.title" />
  </el-form-item>
</el-form>
```

| 要素 | 漏了会怎样 |
|---|---|
| `:model="form"` | 校验完全不工作 |
| `:rules="rules"` | 校验完全不工作 |
| `prop="title"` | 这个字段不校验 |

校验规则是声明式的：

```js
const rules = {
  title: [
    { required: true, message: '请输入任务标题', trigger: 'blur' },
    { max: 100, message: '标题不能超过 100 个字符', trigger: 'blur' }
  ]
}
```

手动触发校验：

```js
const valid = await formRef.value.validate().catch(() => false)
if (!valid) return    // 校验不过就不保存
```

> `validate()` 校验失败会 **reject**，不写 `.catch` 会抛未捕获异常。

### 4.4 一个关键设计：开关用 `:model-value` 而不是 `v-model`

```vue
<el-switch :model-value="row.finished === 1" @change="handleToggle(row)" />
```

如果写 `v-model`，用户一拨开关本地数据就变了；万一来不及（或请求失败），界面就和数据库**不一致**。

现在的写法：拨开关 → 调接口 → 成功 → 重新拉列表 → 界面才变。**状态永远以数据库为准**。

## 五、本项目前端地图

`todo-app/frontend/` 下真正要看的只有这些：

| 文件 | 职责 | 先读哪个 |
|---|---|---|
| `index.html` | 页面骨架，唯一有 `<div id="app">` 的地方 | 第三个 |
| `src/main.js` | 创建应用、注册插件、挂载 | **第一个** |
| `src/App.vue` | 布局外壳：页头 + 内容区 | 第二个 |
| `src/router/index.js` | URL 对应哪个页面 | 第四个 |
| `src/views/TodoView.vue` | 唯一的业务页面，90% 的业务代码在这 | **第五个** |
| `src/api/request.js` | axios 实例 + 拦截器（请求的基础设施） | 第六个 |
| `src/api/task.js` | 每个接口一个函数 | 第七个 |
| `src/styles/global.css` | 全局样式 | 随手 |
| `vite.config.js` | 开发服务器、`/api` 代理、构建 | 排错时看 |
| `package.json` | 依赖和 `npm run` 命令 | 排错时看 |

它们是一条单向链：

```
index.html 的 <div id="app">
   └─ main.js：createApp(App) → app.use(...) → app.mount('#app')
        └─ App.vue：页头 + <router-view />
             └─ router/index.js：'/' → TodoView.vue
                  └─ TodoView.vue：统计卡片 + 表格 + 弹窗
                       └─ api/task.js → api/request.js → /api/tasks
```

**为什么 `App.vue` 这么空？** 它只做外壳。以后加「报表页」「设置页」，只改路由，`App.vue` 一行都不用动。

## 六、读懂 `TodoView.vue` 的顺序

这个文件约 600 行，硬读容易迷路。按作者的分区读：

```js
/* ========== 一、列表状态 ========== */   loading / list / total / query / stats
/* ========== 二、弹窗表单状态 ========== */ dialog / form / rules
/* ========== 三、数据加载 ========== */   loadList / loadStats / loadAll
/* ========== 四、交互动作 ========== */   handleSearch / openCreate / handleSave / handleDelete / handleToggle
/* ========== 五、初始化 ========== */     onMounted(loadAll)
```

先看状态有哪些，再看 `loadAll` 怎么拉数据，最后看每个按钮调了哪个函数。

数据加载的典型写法：

```js
async function loadList() {
  loading.value = true
  try {
    const data = await pageTasks({ ...query })
    list.value = data.records
    total.value = Number(data.total)
  } finally {
    loading.value = false      // 成功失败都要关，否则界面一直转圈
  }
}
```

`finally` 很关键：只在 `try` 里关，请求失败时就永远转圈。

## 七、点击是怎么变成请求的（先混个脸熟）

```
点击「查询」
  → handleSearch()            把页码重置为 1
  → pageTasks({ ...query })   api/task.js
  → request.get('/tasks')     api/request.js，baseURL 是 '/api'
  → GET /api/tasks?...        浏览器发出请求
  → Vite 或 Nginx 转发给后端   见 04 章
```

具体怎么和后端对齐字段、路径、格式，是 [04 前端与后端耦合](04-前端与后端耦合.md) 的内容，这里知道有这么条线就行。

## 八、自测：能不能答上来

1. `ref` 和 `reactive` 各装什么？脚本里怎么取值？
2. `<el-table data="list">` 和 `<el-table :data="list">` 差在哪？
3. 表单校验必须同时有哪三个东西？
4. 为什么 `App.vue` 里几乎没有业务代码？
5. `loadList` 的 `finally` 去掉会怎样？

<details>
<summary>参考答案</summary>

1. `ref` 装基本类型/数组/对象，脚本里用 `.value`；`reactive` 只能装对象/数组，脚本里直接 `obj.field`。
2. 前者传的是字符串 `"list"`，后者传的是变量 `list` 的值。
3. `:model`、`:rules`、`el-form-item` 的 `prop`。
4. 它只负责布局外壳，业务在 `TodoView.vue`；这样加页面时它不用改。
5. 请求失败时 `loading` 永远是 `true`，表格一直转圈。

</details>

## 九、常见错误

| 现象 | 原因 | 解决 |
|---|---|---|
| 页面白屏 | `main.js` 报错、忘装 router，或 Nginx 的 `root` 路径不对 | 先看浏览器控制台，再看 06 章 |
| 界面不更新 | 数据没用 `ref`/`reactive` 包 | 改用响应式 |
| `count` 一直是 0 | 脚本里忘了 `.value` | `count.value++` |
| 组件标签不渲染 | 忘了 `app.use(ElementPlus)` | 检查 `main.js` |
| 列表错位 / 闪烁 | `v-for` 没写 `:key` | `:key="item.id"` |
| 点按钮没反应 | 写成了 `@click="handleSearch()"` | 用 `@click="handleSearch"` |
| `Cannot read property 'value' of null` | `formRef` 在弹窗没打开时是 null | 用 `?` 可选链 |
| 日期传后端报错 | 漏了 `value-format` | 见 04 章 |
| 改了代码页面没变 | dev 服务器没起来 / 改的是配置文件 | 重启 `npm run dev` |
