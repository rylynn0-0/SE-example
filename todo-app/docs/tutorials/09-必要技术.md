# 09 · 必要技术：接口文档、反向代理与一键部署

> 一句话：前面几章让项目**能开发**，这一章让它**能给别人看、能一条命令跑起来**。

> 部署文件（Dockerfile / nginx.conf / compose）的完整模板与语法见本文 §五。

---

## 本章你会

- 用 Knife4j 在线调接口，不用写 Postman 集合
- 看懂 Nginx 的两个职责：托管静态文件、转发 `/api`
- 用 Docker Compose 一条命令起四个容器
- 会排查 404 / 502 / 白屏 / 连不上

## 一、为什么还需要这些

| 阶段 | 你缺什么 | 用什么补 |
|---|---|---|
| 开发时 | 前端要知道后端有哪些接口、参数怎么传 | **Knife4j**：注解自动生成在线文档 |
| 部署时 | 浏览器要访问页面，又要访问接口，最好同一个地址 | **Nginx**：静态托管 + 反向代理 |
| 交付时 | 「在我电脑上能跑」，换台机器环境不对 | **Docker**：把环境和程序一起打包 |

三者的共同点：**它们不写业务逻辑，但决定了项目能不能被使用。**

## 二、Knife4j：代码即文档

### 2.1 它解决什么问题

| 方案 | 问题 |
|---|---|
| 手写 Word / Markdown | 代码一改就过期，没人维护 |
| Postman 集合 | 要手动同步，还是两份 |
| **Knife4j** | **从代码注解自动生成，代码就是文档** |

它不是独立的东西，而是一条链的末端：

```
代码注解 ──springdoc 扫描──▶ OpenAPI 3 JSON ──Knife4j 渲染──▶ /doc.html 网页
                              (/v3/api-docs)
```

### 2.2 依赖与配置

`pom.xml`：

```xml
<dependency>
    <groupId>com.github.xiaoymin</groupId>
    <artifactId>knife4j-openapi3-jakarta-spring-boot-starter</artifactId>
    <version>4.5.0</version>
</dependency>
```

> `jakarta` 后缀 = 适配 Spring Boot 3。Boot 2 要用不带 `jakarta` 的 3.x 版本。

`application.yml`：

```yaml
springdoc:
  api-docs:
    enabled: true
    path: /v3/api-docs
knife4j:
  enable: true
  setting:
    language: zh_cn
```

### 2.3 注解怎么写

```java
@Tag(name = "待办任务", description = "任务的增删改查")   // 分组名
public class TaskController {

    @Operation(summary = "分页查询任务")                 // 接口标题
    public Result<IPage<Task>> page(TaskQuery query) { ... }

    @Operation(summary = "切换完成状态")
    public Result<Task> toggle(
            @Parameter(description = "任务 ID", example = "1") @PathVariable Long id) { ... }
}
```

字段说明写在实体/DTO 上：

```java
@Schema(description = "任务标题", example = "完成开题报告")
private String title;
```

**关键认知**：这些注解**只影响文档，不影响运行**。全删了接口照样工作。

### 2.4 访问入口

| 环境 | 地址 | 谁在转发 |
|---|---|---|
| 后端直连 | `http://localhost:8080/doc.html` | 无 |
| Docker 前端 | `http://localhost:8081/doc.html` | Nginx |
| 前端 dev | `http://localhost:5173/doc.html` | Vite proxy |

### 2.5 文档页为什么需要「一堆」代理

`/doc.html` 不是一个文件，它会加载：

```
doc.html
  ├── /webjars/...        ← 界面的 JS / CSS
  ├── /v3/api-docs        ← 接口规范 JSON
  └── /swagger-resources  ← 分组信息
```

**只代理 `doc.html` 是不够的** —— 页面能打开，但一片空白或一直转圈，因为资源 404。

本项目两处都配全了：

```js
// vite.config.js
proxy: {
  '/api':         { target: BACKEND, changeOrigin: true },
  '/doc.html':    { target: BACKEND, changeOrigin: true },
  '/webjars':     { target: BACKEND, changeOrigin: true },
  '/v3/api-docs': { target: BACKEND, changeOrigin: true },
  '/swagger-ui':  { target: BACKEND, changeOrigin: true }
}
```
```nginx
# nginx.conf
location ~ ^/(doc\.html|webjars/|v3/api-docs|swagger-ui|swagger-resources) {
    proxy_pass http://backend:8080;
}
```

**排查口诀**：文档出问题，先单独访问 `/v3/api-docs`。
有 JSON → 后端没问题，是前端资源没代理到；没有 JSON → 依赖版本或扫描问题。

## 三、Nginx：静态托管 + 反向代理

### 3.1 它干两件事

```
浏览器
  │
  ├── GET /            → ① 托管：把 dist/ 里的 index.html、JS、CSS 发回去
  │
  └── GET /api/tasks   → ② 反代：转发给 http://backend:8080/api/tasks
```

为什么要 ②？因为浏览器不能直接访问 `backend:8080`（那是容器内网的名字），
需要一个对外的统一入口（8081）来做转发。

### 3.2 配置逐段读（`frontend/nginx.conf`）

```nginx
server {
    listen 80;
    root /usr/share/nginx/html;

    # ① 静态托管 + 单页应用回退
    location / {
        try_files $uri $uri/ /index.html;
    }

    # ② 业务接口
    location ^~ /api/ {
        proxy_pass http://backend:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    # ③ 接口文档
    location ~ ^/(doc\.html|webjars/|v3/api-docs|swagger-ui|swagger-resources) {
        proxy_pass http://backend:8080;
    }

    # ④ 压缩与缓存
    gzip on;
    gzip_types text/css application/javascript application/json;

    location ~* \.(js|css|png|jpg|svg|woff2?)$ {
        expires 7d;
        add_header Cache-Control "public, max-age=604800";
    }
}
```

### 3.3 三个必须懂的语法

**① `location` 的匹配优先级**

```
= 精确  >  ^~ 前缀  >  正则 ~ / ~*  >  普通前缀（最长匹配）
```

`/api/` 用 `^~`，是为了命中后**不再尝试下面的正则**，防止 `/api/...` 被文档那条正则抢走。

**② `proxy_pass` 带不带 URI 的区别**

```nginx
proxy_pass http://backend:8080;     # 不带 URI：原样透传 /api/tasks
proxy_pass http://backend:8080/;    # 带 /：把 /api/ 替换掉 → /tasks
```

本项目**不带** URI，所以后端必须真的是 `/api/tasks`，和 `@RequestMapping("/api/tasks")` 对齐。
写成带 `/` 的形式，`/api` 前缀就被吃掉了，后端 404。

**③ `try_files`**

```nginx
try_files $uri $uri/ /index.html;
```

找不到同名文件就回退 `index.html`。
这是前端 history 路由能**刷新**的唯一原因（不配就是刷新 404）。

### 3.4 它和 Vite 代理是什么关系

```
开发：浏览器 → Vite 5173  ──proxy──▶ localhost:8080
部署：浏览器 → Nginx 8081 ──proxy──▶ backend:8080
```

**同样的职责，两套实现。** 所以前端代码里只写 `/api`，两边都不用改。
代价是：改代理规则要改两个地方，漏一个就会出现「本地正常、Docker 404」。

## 四、Docker：把环境一起打包

### 4.1 三个词

| 词 | 含义 | 类比 |
|---|---|---|
| 镜像 image | 只读的打包文件 | 安装光盘 |
| 容器 container | 镜像跑起来的实例 | 装好的程序 |
| 仓库 registry | 存放镜像的地方 | 应用商店 |

一个镜像可以跑出多个容器，容器里的修改默认不影响镜像。

### 4.2 分层与缓存

Dockerfile 每条指令产生一层只读层，层可以被复用：

```dockerfile
FROM maven:3.9-eclipse-temurin-17 AS build
COPY pom.xml .                    # 层 1：依赖清单
RUN mvn dependency:go-offline     # 层 2：下载依赖（最慢，但会缓存）
COPY src ./src                    # 层 3：源码
RUN mvn package                   # 层 4：编译
```

**规则**：某一层变了，它和它之后的所有层都要重建。

所以本项目把 `COPY pom.xml` 和 `COPY src` 分成两步：只改 Java 代码时，依赖那层命中缓存，不用重新下载。

> 本项目实际还多拷了一个 `settings.xml`（阿里云镜像），并用 `mvn -s settings.xml` 指定它 ——
> 容器里没有 `~/.m2/settings.xml`，不显式指定就会去 Maven Central 慢慢下。

### 4.3 多阶段构建

```dockerfile
# 阶段 1：编译（有 Maven、JDK、源码）
FROM maven:3.9-eclipse-temurin-17 AS build
...
# 阶段 2：运行（只要 JDK 和 jar）
FROM eclipse-temurin:17-jre
COPY --from=build /app/target/*.jar app.jar
```

最终镜像里**不包含** Maven 和源码。前端同理：`node:22-alpine` 打包，`nginx:alpine` 托管。

### 4.4 Compose：四个容器

```yaml
# 简化示意（完整版见 docker-compose.yml，含环境变量、健康检查、数据卷）
services:
  mysql:
    image: mysql:8.0
    ports: ["3306:3306"]
  redis:
    image: redis:7-alpine
    ports: ["6379:6379"]
  backend:
    build: ./backend
    ports: ["8080:8080"]
  frontend:
    build: ./frontend
    ports: ["8081:80"]
```

四条关键配置：

**① 网络与服务名**

```yaml
networks:
  todo-net:
    driver: bridge
```

同一网络里，容器可以**用服务名互相访问**：`mysql:3306`、`redis:6379`、`backend:8080`。
这就是 `application.yml` 默认写 `localhost`、容器里却要注入 `mysql` 的原因。

**② 数据卷**

```yaml
volumes:
  - mysql-data:/var/lib/mysql
```

容器删了数据不丢。`docker compose down` 保留卷，`down -v` 才删除。

**③ 健康检查 + 启动顺序**

```yaml
healthcheck:
  test: ["CMD", "mysqladmin", "ping", "-h", "127.0.0.1", "-utodo", "-ptodo123456"]
  interval: 5s
  retries: 30
  start_period: 25s

depends_on:
  mysql:
    condition: service_healthy
```

`depends_on` 只写服务名只能保证**启动顺序**，不能保证**就绪**。
MySQL 进程起来要几秒，初始化完成能接受连接要 20～40 秒 —— 不等就会 `Communications link failure`。

**④ 端口映射**

```yaml
ports:
  - "8081:80"     # 宿主机 8081 → 容器 80
```

左边是你的机器，右边是容器内。容器之间通信**不用映射**，只有浏览器/客户端要访问的才映射。

### 4.5 `init.sql` 只执行一次

```yaml
volumes:
  - ./backend/src/main/resources/db/init.sql:/docker-entrypoint-initdb.d/init.sql:ro
```

MySQL 官方镜像的行为：**只在数据目录为空时**执行初始化脚本。

| 操作 | 会执行吗 |
|---|---|
| 首次 `up` | ✅ |
| 再次 `up` | ❌ 卷已存在 |
| `down` 后 `up` | ❌ |
| `down -v` 后 `up` | ✅ |

## 五、部署文件模板（可直接抄）

前面 §三、§四 讲的是原理，这一节给**完整可抄**的四份文件。每份后面跟「语法点」，告诉你每一行为什么这么写。

### 5.1 `backend/Dockerfile`

```dockerfile
FROM maven:3.9-eclipse-temurin-17 AS build
WORKDIR /app
COPY pom.xml .
COPY settings.xml .
RUN mvn -B -q -s settings.xml dependency:go-offline
COPY src ./src
RUN mvn -B -q -s settings.xml clean package -DskipTests

FROM eclipse-temurin:17-jre
WORKDIR /app
COPY --from=build /app/target/*.jar app.jar
EXPOSE 8080
ENV TZ=Asia/Shanghai
ENTRYPOINT ["java", "-jar", "/app/app.jar"]
```

**语法点**：

| 指令 | 含义 |
|---|---|
| `FROM ... AS build` | 给这个阶段起名，后面能引用 |
| `WORKDIR /app` | 相当于 `cd`，之后所有命令都在这里执行 |
| `COPY pom.xml .` | 把宿主机文件复制进镜像；`.` 表示当前 WORKDIR |
| `RUN ...` | 构建时执行一条命令 |
| `FROM eclipse-temurin:17-jre` | 第二个阶段的新起点（前面阶段不会进最终镜像） |
| `COPY --from=build ...` | 从名为 build 的阶段取文件 |
| `ENTRYPOINT [...]` | 容器启动时执行的命令，JSON 数组形式 |


**拆开看（两个阶段各管什么）**：

| 阶段 | 指令 | 作用 |
|---|---|---|
| 构建 | `FROM maven:3.9-eclipse-temurin-17 AS build` | 带 Maven + JDK 的构建环境 |
| 构建 | `WORKDIR /app` | 后续命令的工作目录 |
| 构建 | `COPY pom.xml .` / `COPY settings.xml .` | 先拷依赖清单，利用层缓存 |
| 构建 | `RUN mvn ... dependency:go-offline` | 预下载依赖（最慢的一层） |
| 构建 | `COPY src ./src` | 再拷源码 |
| 构建 | `RUN mvn ... clean package -DskipTests` | 编译出 jar |
| 运行 | `FROM eclipse-temurin:17-jre` | 全新的运行环境，不含 Maven |
| 运行 | `COPY --from=build /app/target/*.jar app.jar` | 只搬产物 |
| 运行 | `EXPOSE 8080` / `ENV TZ` / `ENTRYPOINT` | 端口、时区、启动命令 |

### 5.2 `frontend/Dockerfile`

```dockerfile
FROM node:22-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci --no-audit --no-fund
COPY . .
RUN npm run build

FROM nginx:alpine
RUN rm -f /etc/nginx/conf.d/default.conf
COPY nginx.conf /etc/nginx/conf.d/default.conf
COPY --from=build /app/dist /usr/share/nginx/html
EXPOSE 80
```

**语法点**：

| 写法 | 含义 |
|---|---|
| `package*.json` | 通配符：`package.json` 和 `package-lock.json` 都拷 |
| `npm ci` | 严格按 lock 文件安装，可复现；要求存在 `package-lock.json` |
| `COPY . .` | 把构建上下文全部拷进来 |
| `COPY --from=build /app/dist ...` | 只搬构建产物，不搬 node_modules |

> 前提：后端模板里的 `settings.xml` 是 Maven 阿里云镜像，没有就删掉 `COPY settings.xml` 和 `-s settings.xml`；
> 前端模板用了 `npm ci`，没有 lock 文件就换成 `npm install`。


**拆开看**：

| 阶段 | 指令 | 作用 |
|---|---|---|
| 构建 | `FROM node:22-alpine AS build` | Node 构建环境 |
| 构建 | `COPY package*.json ./` + `RUN npm ci` | 先装依赖（利用缓存） |
| 构建 | `COPY . .` + `RUN npm run build` | 打包出 `dist/` |
| 运行 | `FROM nginx:alpine` | 运行环境只有 Nginx |
| 运行 | `RUN rm -f .../default.conf` + `COPY nginx.conf ...` | 替换默认站点配置 |
| 运行 | `COPY --from=build /app/dist ...` | 只搬静态产物 |

### 5.3 `frontend/nginx.conf`

```nginx
server {
    listen 80;
    root /usr/share/nginx/html;
    index index.html;

    gzip on;
    gzip_types text/css application/javascript application/json;

    location ^~ /api/ {
        proxy_pass http://backend:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    location ~ ^/(doc\.html|webjars/|v3/api-docs|swagger-ui|swagger-resources) {
        proxy_pass http://backend:8080;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }

    location ~* \.(js|css|png|jpg|jpeg|gif|svg|woff2?)$ {
        expires 7d;
        add_header Cache-Control "public, max-age=604800";
    }
}
```

**语法点**：

| 写法 | 含义 |
|---|---|
| `server { ... }` | 一个虚拟主机，块内是它的配置 |
| `location ^~ /api/` | 前缀匹配，命中后不再尝试正则 |
| `location ~ 正则` | 正则匹配（区分大小写）；`~*` 不区分 |
| `proxy_pass http://backend:8080;` | 把请求原样转发（不带 URI 就保留完整路径） |
| `try_files $uri $uri/ /index.html;` | 依次找文件 → 目录 → 回退 index.html |
| `expires 7d;` | 浏览器缓存 7 天 |


**拆开看（每个 location 管什么）**：

| 配置块 | 匹配什么 | 作用 |
|---|---|---|
| `listen 80` / `root` | 整个 server | 监听端口、静态根目录 |
| `location ^~ /api/` | 以 `/api/` 开头 | 转发给后端，原样透传路径 |
| `location ~ ^/(doc\.html\|webjars/...)` | 文档相关路径 | 转发 Knife4j 资源 |
| `location /` | 其它所有 | `try_files` 回退到 `index.html` |
| `location ~* \.(js\|css\|...)$` | 静态资源后缀 | 浏览器缓存 7 天 |
| `gzip ...` | 全部响应 | 压缩文本，减小体积 |

### 5.4 `docker-compose.yml`

```yaml
name: todo-app

services:
  mysql:
    image: mysql:8.0
    container_name: todo-mysql
    environment:
      MYSQL_ROOT_PASSWORD: root123456
      MYSQL_DATABASE: todo_db
      MYSQL_USER: todo
      MYSQL_PASSWORD: todo123456
      TZ: Asia/Shanghai
      LANG: C.UTF-8
    ports:
      - "3306:3306"
    command:
      - --character-set-server=utf8mb4
      - --collation-server=utf8mb4_general_ci
      - --default-time-zone=+08:00
    volumes:
      - mysql-data:/var/lib/mysql
      - ./backend/src/main/resources/db/init.sql:/docker-entrypoint-initdb.d/init.sql:ro
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "127.0.0.1", "-utodo", "-ptodo123456"]
      interval: 5s
      timeout: 5s
      retries: 30
      start_period: 25s
    networks: [todo-net]

  redis:
    image: redis:7-alpine
    container_name: todo-redis
    command: ["redis-server", "--appendonly", "yes"]
    ports:
      - "6379:6379"
    volumes:
      - redis-data:/data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      retries: 10
    networks: [todo-net]

  backend:
    build: ./backend
    container_name: todo-backend
    environment:
      MYSQL_HOST: mysql
      MYSQL_PORT: "3306"
      MYSQL_DB: todo_db
      MYSQL_USER: todo
      MYSQL_PASSWORD: todo123456
      REDIS_HOST: redis
      REDIS_PORT: "6379"
      TZ: Asia/Shanghai
    ports:
      - "8080:8080"
    depends_on:
      mysql:
        condition: service_healthy
      redis:
        condition: service_healthy
    networks: [todo-net]

  frontend:
    build: ./frontend
    container_name: todo-frontend
    ports:
      - "8081:80"
    depends_on: [backend]
    networks: [todo-net]

volumes:
  mysql-data:
  redis-data:

networks:
  todo-net:
    driver: bridge
```

**语法点**：

| 写法 | 含义 |
|---|---|
| `services:` 下面每项 | 一个容器 |
| `image:` / `build:` | 用现成镜像 / 用本地 Dockerfile 构建 |
| `ports: ["8080:8080"]` | 宿主机端口:容器端口 |
| `environment:` | 注入容器环境变量，名字要和 `application.yml` 占位符一致 |
| `volumes: - 卷名:/容器路径` | 命名卷（数据持久化） |
| `volumes: - ./宿主路径:/容器路径:ro` | 绑定挂载，`ro` 表示只读 |
| `depends_on` + `condition: service_healthy` | 等对方健康检查通过再启动 |
| `networks: [todo-net]` | 加入同一网络，可用服务名互访 |


**拆开看（每个 service 管什么）**：

| service | 关键字段 | 作用 |
|---|---|---|
| `mysql` | `image` / `environment` / `volumes` / `healthcheck` | 建库、账号、挂载初始化脚本、数据持久化 |
| `redis` | `image` / `command` / `volumes` | AOF 持久化、缓存 |
| `backend` | `build` / `environment` / `depends_on` | 编译镜像、注入数据库地址、等 MySQL 就绪 |
| `frontend` | `build` / `ports` | 打包静态页、暴露 8081 |

**四个记忆点**：

1. 服务名 = 容器互相访问的主机名（`mysql`、`redis`、`backend`）
2. 环境变量名 = `application.yml` 里的占位符名
3. `depends_on + condition: service_healthy` 才保证「就绪」，不只是「启动」
4. 数据卷 `down` 保留、`down -v` 删除

## 七、常见错误

| 现象 | 原因 | 解决 |
|---|---|---|
| `Temporary failure in name resolution` | 构建容器 DNS 不通 | 检查 `/etc/docker/daemon.json` 的 `dns` |
| 依赖下载极慢 | 走 Maven Central | 用 `backend/settings.xml` 镜像 |
| 端口被占用 | 宿主机端口有程序 | 改映射或 `ss -ltn` 排查 |
| 502 Bad Gateway | `backend` 没起来 / 服务名错 | `docker compose logs backend` |
| 页面 404 但 API 正常 | Nginx `root` 路径不对 | 检查 `COPY --from=build` 的目标 |
| 刷新页面 404 | history 模式缺回退 | `try_files $uri $uri/ /index.html` |
| 改了 init.sql 没生效 | 数据卷已存在 | `docker compose down -v` |
| 中文乱码 / 时间差 8 小时 | `TZ` 与时区不一致 | 容器加 `TZ=Asia/Shanghai` |
| `doc.html` 空白 | 没代理 `/webjars` | 补正则 location |

> 本项目首次构建时踩过一个 DNS 坑：`daemon.json` 里配的 DNS 不可达，导致所有容器（包括构建容器）
> 解析不了域名。错误看起来像代码问题，其实是 Docker 守护进程配置 —— 排查方法：
> 对比 `cat /etc/resolv.conf` 和 `docker run --rm alpine cat /etc/resolv.conf`。

## 八、自测：能不能答上来

1. `/v3/api-docs` 和 `/doc.html` 分别是什么、给谁用？
2. `proxy_pass http://backend:8080;` 末尾加 `/` 会怎样？
3. `try_files` 那一行不写，会出现什么现象？
4. 为什么 `depends_on` 要配 `condition: service_healthy`？
5. `docker compose down` 和 `down -v` 的区别？

<details>
<summary>参考答案</summary>

1. 前者是 OpenAPI 规范 JSON（给机器/工具），后者是可视化文档页（给人看和调试）。
2. `/api` 前缀会被替换掉，后端收到 `/tasks`，导致 404。
3. 前端路由一刷新就 404（服务器找不到 `/xxx` 这个文件）。
4. 只配服务名只保证启动顺序，不等 MySQL 初始化完成，后端会连不上库而退出。
5. 前者保留数据卷；后者连数据卷一起删，`init.sql` 会重新执行。

</details>
