## 一、链路总览

```
点「＋ 新增任务」
  → openCreate()：dialog.id=null，重置 form，打开弹窗
  → 用户填写 form
  → 点「保存」：handleSave()
  → 表单校验通过 → dialog.saving=true
  → createTask({ ...form })
  → axios：POST /api/tasks，JSON 请求体
  → Vite / Nginx 把 /api 转到 backend:8080
  → TaskController.create：标题校验
  → TaskServiceImpl.createTask：默认值 → INSERT → 清缓存 → 回查
  → Result.ok(Task) → JSON
  → 关弹窗 → loadAll()
  → 列表多一行、统计数字变化
```

## 二、打开弹窗：先把状态清干净

`TodoView.vue:179-185`：

```js
function openCreate() { // 点“＋ 新增任务”时执行
  dialog.id = null // null 表示“新增”；有 id 才是编辑
  Object.assign(form, { title: '', description: '', priority: 2, dueDate: null }) // 重置表单
  dialog.visible = true // 打开弹窗
  formRef.value?.clearValidate() // 清掉上次的红字校验提示
}
```

- **做什么**：重置表单、打开弹窗。
- **为什么**：弹窗是新增/编辑共用的；`dialog.id=null` 让保存时走新增分支，重置表单避免残留上次的数据。

`TodoView.vue:61`：

```js
const dialog = reactive({ visible: false, saving: false, id: null }) // 弹窗状态
```

- **做什么**：控制弹窗显隐、保存按钮 loading、当前编辑 id。
- **为什么**：`visible` 绑 `v-model` 控制弹窗；`saving` 防止连点；`id` 区分新增/编辑。

## 三、表单和校验

`TodoView.vue:67-72`：

```js
const form = reactive({ // 表单数据
  title: '',        // 标题，必填
  description: '',  // 备注，可空
  priority: 2,      // 优先级：1 低，2 中，3 高；默认中
  dueDate: null     // 截止日期，可空
})
```

- **做什么**：保存用户输入。
- **为什么**：`reactive` 让 `form.title` 变化时输入框同步，输入框变化时 `form.title` 也同步。

`TodoView.vue:75-80`：

```js
const rules = { // el-form 校验规则
  title: [
    { required: true, message: '请输入任务标题', trigger: 'blur' }, // 必填
    { max: 100, message: '标题不能超过 100 个字符', trigger: 'blur' } // 最长 100
  ]
}
```

- **做什么**：声明标题校验。
- **为什么**：前端校验让用户立刻看到错误，少发无效请求；但后端仍要校验，因为前端校验可以被绕过。

日期选择器：

```vue
<el-date-picker v-model="form.dueDate" type="date" value-format="YYYY-MM-DD" /> <!-- 输出字符串日期 -->
```

- **做什么**：把日期存成 `"2026-11-15"` 字符串。
- **为什么**：后端 `LocalDate` + `@JsonFormat(pattern="yyyy-MM-dd")` 认这个格式；不写 `value-format` 可能得到 Date 对象，JSON 序列化后格式对不上。

## 四、保存：先校验，再提交

`TodoView.vue:209-230`（新增分支节选）：

```js
async function handleSave() { // 点“保存”时执行
  const valid = await formRef.value.validate().catch(() => false) // 触发校验；失败转 false
  if (!valid) return // 校验不过，不发请求

  dialog.saving = true // 按钮转圈，防止连点
  try {
    await createTask({ ...form }) // 提交表单
    ElMessage.success('新增成功') // 成功提示
    dialog.visible = false        // 关闭弹窗
    await loadAll()               // 刷新列表和统计
  } finally {
    dialog.saving = false // 成功失败都停止转圈
  }
}
```

- **做什么**：校验 → 提交 → 关弹窗 → 刷新。
- **为什么**：
  - 校验不通过就 `return`，避免无效请求。
  - `saving=true` 防连点，否则会插入两条。
  - 成功后才关弹窗；失败时弹窗保留，用户不用重填。
  - `loadAll` 让页面以数据库为准，不自己拼新行。

`TodoView.vue:136-142`：

```js
async function loadAll() { // 同时刷新列表和统计
  try {
    await Promise.all([loadList(), loadStats()]) // 两个请求并行
  } catch (e) { // 错误提示已由拦截器统一弹出
  }
}
```

- **做什么**：并行请求列表和统计。
- **为什么**：写操作会改变这两个数据；并行比串行快，`Promise.all` 等两个都结束。

## 五、请求：axios 和代理

`api/task.js:40-42`：

```js
export function createTask(data) { // 新增接口封装
  return request.post('/tasks', data) // POST /api/tasks；data 是请求体
}
```

- **做什么**：把新增封装成一个函数。
- **为什么**：页面不用关心 URL 和 HTTP 方法；以后改路径只改这里。

`api/request.js:15-18`：

```js
const request = axios.create({ // 创建 axios 实例
  baseURL: '/api',              // 自动加 /api
  timeout: 10000                // 10 秒超时
})
```

- **做什么**：创建统一 HTTP 客户端。
- **为什么**：接口写相对路径，开发/Docker 换代理即可，代码不用改。

`api/request.js:42-59`（简化）：

```js
request.interceptors.response.use((response) => { // 响应先到这里
  const body = response.data // 后端 JSON
  if (body.code === 200) return body.data // 成功只返回 data
  ElMessage.error(body.message) // 失败弹提示
  return Promise.reject(new Error(body.message)) // 中断
})
```

- **做什么**：统一拆 `{ code, message, data }`。
- **为什么**：页面里直接拿 `data`，不用每次判断 `code`。

请求路径：

```text
createTask({ ...form })
  → request.post('/tasks', data)  // axios 方法
  → POST /api/tasks               // baseURL '/api' + '/tasks'
  → 浏览器发到 5173 / 8081
  → Vite / Nginx 匹配 /api
  → http://backend:8080/api/tasks
  → TaskController.create
```

- **做什么**：把 JSON 请求体送到后端。
- **为什么**：浏览器只访问前端端口，代理负责跨进程转发，避免跨域和写死地址。

## 六、后端 Controller：接 JSON 并校验

`TaskController.java:102-109`：

```java
@PostMapping // 处理 POST /api/tasks
public Result<Task> create(@RequestBody Task task) { // 请求体 JSON → Task 对象
    if (!StringUtils.hasText(task.getTitle())) { // null、空串、空格都算空
        return Result.fail(400, "任务标题不能为空"); // 业务失败，code=400
    }
    return Result.ok(taskService.createTask(task)); // 交给 Service
}
```

- **做什么**：反序列化 JSON，校验标题，调用 Service。
- **为什么**：
  - `@RequestBody` 让 Jackson 自动把 JSON 转成对象。
  - 后端必须再校验一次，不能只信前端。
  - `Result.fail` 返回业务错误，HTTP 仍是 200。

## 七、后端 Service：默认值 → 入库 → 清缓存 → 回查

`TaskServiceImpl.java:175-194`：

```java
@Transactional(rollbackFor = Exception.class) // 出异常回滚
public Task createTask(Task task) { // 返回新增后的任务
    if (task.getPriority() == null) task.setPriority(2); // 没传优先级，默认中
    if (task.getFinished() == null) task.setFinished(0); // 新任务默认未完成

    this.save(task); // INSERT，自增 id 回填到 task.id
    clearStatsCache(); // 统计变了，删 Redis 缓存
    return this.getById(task.getId()); // 再查一次，补齐数据库生成的时间
}
```

- **做什么**：补默认值、插入、清缓存、回查。
- **为什么**：
  - 默认值兜底，避免前端漏传导致排序/统计异常。
  - `@Transactional` 保证插入和后续操作要么都成功，要么都回滚。
  - 写操作必须清统计缓存，否则统计卡片最多 60 秒还是旧数字。
  - `save` 只回填 `id`，`create_time/update_time` 是数据库生成的，必须再查。

`TaskServiceImpl.java:290-298`：

```java
private void clearStatsCache() { // 删除统计缓存
    try {
        redisTemplate.delete(STATS_KEY); // DEL todo:stats
    } catch (Exception e) {
        log.warn("清除 Redis 缓存失败：{}", e.getMessage()); // 缓存失败不影响业务
    }
}
```

- **做什么**：删除 Redis 里的统计缓存。
- **为什么**：缓存只是加速层，Redis 挂了也不应该让新增失败；下次读统计会重新查数据库。

## 八、实体和 SQL：数据库怎么写

`Task.java:40-42`：

```java
@TableId(type = IdType.AUTO) // 主键由数据库自增
private Long id;
```

- **做什么**：声明主键策略。
- **为什么**：插入时不用自己生成 id，数据库生成后 MyBatis-Plus 会回填。

`Task.java:80-92`：

```java
@JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss") // JSON 时间格式
private LocalDateTime createTime; // 创建时间

@JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss")
private LocalDateTime updateTime; // 更新时间
```

- **做什么**：声明时间字段的 JSON 格式。
- **为什么**：数据库默认值生成时间，Java 对象插入时是 null；统一格式后前端好展示。

实际 SQL：

```sql
INSERT INTO t_task (title, description, priority, finished, due_date) -- 只写有值的列；没写的 create_time/update_time/deleted 用数据库默认值
VALUES (?, ?, ?, ?, ?); -- ? 是参数，不是拼接字符串
```

- **做什么**：插入一行任务。
- **为什么**：
  - 只写前端传了的字段，没传的用数据库默认值。
  - 用 `?` 占位符，防止 SQL 注入。
  - `id` 由 `AUTO_INCREMENT` 生成，插入后回填给 Java 对象。

## 九、返回和回显

`Result.java:42-59`：

```java
public static <T> Result<T> ok(T data) { // 成功响应
    Result<T> result = new Result<>();
    result.setCode(200);       // 业务成功
    result.setMessage("成功"); // 提示
    result.setData(data);      // 新增后的任务
    return result;
}
```

- **做什么**：包装统一响应。
- **为什么**：前端拦截器按 `code` 判断成败，页面直接拿 `data`。

响应（节选）：

```json
{
  "code": 200,
  "message": "成功",
  "data": {
    "id": 9,
    "title": "复习软件工程",
    "priority": 2,
    "finished": 0,
    "createTime": "2026-11-12 20:15:30"
  }
}
```

回显：

```js
dialog.visible = false // 关闭弹窗
await loadAll()        // 重新查列表和统计
```

- **做什么**：关闭弹窗，重新加载页面数据。
- **为什么**：新行该排在哪、统计变多少，交给数据库和查询逻辑决定，前端不自己猜。

## 十一、常见坑

| 现象 | 原因 |
|---|---|
| 保存没反应 | 表单校验没过，看标题下方红字 |
| `code=400` 但 HTTP 200 | 业务失败看 body 的 `code` |
| 新增后统计没变 | `clearStatsCache` 没执行，或 Redis 挂了 |
| 日期格式错 | 日期选择器没写 `value-format` |
