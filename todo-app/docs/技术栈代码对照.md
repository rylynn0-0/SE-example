## 1. Vue 3 —— 页面与状态

**职责**：把后端返回的 JSON 渲染成界面，并管理「加载中、当前页、表单、弹窗」等界面状态。

### 1.1 入口：创建应用并挂载（`frontend/src/main.js`）

```js
import { createApp } from 'vue'
import ElementPlus from 'element-plus'
import 'element-plus/dist/index.css'
import zhCn from 'element-plus/es/locale/lang/zh-cn'

import App from './App.vue'
import router from './router'
import './styles/global.css'

const app = createApp(App)

app.use(ElementPlus, { locale: zhCn })  // 注册 UI 组件库（中文）
app.use(router)                          // 注册路由
app.mount('#app')                        // 渲染到 index.html 的 <div id="app">
```

### 1.2 响应式状态（`frontend/src/views/TodoView.vue`）

```js
// 简单值用 ref，取值/赋值要加 .value
const loading = ref(false)
const list = ref([])
const total = ref(0)

// 对象用 reactive，可直接 query.pageNum = 2
const query = reactive({ pageNum: 1, pageSize: 5, keyword: '', finished: null })

// 统计卡片，字段与后端 TaskStats 一一对应
const stats = reactive({ total: 0, finished: 0, unfinished: 0, fromCache: false, ttl: 0 })
```

> **为什么区分 ref / reactive**：`ref` 适合基本类型与整体替换的场景；`reactive` 适合多字段对象且不会整体替换的场景。页面中 `list` 会被整体替换（`list.value = data.records`），所以用 `ref`；`query` 只改字段，所以用 `reactive`。

### 1.3 页面模板结构（`TodoView.vue`）

```
<el-row>            统计卡片区（总数 / 未完成 / 已完成）
<el-card>           主卡片
  ├─ .toolbar       搜索框 + 状态筛选 + 查询按钮 + 缓存状态标签 + 新增按钮
  ├─ <el-table>     表格：ID / 标题 / 优先级 / 截止日期 / 状态开关 / 更新时间 / 操作
  └─ <el-pagination> 分页
<el-dialog>         新增 / 编辑共用弹窗（含 el-form 校验）
```

## 3. Vite —— 开发服务器与构建

**职责**：开发时提供热更新与接口代理；构建时把 Vue 源码编译成纯静态文件。

### 3.1 接口代理（`frontend/vite.config.js`）

```js
const BACKEND = 'http://localhost:8080'

export default defineConfig({
  plugins: [vue()],
  server: {
    host: '0.0.0.0',
    port: 5173,
    proxy: {
      '/api':        { target: BACKEND, changeOrigin: true },  // 业务接口
      '/doc.html':   { target: BACKEND, changeOrigin: true },  // Knife4j 页面
      '/webjars':    { target: BACKEND, changeOrigin: true },  // 文档静态资源
      '/v3/api-docs':{ target: BACKEND, changeOrigin: true },  // OpenAPI JSON
    }
  },
  build: { outDir: 'dist', sourcemap: false }
})
```

> **这一层解决了跨域**：浏览器只请求 5173，Vite 在服务端转发到 8080，浏览器看不到「端口不同」。因此前端代码里统一写 `/api/tasks` 这样的相对路径，Docker 环境换成 Nginx 转发也无需改代码。

### 3.2 构建产物

```bash
npm run build   # 输出 frontend/dist/（index.html + assets/*.js + *.css）
```

Node 到此就不再参与运行 —— 这也是 `frontend/Dockerfile` 第二阶段能换成 Nginx 的原因。

## 4. Axios —— 请求封装

**职责**：统一 baseURL、超时、错误提示，并把后端 `{code,message,data}` 外壳拆掉。

### 4.1 实例与响应拦截器（`frontend/src/api/request.js`）

```js
const request = axios.create({
  baseURL: '/api',   // 所以 request.get('/tasks') 实际请求 /api/tasks
  timeout: 10000
})

request.interceptors.response.use(
  (response) => {
    const body = response.data

    // 非统一格式（如静态资源）原样返回
    if (body === null || typeof body !== 'object' || body.code === undefined) return body

    // 业务成功：只把 data 交给调用方，页面不用写 res.data.data
    if (body.code === 200) return body.data

    // 业务失败：弹提示并中断调用链
    ElMessage.error(body.message || '请求失败')
    return Promise.reject(new Error(body.message || '请求失败'))
  },
  (error) => {
    const message = error.response?.data?.message || '网络异常，请确认后端服务已启动（默认 8080 端口）'
    ElMessage.error(message)
    return Promise.reject(error)
  }
)
```

### 4.2 接口方法封装（`frontend/src/api/task.js`）

```js
export const pageTasks  = (params)   => request.get('/tasks', { params })
export const createTask = (data)     => request.post('/tasks', data)
export const updateTask = (id, data) => request.put(`/tasks/${id}`, data)
export const toggleTask = (id)       => request.patch(`/tasks/${id}/finished`)
export const deleteTask = (id)       => request.delete(`/tasks/${id}`)
export const getStats   = ()         => request.get('/tasks/stats')
```

> 页面只调用这些方法，不关心 URL 与 HTTP 方法；后端改路径时只改这一个文件。

## 5. Spring Boot —— 分层与 REST

**职责**：内嵌 Tomcat 承载 HTTP 请求，靠注解完成依赖注入与路由映射。

### 5.1 启动类（`backend/.../TodoApplication.java`）

```java

@MapperScan("com.example.todo.mapper")   // 为 Mapper 接口生成动态代理
public class TodoApplication {
    public static void main(String[] args) {

    }
}
```

### 5.2 分层组织

```
Controller  ← 收参数 / 基础校验 / 包装 Result
    ↓ 注入
Service     ← 业务规则 + 事务 + 缓存失效
    ↓ 注入
Mapper      ← 只与数据库交互（BaseMapper 提供实现）
    ↓
Entity      ← 表映射
```

### 5.3 统一响应体（`backend/.../common/Result.java`）

```java
@Data
public class Result<T> {
    private Integer code;
    private String message;
    private T data;

    public static <T> Result<T> ok() { return ok(null); }

    public static <T> Result<T> ok(T data) {
        Result<T> result = new Result<>();
        result.setCode(200);
        result.setMessage("成功");
        result.setData(data);
        return result;
    }

    public static <T> Result<T> fail(Integer code, String message) {
        Result<T> result = new Result<>();
        result.setCode(code);
        result.setMessage(message);
        return result;
    }
}
```

### 5.4 控制器（`backend/.../controller/TaskController.java`）

```java
@RestController
@RequestMapping("/api/tasks")
@RequiredArgsConstructor          // Lombok：为 final 字段生成构造器 → 构造器注入
@Tag(name = "待办任务", description = "任务的增删改查、分页搜索与统计")
public class TaskController {

    private final TaskService taskService;

    @GetMapping
    @Operation(summary = "分页查询任务")
    public Result<IPage<Task>> page(TaskQuery query) {     // 对象参数：Spring 按字段名绑定 URL 参数
        return Result.ok(taskService.pageTasks(query));
    }

    @PostMapping
    @Operation(summary = "新增任务")
    public Result<Task> create(@RequestBody Task task) {   // @RequestBody：JSON → 对象
        if (!StringUtils.hasText(task.getTitle())) {
            return Result.fail(400, "任务标题不能为空");
        }
        return Result.ok(taskService.createTask(task));
    }

    @PatchMapping("/{id}/finished")
    @Operation(summary = "切换完成状态")
    public Result<Task> toggle(@PathVariable Long id) {
        Task task = taskService.toggleFinished(id);
        if (task == null) return Result.fail(404, "任务不存在");
        return Result.ok(task);
    }
}
```

> **RESTful 约定**：URL 表示资源（`/api/tasks`、`/api/tasks/{id}`），HTTP 方法表示动作（GET 查、POST 增、PUT 改、DELETE 删、PATCH 局部改）。接口路径里不出现动词。

### 5.5 配置外置（`backend/src/main/resources/application.yml`）

```yaml
spring:
  datasource:
    url: jdbc:mysql://${MYSQL_HOST:localhost}:${MYSQL_PORT:3306}/${MYSQL_DB:todo_db}?...
    username: ${MYSQL_USER:todo}
    password: ${MYSQL_PASSWORD:todo123456}
  data:
    redis:
      host: ${REDIS_HOST:localhost}
      port: ${REDIS_PORT:6379}
```

`${XXX:默认值}` = 「优先读环境变量 XXX，读不到用默认值」。同一份 jar 包，本地读 `localhost`，容器里读注入的 `mysql`/`redis`，**代码零改动**。

## 6. MyBatis-Plus —— ORM 三件套

**职责**：把实体映射成表，用条件构造器拼 SQL，并接管分页与逻辑删除。

### 6.1 实体映射（`backend/.../entity/Task.java`）

```java
@Data
@TableName("t_task")
public class Task {

    @TableId(type = IdType.AUTO)      // 主键由 MySQL 自增
    private Long id;

    private String title;

    @TableField(updateStrategy = FieldStrategy.ALWAYS)  // 允许被清空（否则 null 被忽略）
    private String description;

    private Integer priority;
    private Integer finished;

    @TableField(updateStrategy = FieldStrategy.ALWAYS)
    @JsonFormat(pattern = "yyyy-MM-dd")
    private LocalDate dueDate;

    @JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss")
    private LocalDateTime createTime;   // 由数据库 DEFAULT CURRENT_TIMESTAMP 填充

    @JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss")
    private LocalDateTime updateTime;   // 由数据库 ON UPDATE 维护

    @TableLogic              // 逻辑删除：查询自动加 deleted=0
    @JsonIgnore              // 不出现在接口响应中
    private Integer deleted;
}
```

### 6.2 Mapper：零 SQL 拿 CRUD（`backend/.../mapper/TaskMapper.java`）

```java
@Mapper
public interface TaskMapper extends BaseMapper<Task> {
    // 无需任何方法：insert / deleteById / updateById / selectById /
    // selectList / selectPage / selectCount 等 17 个方法由 BaseMapper 提供
}
```

### 6.3 分页拦截器（`backend/.../config/MybatisPlusConfig.java`）

```java
@Configuration
public class MybatisPlusConfig {
    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        interceptor.addInnerInterceptor(new PaginationInnerInterceptor(DbType.MYSQL));
        return interceptor;
    }
}
```

> **不注册这个拦截器，`page()` 会退化成查全表**，分页参数完全失效 —— 这是 MyBatis-Plus 最常见的坑。

### 6.4 条件构造器（`backend/.../service/impl/TaskServiceImpl.java`）

```java
@Override
public IPage<Task> pageTasks(TaskQuery query) {
    Page<Task> page = new Page<>(query.getPageNum(), query.getPageSize());

    LambdaQueryWrapper<Task> wrapper = new LambdaQueryWrapper<Task>()
            .like(StringUtils.hasText(query.getKeyword()), Task::getTitle, query.getKeyword())
            .eq(query.getFinished() != null, Task::getFinished, query.getFinished())
            .orderByAsc(Task::getFinished)     // 未完成优先
            .orderByDesc(Task::getPriority)    // 优先级高的优先
            .orderByDesc(Task::getId);         // 新建的优先

    return this.page(page, wrapper);
}
```

两个设计点：

- `Task::getTitle` 是方法引用，字段名写错**编译期**就报错，而不是运行期；
- 每个条件的第一个布尔参数是开关，为 `false` 时该条件不拼接 SQL，省掉一堆 `if-else`。

### 6.5 逻辑删除生效后的实际 SQL

| 调用 | 实际执行的 SQL |
|---|---|
| `this.page(page, wrapper)` | `SELECT ... FROM t_task WHERE deleted=0 AND (title LIKE ?) ORDER BY ... LIMIT 0,5` |
| `this.getById(id)` | `SELECT ... FROM t_task WHERE id=? AND deleted=0` |
| `this.removeById(id)` | `UPDATE t_task SET deleted=1 WHERE id=? AND deleted=0` |
| `this.count()` | `SELECT COUNT(*) FROM t_task WHERE deleted=0` |

## 8. MySQL —— 表结构与初始化

**职责**：唯一的数据权威来源（Redis 只是缓存）。

### 8.1 建表（`backend/src/main/resources/db/init.sql`）

```sql
CREATE DATABASE IF NOT EXISTS todo_db
    DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
USE todo_db;

CREATE TABLE t_task
(
    id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键 ID',
    title       VARCHAR(100)    NOT NULL COMMENT '任务标题',
    description VARCHAR(500)             DEFAULT NULL COMMENT '任务备注',
    priority    TINYINT         NOT NULL DEFAULT 1 COMMENT '优先级：1低 2中 3高',
    finished    TINYINT         NOT NULL DEFAULT 0 COMMENT '完成状态：0未完成 1已完成',
    due_date    DATE                     DEFAULT NULL COMMENT '截止日期',
    create_time DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    update_time DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP
                                 ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
    deleted     TINYINT         NOT NULL DEFAULT 0 COMMENT '逻辑删除：0未删除 1已删除',
    PRIMARY KEY (id),
    KEY idx_finished (finished),
    KEY idx_title (title)
) ENGINE = InnoDB DEFAULT CHARSET = utf8mb4 COLLATE = utf8mb4_general_ci COMMENT ='待办任务表';
```

三个设计点：

1. **时间由数据库维护**：`DEFAULT CURRENT_TIMESTAMP` 与 `ON UPDATE CURRENT_TIMESTAMP`。插入时 Java 侧字段留 null，MyBatis-Plus 不拼接该列，数据库自动填值 —— 业务代码不用手写时间。
2. **索引**：`finished` 服务于状态筛选与排序，`title` 服务于关键词搜索。
3. **逻辑删除**：`deleted` 配合 `@TableLogic`，删除不物理删数据，可追溯。

### 8.2 初始化时机

```yaml
# docker-compose.yml
volumes:
  - ./backend/src/main/resources/db/init.sql:/docker-entrypoint-initdb.d/init.sql:ro
```

MySQL 官方镜像会在**数据目录为空（首次启动）**时自动执行该目录下的 `*.sql`。所以改脚本后需要 `docker compose down -v` 才会重新执行。

### 8.3 连接配置

```yaml
url: jdbc:mysql://${MYSQL_HOST:localhost}:${MYSQL_PORT:3306}/${MYSQL_DB:todo_db}
     ?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
     &useSSL=false&allowPublicKeyRetrieval=true
```

`serverTimezone=Asia/Shanghai` 与容器 `TZ=Asia/Shanghai` 保持一致，避免时间差 8 小时。

## 9. Redis —— Cache-Aside 缓存

**职责**：挡住高频的统计查询，避免每次都做两次 `COUNT(*)`。

### 9.1 读：先缓存后数据库（`TaskServiceImpl.stats()`）

```java
@Override
public TaskStats stats() {
    // ---------- 第 1 步：尝试读缓存 ----------
    try {
        String cachedJson = redisTemplate.opsForValue().get(STATS_KEY);
        if (cachedJson != null) {
            TaskStats cached = objectMapper.readValue(cachedJson, TaskStats.class);
            Long ttl = redisTemplate.getExpire(STATS_KEY, TimeUnit.SECONDS);
            cached.setFromCache(true);
            cached.setTtl(ttl == null ? 0L : ttl);
            return cached;                       // 命中：直接返回，不碰数据库
        }
    } catch (Exception e) {
        log.warn("读取 Redis 失败，降级查询数据库：{}", e.getMessage());
    }

    // ---------- 第 2 步：未命中，查数据库 ----------
    long total = this.count();
    long finished = this.count(new LambdaQueryWrapper<Task>().eq(Task::getFinished, 1));

    TaskStats stats = new TaskStats();
    stats.setTotal(total);
    stats.setFinished(finished);
    stats.setUnfinished(total - finished);
    stats.setFromCache(false);
    stats.setTtl(STATS_TTL_SECONDS);

    // ---------- 第 3 步：写回缓存，60 秒过期 ----------
    try {
        String json = objectMapper.writeValueAsString(stats);
        redisTemplate.opsForValue().set(STATS_KEY, json, STATS_TTL_SECONDS, TimeUnit.SECONDS);
    } catch (Exception e) {
        log.warn("写入 Redis 失败（不影响本次返回）：{}", e.getMessage());
    }
    return stats;
}
```

### 9.2 写：改库后立刻删缓存（`clearStatsCache()`）

```java
private void clearStatsCache() {
    try {
        redisTemplate.delete(STATS_KEY);       // todo:stats
    } catch (Exception e) {
        log.warn("清除 Redis 缓存失败：{}", e.getMessage());
    }
}
```

调用点（`createTask` / `updateTask` / `removeTask` / `toggleFinished` 四个写方法末尾各一次）：

```java
this.save(task);
clearStatsCache();      // 统计数字变了 → 让缓存失效 → 下次读自然回源
```

### 9.3 三个关键设计决策

| 决策 | 原因 |
|---|---|
| **删缓存而不是更新缓存** | 并发写时「更新缓存」容易出现旧值覆盖新值；「删除」强制下次回源，更稳 |
| **Redis 操作全部 try/catch** | 缓存是加速层不是数据源。Redis 挂了应降级查库，而不是让接口 500 |
| **返回 `fromCache` 与 `ttl`** | 让缓存命可在界面上被看见，便于演示与排查 |

### 9.4 已知简化（生产需改进）

缓存是在**事务提交前**删除的。极端并发下可能出现：删缓存 → 事务未提交 → 另一请求读到旧值并写回缓存。生产做法是用 `TransactionSynchronizationManager` 注册 `afterCommit` 回调，在事务真正提交后再删。代码注释中已标注。

## 10. Docker —— 镜像与编排

**职责**：把「应用 + 运行环境」一起打包，四容器一键起。

### 10.1 后端多阶段构建（`backend/Dockerfile`）

```dockerfile
# 阶段 1：编译
FROM maven:3.9-eclipse-temurin-17 AS build
WORKDIR /app
COPY pom.xml .
COPY settings.xml .
RUN mvn -B -q -s settings.xml dependency:go-offline   # 依赖层：pom 不变则复用缓存
COPY src ./src
RUN mvn -B -q -s settings.xml clean package -DskipTests

# 阶段 2：运行（不含 Maven 与源码，体积 ~250MB）
FROM eclipse-temurin:17-jre
WORKDIR /app
COPY --from=build /app/target/*.jar app.jar
EXPOSE 8080
ENV TZ=Asia/Shanghai
ENTRYPOINT ["java", "-jar", "/app/app.jar"]
```

> `COPY pom.xml` 与 `COPY src` 分成两步，是为了利用 Docker 层缓存：只改 Java 代码时不会重新下载依赖。

### 10.2 前端多阶段构建（`frontend/Dockerfile`）

```dockerfile
# 阶段 1：构建静态文件
FROM node:20-alpine AS build
WORKDIR /app
COPY package.json ./
RUN npm install
COPY . .
RUN npm run build                        # 产物 /app/dist

# 阶段 2：Nginx 托管（不含 Node 与 node_modules，体积 ~50MB）
FROM nginx:alpine
RUN rm -f /etc/nginx/conf.d/default.conf
COPY nginx.conf /etc/nginx/conf.d/default.conf
COPY --from=build /app/dist /usr/share/nginx/html
EXPOSE 80
```

### 10.3 Nginx 反向代理（`frontend/nginx.conf`）

```nginx
location ^~ /api/ {
    proxy_pass http://backend:8080;      # 用「服务名」访问另一个容器
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
}

location ~ ^/(doc\.html|webjars/|v3/api-docs|swagger-ui|swagger-resources) {
    proxy_pass http://backend:8080;      # Knife4j 文档也走代理
}

location / {
    try_files $uri $uri/ /index.html;    # 单页应用路由回退
}
```

> `location ^~ /api/` 的 `^~` 表示命中该前缀后**不再尝试正则匹配**，否则可能被下面的正则 location 抢走。

### 10.4 编排（`docker-compose.yml`）

```yaml
services:
  mysql:
    image: mysql:8.0
    volumes:
      - mysql-data:/var/lib/mysql
      - ./backend/src/main/resources/db/init.sql:/docker-entrypoint-initdb.d/init.sql:ro
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "127.0.0.1", "-utodo", "-ptodo123456"]
    networks: [todo-net]

  redis:
    image: redis:7-alpine
    command: ["redis-server", "--appendonly", "yes"]
    networks: [todo-net]

  backend:
    build: { context: ./backend }
    environment:
      MYSQL_HOST: mysql        # 容器内用服务名，而不是 localhost
      REDIS_HOST: redis
    depends_on:
      mysql: { condition: service_healthy }   # 等健康检查通过再启动
      redis: { condition: service_healthy }
    networks: [todo-net]

  frontend:
    build: { context: ./frontend }
    ports: ["8081:80"]
    depends_on: [backend]
    networks: [todo-net]

volumes: { mysql-data: , redis-data: }
networks: { todo-net: { driver: bridge } }
```

**四个组织要点**

| 要点 | 说明 |
|---|---|
| **自定义网络** | 同一 `todo-net` 上的容器可用**服务名**互访（`backend` 连 `mysql:3306`）。这就是 `application.yml` 默认写 `localhost`、容器里要注入 `mysql` 的原因 |
| **健康检查 + depends_on** | 用业务账号 `mysqladmin ping` 真正验证库已就绪，避免后端「连不上库直接退出」 |
| **命名卷** | `down` 不丢数据，`down -v` 才彻底重置 |
| **配置外置** | 地址密码全由 `environment` 注入，换环境不改代码 |
